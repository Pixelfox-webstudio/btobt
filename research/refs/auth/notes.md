# 로그인·회원가입형 레퍼런스 기록

본 날짜: 2026-11-17. 모든 관찰은 이 폴더에 남아 있는 캡처(PC 1440×900, 모바일 390×844)에서 직접 본 것만 적었다. 로그인·가입·양식 제출은 하지 않았고, 누른 것은 이동 링크와 회원 유형 선택뿐이다. 색·글꼴·모서리·그림자는 적지 않았다(DESIGN.md 값을 쓴다). 폭 수치는 캡처에서 잰 대략값이다.

우리 페이지: 로그인 / 회원가입 유형 선택 / 일반·기업 가입 방법 선택 / 일반 정보 입력 / 기업 정보 입력 / 광고 수신거부.


## 1. 훑어본 후보 목록

### 남긴 곳 (5곳, PC·모바일 짝 있음)

1. Printful (해외) — 사진·소개 문구와 로그인 양식을 좌우로 나눈 화면. 로그인과 가입이 같은 틀을 쓴다.
2. 교보문고 (국내) — 가입 방법 선택(기본 가입 + 간편 가입 6가지를 3단으로 나눔), 법인회원 사업자번호 인증 한 화면.
3. 컬리 (국내) — 일반 회원 정보 입력 한 화면, 입력 즉시 안내가 뜬 상태, 광고성 정보 수신 채널 선택. 없는 주소 안내 화면(결과만 알리는 한 화면 참고)도 함께 남겼다.
4. 삼성전자 비즈니스 파트너 신청 (국내) — 기업 정보 입력 양식(사업자등록번호 확인, 주소 우편번호 찾기, 회사 정보 → 담당자 정보 순서, 약관 3종).
5. 나비엠알오 (국내, 기업 전용 쇼핑몰) — 회원 유형 선택(사업자·구매담당자 / 개인), 계정 형태 비교 카드, 진행 막대.

### 버린 곳과 이유

오늘 다시 열어 확인한 결과다(앞 담당자가 훑어본 31곳 + 새로 연 곳).

- 교보문고 로그인(mmbr.kyobobook.co.kr/login) — 모바일만 찍혀 있었고 PC는 두 번 모두 "400 Request Blocked". 짝을 못 맞춰 모바일 캡처를 지웠다.
- 무신사 로그인 — 아이디·비밀번호 + 카카오·Apple 구성. 29CM과 같은 통합계정 화면이라 겹친다.
- 컬리 로그인 — 주소를 열면 메인으로 넘어가 로그인 화면이 찍히지 않는다.
- 오늘의집 로그인 — 403 Access Denied.
- KREAM 로그인·가입 — 500, 빈 화면.
- W컨셉 로그인, G마켓 가입 — 주소를 찾지 못함(이름 해석 실패).
- 사람인 기업회원 가입 — 45초 안에 열리지 않음.
- 잡코리아 기업회원 가입 — PC는 열린다(개인회원/기업회원 탭, 기업정보·기업인증·인사담당자 정보 3묶음이 한 화면). 모바일 주소는 빈 화면이고, PC 주소는 폰 폭에서 PC 배치가 잘려 보여 짝을 못 맞췄다. 캡처는 남기지 않았다.
- SSG 가입 — 404 안내 화면.
- 스마트스토어 가입 — 판매자센터 소개 화면으로 넘어간다. 가입 양식은 로그인 뒤에 있다.
- 배민 사장님 가입 — 403 "올바르지 않은 요청".
- 쿠팡 비즈 — 403 Access Denied.
- 쿠팡 윙 판매자 가입 — 열린다. 한 열 카드에 아이디·비밀번호·이름·이메일 인증·휴대폰 인증·약관. 사업자 정보는 이 화면에 없고 구성이 컬리와 겹친다.
- 토스페이먼츠 가입, 카카오스타일 파트너센터 가입 — 로그인 화면으로 넘어간다.
- IKEA 로그인·가입·비즈니스 가입 — "잠깐만" 세션 확인 팝업이 양식을 가린 채 찍힌다. 비즈니스 가입 주소는 IKEA Family 가입으로 넘어간다.
- 카페24 쇼핑몰 관리자 로그인 — 운영자 유형 탭 + 아이디·비밀번호 + Google. 양식 아래 광고 배너 2개가 붙어 있고 관리자용 화면이다.
- 채널톡 로그인 — Google·SAML SSO + 이메일·비밀번호. 업무 도구용 구성(SSO)이라 우리 간편 로그인과 다르다.
- 오프린트미 로그인 — 카카오 큰 버튼 + 네이버·구글·Apple 원형 아이콘. 마플과 같은 배치라 마플만 남겼다.
- Stripe 가입 — 흐린 대시보드 배경 위 카드형 양식 + 쿠키 띠. 사업자 정보 단계는 가입 뒤에 있다.
- Shopify 가입 — 어두운 바탕 위 이메일 한 칸. 우리 인상(흰 바탕)과 다르고 볼 입력 항목이 없다.
- Unsplash 가입 — 403 Access Denied. Airtable 가입 — "Verify it's you" 보안 확인.
- Dribbble 로그인 — 왼쪽 양식 + 오른쪽 그림 2열. 쿠키 팝업이 양식 아래를 가린다. Printful과 같은 구성이다.
- Klaviyo 로그인 — 왼쪽 양식 + 오른쪽 영상 패널. 양식 안에 reCAPTCHA 체크 상자가 있다. Printful과 겹친다.
- Squarespace 로그인 — 왼쪽 이메일·비밀번호, 오른쪽 Google·Apple·Facebook 버튼. 사진·소개 문구가 없다.
- 도매꾹 가입 — 가입 방법 선택 한 화면(가입 버튼 + 네이버·카카오·Apple 원형 아이콘 + 해외거주 가입 링크). 교보문고와 겹친다.
- 오너클랜 가입 — 약관 단계가 먼저 나오고 PC는 좌우 광고 배너가 많다.
- 신상마켓 — PC는 보안 확인(403), 모바일은 앱 소개 화면.
- 오피스디포 가입 — PC는 4단계 표시(STEP 01 본인확인 → 02 약관동의 → 03 정보입력 → 04 가입완료)와 개인회원/기업회원 탭이 있다. 모바일은 가입 화면에 닿지 못해(메인으로 감) 짝을 못 맞췄다.
- 오피스넥스 가입 — PC는 사업자회원/개인회원 2칸 선택. 모바일은 PC 배치가 그대로 잘려 보인다.
- 아이더세이프티·K2세이프티(추측한 주소), 식봄 — 열리지 않음. 링크샵스 — 도메인 판매 페이지로 넘어감.


## 2. 남긴 곳

### 2-1. Printful — 사진·소개 문구 + 로그인 양식

- 주소: https://www.printful.com/auth/login , https://www.printful.com/auth/register
- 본 날짜: 2026-11-17
- 캡처: printful-login-pc.jpg, printful-login-m.jpg, printful-register-pc.jpg, printful-register-m.jpg

관찰한 사실

- PC 로그인은 화면을 좌우 2열(각 약 720px)로 나눈다. 사이트 전체 메뉴와 바닥글은 없다.
- 왼쪽 열(양식, 실제 양식 폭 약 440px)의 순서: 왼쪽 위 로고 → 제목 한 줄 + 보조 문장 한 줄 → Google 버튼 → Apple 버튼(둘 다 양식 폭 전체, 글자는 왼쪽·로고는 오른쪽 끝) → "or" 구분선 → Email 라벨과 입력 → Password 라벨과 입력(칸 안 오른쪽에 보기 아이콘) → "Forgot password?" 링크 → "Log in" 버튼(왼쪽 정렬, 작은 폭) → "Don't have an account? Sign up" → 회사 주소와 reCAPTCHA 고지(작은 글씨).
- 오른쪽 열(소개, 바탕이 다른 패널)의 순서: 상품 사진 2장을 겹친 그림 → 제목 한 줄 → 설명 3줄 → 테두리 버튼 1개. 모두 가운데 정렬이다.
- 모바일 로그인은 1열이다. 로고(심벌만, 가운데) → 제목·보조 문장 → Google → Apple → or → Email → Password → Forgot → Log in(전폭) → Sign up → 주소·고지 → 그 아래로 소개 패널(사진 → 제목 → 설명 → 버튼)이 통째로 내려간다. PC의 오른쪽 열이 모바일에서는 양식 뒤로 간다.
- PC 가입도 같은 2열이다. 왼쪽: 제목 + 보조 문장("Sign up with existing accounts to make it faster") → Google → Apple → or → "Sign up with your email" 버튼 → "Have an account? Log in". 첫 화면에 입력칸이 없고 이메일 양식은 버튼을 눌러야 나온다(누르지 않음). 오른쪽: 상품 사진 + 체크 표시 3줄(굵은 한 줄 + 설명 한 줄씩).
- 모바일 가입은 양식 열 다음에 소개 패널이 오는데, 패널에는 체크 3줄만 있고 사진은 보이지 않는다.
- 로그인과 가입이 같은 틀이고 오른쪽 열 내용만 다르다(로그인은 시즌 안내, 가입은 가입 이유 3가지).

가져올 것

- 로그인·유형 선택·가입 방법 선택을 같은 2열 틀로 만들고 소개 열 내용만 바꾼다. 이유: 화면이 바뀌어도 양식 위치가 같아 다시 찾을 필요가 없고, 대표 사진을 한 번만 준비하면 된다.
- 양식 열에는 로고만 두고 전체 메뉴를 넣지 않는다. 이유: 아이디·비밀번호·로그인 버튼·간편 로그인이 PC 첫 화면(900px) 안에 들어온다.
- 모바일에서는 양식을 먼저, 사진·소개를 양식 아래에 둔다. 이유: 폰에서 사진이 위에 오면 입력칸이 첫 화면 밖으로 밀린다.
- 가입 쪽 소개 열의 "체크 3줄(굵은 한 줄 + 설명 한 줄)" 형식. 이유: 기업 회원으로 가입하면 달라지는 점을 3줄로 적기에 맞다.

바꿔서 쓸 것

- 소개 열에는 시즌 판촉 문구 대신 대표 사진 1장 + 소개 제목 한 줄 + 문장 한두 줄을 고정으로 둔다. 이유: 로그인 화면을 판촉 때마다 바꾸지 않아도 된다. 연출 사진이면 "연출 이미지입니다."를 사진 위에 붙인다(DESIGN.md 규칙).
- 간편 로그인을 양식 위가 아니라 아래에 둔다. 이유: 사업자 회원은 아이디·비밀번호로 들어오므로 아이디 양식이 첫 줄이어야 한다(간편 가입이 일반 회원 전용인지 구현 때 확인).
- 로그인 버튼을 왼쪽 작은 폭이 아니라 양식 폭 전체로 둔다. 이유: 모바일과 같은 모양으로 맞춘다.

쓰지 않을 것

- 오른쪽 아래 채팅 버튼, reCAPTCHA 고지 문단. 이유: 우리 화면에 없는 기능이다.
- "이메일로 가입" 버튼을 눌러야 양식이 나오는 방식. 이유: 우리는 가입 방법 선택 화면이 따로 있어 같은 선택을 두 번 묻게 된다.


### 2-2. 교보문고 — 가입 방법 선택, 법인회원 사업자번호 인증

- 주소: https://mmbr.kyobobook.co.kr/join , https://mmbr.kyobobook.co.kr/join/company
- 본 날짜: 2026-11-17
- 캡처: kyobo-join-pc.jpg, kyobo-join-m.jpg, kyobo-company-pc.jpg, kyobo-company-m.jpg

관찰한 사실

- 두 화면 모두 사이트 머리말 없이 로고만 가운데에 두고, 폭 약 400px 한 열만 쓴다(PC 1440px에서 좌우가 비어 있다). 바닥에는 저작권 한 줄만 있다.
- 가입 방법 선택의 순서: 로고 → 혜택 말풍선 한 줄 → "회원가입" 버튼(열 폭 전체, 가장 큼) → 글자 링크 2개 "법인회원 가입 | 로그인" → "카카오로 회원가입" 버튼(전폭) → "네이버로 회원가입" 버튼(전폭) → "다른 방법으로 회원가입" 작은 글씨 → 원형 아이콘 4개 한 줄(구글·애플·휴대폰·이메일, 아이콘 아래 이름).
- 가입 수단 7가지를 크기로 3단으로 나눴다: 기본 가입 1개(가장 큰 버튼) / 카카오·네이버 2개(전폭 버튼, 서비스 이름을 글자로 적음) / 나머지 4개(아이콘 + 이름).
- 법인회원 가입은 버튼이 아니라 주 버튼 아래의 작은 글자 링크다.
- 모바일은 같은 순서·같은 구성이고 왼쪽 위에 뒤로 가기 화살표가 추가된다. 버튼은 좌우 여백을 뺀 화면 폭 전체다.
- 법인회원 화면의 순서: 로고 → "사업자번호" 라벨과 입력 → "법인명" 라벨과 입력 → "인증하기" 버튼(입력 전에는 흐림) → "사업자번호 인증이 안 되시나요?" 굵은 한 줄 + 안내 3줄(FAX로 사업자등록증 1부와 연락처 접수 / 사업자 구매회원 사업자등록 바로 가기 / 신용평가사 전화번호와 바로 가기).
- 법인 가입의 첫 단계는 입력칸 2개와 버튼 1개가 전부다. 나머지 정보 입력은 인증 뒤 단계다(누르지 않아 보지 못함).
- 라벨은 PC·모바일 모두 입력칸 위에 있다.

가져올 것

- 가입 수단을 크기로 단을 나누는 방식. 이유: 수단이 여러 개여도 어느 것이 기본인지 한눈에 정해진다.

- 머리말 없이 로고 + 좁은 한 열. 이유: 선택지가 적은 화면에서 다른 메뉴로 새지 않는다.

바꿔서 쓸 것

- 법인회원 가입을 작은 글자 링크로 두지 않고 유형 선택 화면에서 일반 회원과 같은 크기의 카드로 둔다. 이유: 우리 주 고객이 기업·관공서 구매 담당자다.

쓰지 않을 것

- 혜택 금액 말풍선. 이유: 확인되지 않은 수치·혜택 문구를 쓰지 않는다.

- 같은 주소인데 PC와 모바일이 서로 다른 선택 화면을 보여 줬다. PC는 "1인 계정 / 조직 계정", 모바일은 "사업자·구매담당자 회원 / 개인 회원"이다. 같은 가입 흐름의 다른 단계인지는 확인하지 않았다(더 누르지 않음).
- 두 화면 모두 사이트 머리말이 없다. 맨 위 띠에 왼쪽 "‹"(이전) · 가운데 "회원가입" · 오른쪽 "×"(닫기)가 있고, 띠 바로 아래에 가는 진행 막대가 왼쪽 일부만 채워져 있다. 단계 이름이나 숫자는 없다.
- PC: 로고 아래 폭 약 800px 카드 한 장. 제목 한 줄 + 보조 문장 한 줄 아래에 선택 카드 2장이 좌우로 나란히 있다. 카드 한 장의 구성: 머리띠(쓰는 사람의 말투 한 줄) → 그림 → 체크 3줄(계정으로 할 수 있는 일) → 카드 맨 아래 버튼("1인 계정으로 가입하기" / "조직 계정으로 가입하기"). 두 카드는 높이와 줄 수가 같고, 조직 계정 쪽만 머리띠와 테두리가 강조되어 있다.
- 모바일: 제목 2줄 → 질문 2줄("고객님은 어떤 회원 이신가요? 가입하시려는 회원 유형을 선택해주세요.") → 테두리 카드 2장이 세로로. 카드 한 장 = 유형 이름 한 줄(굵게) + 누구인지 설명 한두 줄. "일반 사업자/구매담당자 회원 — 사업자, 기업의 구매담당자 등 사업자로 등록되어 있는 고객" / "개인 회원 — 사업자로 등록되지 않은 개인구매 회원". 별도 버튼이 없고 카드 전체가 누르는 대상이다. 그림은 없다.
- 모바일 화면에는 카드 2장 외에 다른 입력이 없다(화면 높이 한 장 안에 끝난다).

가져올 것

- 유형 이름 아래 "누구인지" 한 줄을 붙인 카드, 카드 전체가 버튼. 이유: "기업 회원"이라는 이름만으로는 개인사업자·관공서 담당자가 자기가 어느 쪽인지 망설인다.
- 사업자 유형 이름에 "구매담당자"를 함께 적은 것. 이유: 우리 고객도 대표가 아니라 구매 담당자인 경우가 많다.
- PC 비교 카드의 "체크 3줄" 형식. 이유: 유형마다 가입 뒤 달라지는 점을 같은 줄 수로 나란히 보여 준다.
- 맨 위 띠(이전 · 화면 이름 · 닫기) + 진행 막대. 이유: 유형 선택 → 가입 방법 선택 → 정보 입력으로 이어지는 우리 흐름에서 어디쯤인지와 되돌아갈 길을 같은 자리에 둔다.

바꿔서 쓸 것

- 진행 막대만 두지 않고 "1/3 유형 선택"처럼 숫자와 단계 이름을 함께 적는다. 이유: 막대만으로는 전체가 몇 단계인지 알 수 없다.
- PC와 모바일에서 같은 질문 하나만 묻는다(기업 회원 / 일반 회원). PC는 좌우 2장, 모바일은 세로 2장. 이유: 나비엠알오처럼 기기에 따라 질문이 달라지면 안내·문의 응대가 어긋난다.
- 두 카드를 같은 무게로 두되 기업 회원을 왼쪽(모바일은 위)에 둔다. 이유: 한쪽이 "권장"이 아니라 둘 다 맞는 선택이고, 주 고객이 먼저 보인다.

쓰지 않을 것

- 카드 안 그림(일러스트)과 말투형 머리띠, 느낌표가 붙은 환영 문구. 이유: 우리 문구 톤(짧은 평서문, 장식 최소)과 다르다.

- 대표 사진 + 소개 문구 + 로그인 양식: Printful(PC 좌우 2열, 모바일 양식 먼저).
- 간편 로그인 3종 배치: 마플(한 줄), 29CM·교보문고(세로 전폭 버튼), Printful(양식 위 전폭 2개).
- 기업 회원 / 일반 회원 유형 선택: 나비엠알오(설명 붙은 카드 2장), 네이버 클라우드(2칸 토글), 아이마켓(양식 안 라디오), 교보문고(글자 링크).
- 가입 단계 표시: 네이버 클라우드("1/6"), 나비엠알오(진행 막대 + 이전·닫기).
- 사업자등록번호 확인: 삼성전자 비즈니스(입력 + 확인 버튼 + 조건 한 줄), 교보문고(번호 + 법인명 인증 한 화면 + 안 될 때 안내).
- 주소 검색: 컬리(PC 버튼형, 모바일 돋보기 입력칸형), 삼성(입력 + 우편번호 버튼).
- 아이디 중복확인·비밀번호 규칙·일치 표시: 아이마켓(중복확인 버튼, 규칙 고정 표시), 컬리(칸 아래 한 줄 안내), Apple(규칙 목록 + 체크).
- 자동등록방지 그림: Apple(문자 그림 + 입력 + 새로 받기·소리로 듣기).
- 광고 수신 동의: 컬리(채널별 들여쓰기), 아이마켓(문자·이메일), 삼성(전체 동의에 선택 포함 명시), Apple(설명 줄).
- 결과만 알리는 한 화면: 컬리 없는 주소 안내 화면(뼈대만 참고).
- 사업자등록증 첨부와 미리보기: 실제 가입 화면은 찾지 못함. KRDS(첨부 칸 구성)와 Ant Design(썸네일 모양) 문서 화면으로 대신함.

끝내 채우지 못한 것

- 사업자등록증 파일 첨부와 미리보기가 들어간 실제 가입 화면. 로그인 없이 볼 수 있는 곳을 찾지 못했다.
- 업태·업종 입력칸이 있는 화면. 남긴 곳 어디에도 없다.
- 광고 수신거부 화면과 그 결과 화면. 수신거부는 메일 속 개인별 링크로만 열려 찍을 수 없었다. 컬리의 없는 주소 안내 화면으로 뼈대만 확인했다.
- 숫자만 나오는 자동등록방지 그림. Apple은 영문과 숫자가 섞인 그림이다.
- 가입 단계 표시가 있는 2단계 이후 화면. 네이버 클라우드 1단계 한 장뿐이다.
- 가입 완료 화면. 가입을 하지 않아 보지 못했다.
- 국내 사이트의 "사진 + 로그인 양식" 2열 화면. 훑어본 국내 로그인 화면은 모두 가운데 한 열이었다(IKEA 국내 로그인은 2열이지만 대기 팝업에 가려 찍히지 않음).


## 5. 사용성 근거

아래는 2026-11-17에 주소를 열어 내용을 확인한 공개 글이다. 본문을 요약 도구로 읽었으므로 수치를 밖에 인용할 때는 원문을 다시 확인한다.

1. NN/g, "Website Forms Usability: Top 10 Recommendations" (Kathryn Whitenton, 2016-05-01) — https://www.nngroup.com/articles/web-form-design/
   - 양식은 짧게: 다른 곳에서 알 수 있거나 나중에 받아도 되는 칸은 뺀다.
   - 한 열 배치로 둔다(짧고 서로 관련된 칸은 예외).
   - 칸 안 안내 글(placeholder)은 피한다.
   - 선택지가 두세 개면 선택 상자 대신 라디오를 쓴다.
   - 필수와 선택을 구분해 표시한다.
   - 입력 형식·비밀번호 규칙은 오류가 난 뒤가 아니라 미리 적는다.
   - 초기화 버튼은 두지 않고, 취소 버튼은 제출 버튼보다 덜 눈에 띄게 둔다.
   - 오류 안내는 색 외의 단서도 함께 쓰고, 틀린 입력을 지우지 않는다.
2. NN/g, "10 Design Guidelines for Reporting Errors in Forms" (Rachel Krause, 2019-02-03) — https://www.nngroup.com/articles/errors-forms-design-guidelines/
   - 가능한 한 칸 단위로 바로 검사하고 안내를 칸 옆이나 아래에 둔다.
   - 아이디·비밀번호처럼 까다로운 칸은 성공도 표시한다(체크, 강도 표시).
   - 입력이 끝나기 전에는 검사하지 않는다(칸을 벗어난 뒤에 오류를 보인다).
   - 위쪽 요약만으로 오류를 알리지 않는다. 툴팁으로 오류를 알리지 않는다.
3. NN/g, "Password Creation: 3 Ways To Make It Easier" (Katie Sherwin, 2015-04-26) — https://www.nngroup.com/articles/password-creation/
   - 비밀번호 규칙을 입력 전부터 보여 주고 칸을 쓰는 동안 계속 보이게 둔다.
   - 규칙이 충족되는 대로 표시를 바꿔 진행 정도를 보여 준다.
   - 비밀번호 보기 전환을 제공한다.
4. Baymard, "Usability Testing of Inline Form Validation: 31% Don't Have It, 4% Get It Wrong" (2024-01-09) — https://baymard.com/blog/inline-form-validation
   - 다 입력하기 전에 오류를 띄우지 않는다. 대부분의 칸은 칸을 벗어날 때 검사한다.
   - 고치는 동안에는 글자 단위로 다시 검사해 맞는 순간 오류를 지운다(비밀번호 확인처럼 서로 얽힌 칸에서 특히 중요).
   - 맞게 입력한 칸에는 맞았다는 표시를 한다.
   - 글 제목은 31%, 글 안 영상 요약은 32%로 적혀 있어 수치가 한 글 안에서 다르다.
5. Baymard, "E-Commerce Checkouts Need to Mark Both Required Fields and Optional Fields Explicitly (Only 14% Do So)" (2018-10-02) — https://baymard.com/blog/required-optional-form-fields
   - 필수와 선택을 둘 다 표시한다. 필수에는 별표, 선택에는 라벨 옆 "(선택)".
6. NN/g, "Top 10 Design Mistakes in the Unsubscribe Experience" (Kim Flaherty, 2018-04-29) — https://www.nngroup.com/articles/unsubscribe-mistakes/
   - 수신거부에 로그인이나 개인정보 입력을 요구하지 않는다. 대신 어떤 주소가 해지되는지 보여 준다.
   - 선택지가 많은 설정 화면이면 "모두 수신거부"를 맨 위에 눈에 띄게 둔다.
   - 해지 이유는 해지를 끝낸 뒤에, 선택으로 묻는다.
   - 다시 구독하라고 밀지 않는다(유지 선택을 미리 골라 두지 않는다).
   - 확인 메일을 또 보내지 않고 화면에서 해지되었음을 알린다. 해지는 바로 반영한다.
7. KRDS(대한민국 정부 디자인 시스템), "파일 업로드" 사용성 가이드라인 — https://www.krds.go.kr/html/site/component/component_09_04.html (캡처에 찍힌 본문)
   - 파일 업로드는 꼭 필요한 경우에만 쓴다. 레이블로 무엇을 올려야 하는지 알린다.
   - 파일 유형·크기·개수 제한을 도움말로 미리 안내한다.
   - 파일이 올라간 뒤에도 파일 선택 버튼을 계속 쓸 수 있는 상태로 둔다.
   - 양식 제출 버튼이 있으면 파일 선택 버튼은 그보다 낮은 강조로 둔다.

확인한 글 없음: 간편 로그인 버튼의 순서·배치, 회원 유형 선택 화면, 사업자등록번호 확인 방식, 자동등록방지 그림, 로그인 화면의 사진 배치에 대한 Baymard·NN/g 글은 이번에 열어 확인하지 못했다. 이 부분의 판단은 위 캡처 관찰에만 근거한다.


## 6. 이 유형에 그대로 쓸 수 있는 문장

1. 로그인·유형 선택·가입 방법 선택은 PC에서 좌우 2열로 나눈다. 왼쪽 열에는 로고와 양식만, 오른쪽 열에는 대표 사진 1장 + 제목 한 줄 + 문장 두 줄 이내를 둔다. 모바일에서는 양식을 먼저 두고 사진·소개를 양식 아래로 내린다. 전체 메뉴는 넣지 않고 로고를 누르면 홈으로 간다.
2. 로그인 양식의 순서는 아이디 → 비밀번호(칸 안 오른쪽에 보기 전환) → "로그인" 버튼(양식 폭 전체) → "아이디 찾기 · 비밀번호 찾기" → "간편 로그인" 작은 제목 → 같은 폭 버튼 3칸 한 줄(카카오 · 네이버 · Google, 버튼마다 로고와 이름) → "회원가입" 링크로 한다. PC 900px 높이 안에 가입 링크까지 들어오게 한다.
3. 가입 방법 선택 화면에서는 간편 가입 3종을 "카카오로 가입 / 네이버로 가입 / Google로 가입" 전폭 버튼 3줄로 세로로 쌓고, 그 아래 구분선을 두고 "아이디로 가입" 버튼을 둔다. 아이콘만 있는 버튼은 쓰지 않는다.
4. 유형 선택은 카드 2장으로 한다(PC 좌우, 모바일 세로, 기업 회원이 먼저). 카드 한 장 = 유형 이름 + 누구인지 한 줄("사업자등록증이 있는 기업·관공서 구매 담당자") + 가입 뒤 달라지는 점 3줄. 카드 전체가 버튼이고 두 카드의 줄 수를 같게 맞춘다.
5. 가입 화면 맨 위에는 왼쪽 "이전", 가운데 단계 표시("2/3 가입 방법 선택"처럼 현재/전체 숫자 + 단계 이름), 오른쪽 "닫기"를 한 줄로 둔다.
6. 기업 정보 입력은 묶음 3개를 소제목 + 가로선으로 나눈다: 사업자 정보(사업자등록번호 → 상호 → 대표자명 → 업태 | 업종 한 줄 2칸 → 주소 → 사업자등록증 첨부) → 담당자 정보(아이디 → 비밀번호 → 비밀번호 확인 → 이름 → 휴대폰 → 이메일) → 약관 동의. 첫 묶음 소제목 줄 오른쪽 끝에 "* 필수 입력 항목"을 적고, 선택 칸에는 라벨 뒤에 "(선택)"을 적는다.
7. 버튼이 딸린 칸(사업자등록번호 + "확인", 아이디 + "중복확인", 주소 + "주소 검색")은 PC·모바일 모두 입력칸과 버튼을 한 줄에 두고, 결과를 칸 바로 아래 한 줄로 적는다("확인되었습니다." / "사용할 수 있는 아이디입니다."). 값을 고치면 결과 줄을 지우고 다시 확인하게 한다. 사업자등록번호 칸 아래에는 "확인이 안 되면 아래 사업자등록증 첨부만으로 가입할 수 있습니다."를 미리 적는다.
8. 사업자등록증 첨부 칸은 라벨 → 안내 한 줄(올릴 수 있는 형식 · 최대 크기 · 1개) → "파일 선택" 버튼 순서로 둔다. 파일을 고르면 버튼 아래에 한 행(작은 썸네일 또는 PDF 아이콘 + 파일 이름 + 크기 + "삭제")을 보이고, 썸네일을 누르면 크게 본다. 버튼은 "파일 바꾸기"로 계속 누를 수 있게 두고 새 파일은 기존 파일을 대신한다.
9. 아이디·비밀번호 규칙은 입력 전부터 칸 아래에 적어 둔다. 비밀번호 규칙은 줄 단위 목록으로 두고 충족한 줄 앞에 체크를 붙인다. 오류는 칸을 벗어날 때 칸 바로 아래 한 줄로 보이고, 고치는 동안에는 글자마다 다시 검사해 맞는 순간 지운다. 비밀번호 확인 칸에는 일치하면 "비밀번호가 일치합니다."를 같은 자리에 적는다. 안내 줄의 높이를 미리 잡아 아래 칸이 밀리지 않게 한다.
10. 약관 묶음은 "전체 동의"(바로 아래 "선택 항목에 동의하지 않아도 가입할 수 있습니다.") → (필수) 항목들 → "광고성 정보 수신 (선택)" + 그 아래 들여쓴 채널 체크(문자 · 이메일) 순서로 두고, 전문은 줄 오른쪽 "보기"로 연다. 자동등록방지는 약관 다음, 제출 버튼 바로 위에 둔다: PC는 숫자 그림 + 입력칸 한 줄, 모바일은 그림 위·입력칸 아래, 그림 아래에 "새로고침"과 "음성으로 듣기" 글자 버튼.
11. 광고 수신거부 결과 화면은 가운데 한 덩어리로 만든다: 상태 아이콘 → 결과 한 줄("광고 수신을 거부했습니다.") → 무엇이 언제 바뀌었는지 두 줄 이내(일부를 가린 이메일·휴대폰 번호, 처리 일시) → "홈으로" 버튼 1개 → 그 아래 글자 링크 1개("수신 설정 변경"). 로그인을 요구하지 않고, 해지 이유를 묻지 않는다.
