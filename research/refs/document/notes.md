## 1. 무신사 개인정보 처리방침

- 주소: https://member.one.musinsa.com/agreement/privacy-policy (29cm.co.kr/home/private 로 열어도 이 주소로 넘어온다)
- 본 날짜: 2026-11-17
- 캡처: `musinsa-privacy-full-pc.jpg`, `musinsa-privacy-full-m.jpg`(전문 탭), `musinsa-privacy-history-pc.jpg`, `musinsa-privacy-history-m.jpg`(개정 이력 탭), `musinsa-privacy-compare-pc.jpg`, `musinsa-privacy-compare-m.jpg`(전후 비교 탭)
- 캡처 주의: 화면에 고정된 검색 띠와 헤더 줄이 그림 중간에 한 번 끼어 찍혔다. 실제로는 화면 위쪽에 붙어 있는 요소다.

### 관찰한 사실

- 맨 위 순서: ① 검정 한 줄 안내 띠("개정 안내 개인정보 처리방침이 개정되어 2026.10.28부터 시행 중입니다. 변경 전후 비교 보기 →") ② 제목 "개인정보 처리방침" ③ 버전 선택 상자("2026.10.28 - 현재", 지난 버전까지 선택지 64개, 현행이 v64) + 검정 "현행" 배지 + "적용기간 2026.10.28 - 현재 · 고지일 2026.10.21" ④ 밑줄 탭 4개(쉽게 보기 / 전문 / 개정 이력 / 전후 비교) ⑤ 탭 내용.
- 전문 탭 순서: 서문 문단 → 회색 상자(서비스별 처리방침 바로가기 버튼 2개) → "주요 개인정보 처리 표시" 카드 8개(아이콘 + 이름 + 한두 줄 요약, "항목을 누르면 해당 조항으로 이동") → 회색 바탕 "목차" 상자(14항목, 번호 붙음) → "서비스별 보기" 버튼 4개와 "전체 접기 / 전체 펼치기" → 조항.
- 조항은 3단계다. 1단계 "1. …"은 왼쪽에 접기 화살표, 2단계 "1.1 …"은 오른쪽 끝에 접기 화살표, 3단계 "가. …"는 회색 띠 제목. 3단계 아래에는 "수집·이용 목적 / 수집 항목 / 보유 및 이용기간 / 법적 근거"가 굵은 라벨 + 내용인 글머리표 네 줄로 반복된다. 표는 쓰지 않았다. 전후 비교 탭에 "회원·비회원·입점업체별 표를 서비스 분야별 목록으로 재구성하였으며"라고 적혀 있다.
- 개정 이력 탭: 버전마다 1px 테두리 카드 하나. "v64 [현행] 적용기간 … · 고지 …" 한 줄 → 바뀐 조항을 조항 번호로 시작하는 글머리표 → 버튼 2개("이 버전 전문 보기", "직전 버전과 비교"). 지난 버전에는 회색 "이전 버전" 배지가 붙는다.
- 전후 비교 탭: 버전 선택 2개("v63 (2026-07-13)" → "v64 (2026-10-28)")와 "비교" 버튼 → "이번 개정에서 달라진 점" 요약 카드 3개(번호 원 + 제목 + 두세 줄) → "개정 요지 전체 보기 (8개)" 펼침 → 2열 표(개정 전 | 개정 후). 바뀐 곳은 굵게, 새 조항은 "(신설)".
- 화면에 고정된 것: 위쪽 "처리방침 내 검색 (예: 보유기간, 위탁)" 입력란과 위·아래 이동·닫기 버튼, 오른쪽 가장자리 원형 버튼 3개(검색, 글자 크기 "가", 맨 위로).
- PC 본문 폭은 약 1,060px이고 서문 한 줄에 한글이 90자 안팎 들어간다.
- PC와 모바일에서 달라지는 점
  - 버전 줄: PC는 선택 상자·배지·적용기간이 한 줄. 모바일은 선택 상자 + 배지가 한 줄, 적용기간·고지일은 다음 줄.
  - 탭 4개는 모바일에서도 한 줄에 다 들어간다(가로 스크롤 없음).
  - 주요 처리 표시 카드: PC 4열 2행 → 모바일 2열 4행.
  - 목차: PC 2열(7 + 7) → 모바일 1열 14줄. 양쪽 다 펼쳐져 있고 화면에 고정되지 않는다.
  - 요약 카드 3개: 3열 → 1열. "비교" 버튼은 전체 폭이 된다.
  - 전후 비교 표: PC 2열 → 모바일에서는 조항마다 "개정 전" 상자, "개정 후" 상자가 전체 폭으로 번갈아 쌓인다. 상자 안의 작은 표는 "목적 | 값", "항목 | 값", "보유 및 이용 기간 | 값"처럼 왼쪽 좁은 라벨 칸 + 오른쪽 값 칸의 행 묶음이다.

### 우리가 가져올 것

- 제목 바로 아래 "버전 선택 상자 + 현행 배지 + 적용기간·고지일" 한 줄. 시행일 표시와 이전 방침 보기가 한 자리에서 끝나고, 정책 문서 4종에 같은 틀로 쓸 수 있다.
- 지난 버전을 고르면 배지가 "이전 버전"(회색)으로 바뀌는 것. 지금 보는 글이 현행인지 헷갈리지 않는다.
- 서문 아래·조항 위의 회색 "목차" 상자(PC 2열, 모바일 1열, 고정하지 않음). 사용성 근거의 NN/g 권고(제목 아래·본문 위, 본문 안 목차는 비고정)와 같다.
- 표 대신 "굵은 라벨 : 내용" 글머리표 네 줄. 수집 항목·목적·보유 기간처럼 한 묶음에 서너 가지 값이 있는 내용은 모바일에서 표보다 잘 읽힌다.
- 개정 때만 맨 위에 붙는 한 줄 안내 띠(시행일 + 바뀐 내용 보기 링크).

### 바꿔서 쓸 것

- 탭 4개(쉽게 보기 / 전문 / 개정 이력 / 전후 비교) → 우리는 탭을 문서 묶음 이동(이용약관 / 취소·환불 정책 / 개인정보처리방침 / 비회원 개인정보처리방침)에 쓰고, 버전은 선택 상자 하나로만 다룬다. 한 화면에 탭 줄이 두 개 생기지 않게 하려는 것이다.
- 개정 이력 카드 → 별도 탭이 아니라 문서 맨 아래 "개정 이력" 조항에 "시행일 + 바뀐 조항 글머리표 + 이 버전 보기" 목록으로 둔다. 우리 개정 횟수는 적다.
- "현행" 배지와 검정 안내 띠 → 견적서의 "미리보기" 표시에 같은 자리·같은 모양으로 쓴다(제목 옆 배지 + 문서 위 한 줄 띠). (제안)
- 본문 폭 약 1,060px → 우리는 DESIGN.md의 760px 단일 열을 그대로 쓴다. 무신사 폭에서는 한 줄이 90자 안팎이라 길다.

### 쓰지 않을 것

- 서비스별 보기 버튼, 처리방침 내 검색 띠, 글자 크기 버튼. 우리는 서비스가 하나이고 문서가 짧아 브라우저 찾기로 충분하다.
- 조항 접기·펼치기. 접어 두면 브라우저 찾기와 인쇄에서 본문이 빠진다. 우리 문서는 모두 펼친 채로 둔다.
- "쉽게 보기" 요약 화면, 전후 비교 표, 주요 처리 표시 카드 8개. 만들고 유지할 분량이 문서 본문보다 커진다.

- 캡처: `kakao-privacy-pc.jpg`, `kakao-privacy-m.jpg`(위쪽), `kakao-privacy-bottom-pc.jpg`, `kakao-privacy-bottom-m.jpg`(맨 아래), `kakao-privacy-menu-m.jpg`(모바일 묶음 메뉴 펼침)

### 관찰한 사실

- PC 맨 위 순서: 로고 줄(오른쪽에 언어 전환) → 회색 안내 상자(문장 + 오른쪽 버튼) → 묶음 탭 7칸(이용약관 / 위치정보 이용약관 / 개인정보 처리방침 / 운영정책 / 청소년보호정책 / 권리침해신고안내 / 공지사항) → 문서 제목 → 목차 상자 → 굵은 가로선 → 조항.
- 묶음 탭은 7칸이 같은 폭으로 한 줄을 채우고 1px 선으로 나뉜다. 지금 문서 칸만 검정 바탕 흰 글씨다.
- 목차 상자는 1px 검정 테두리, 11항목, 3열. 항목은 "1. 카카오 개인정보 처리방침"처럼 번호 + 조항 제목 그대로다.
- 조항 제목은 "1. …" 번호 붙은 굵은 글씨, 조항 사이에 1px 가로선. 본문 폭은 약 1,160px.
- 표는 2열(목적 | 항목). 위쪽에만 굵은 선, 머리칸 가운데 정렬, 두 칸 사이 세로선 하나, 행 아래 1px 선. 칸 안에 굵은 소제목과 "-" 목록이 들어간다.
- 맨 아래 11번 조항: "시행일자: 2026년 10월 28일" 한 줄 → "이전의 개인정보 처리방침은 아래에서 확인하실 수 있습니다." → 테두리 버튼 "이전 개인정보처리방침 목록보기 >".
- 푸터에 묶음 링크가 다시 나오고 지금 문서 이름만 굵다.
- PC와 모바일에서 달라지는 점
  - 묶음 탭 7칸 → "개인정보 처리방침 ∨" 한 줄 선택 상자. 누르면 바로 아래로 목록이 펼쳐진다(가운데 정렬, 네 줄 높이, 오른쪽에 세로 스크롤 막대).
  - 목차 3열 → 1열 11줄(굵게), 펼친 상태.
  - 2열 표는 2열 그대로다. 한 칸에 한글이 12~14자씩 들어가고, 첫 표 하나가 화면 서너 개 높이다.
  - 맨 아래 묶음 링크는 2열, 그 위에 맨 위로 가는 화살표.

### 우리가 가져올 것

- 문서 제목 위의 묶음 탭 한 줄, 지금 문서만 검정. 약관 묶음 사이 이동을 한 번 누름으로 끝낸다. 우리 선택 상태 색(검정)과도 같다.
- 모바일에서 탭을 선택 상자 하나로 바꾸는 것. "비회원 개인정보처리방침"처럼 긴 이름 4개는 390px 한 줄에 다 들어가지 않는다. 사용성 근거의 Baymard 글도 가로로 밀어야 보이는 탭을 피하라고 한다.
- 목차 문구를 조항 제목과 글자까지 같게 쓰고 번호를 붙이는 것.
- 문서 맨 아래 조항에 시행일 한 줄과 "이전 방침 목록 보기" 버튼을 한 번 더 두는 것. 끝까지 읽은 사람이 위로 돌아가지 않아도 된다.
- 푸터의 묶음 링크에서 지금 문서만 굵게 표시하는 것.

### 바꿔서 쓸 것

- 네모 칸 탭 → DESIGN.md의 알약 탭. PC에서는 4개가 한 줄에 들어간다.
- 시행일이 맨 아래에만 있는 것 → 우리는 제목 아래(무신사 방식)에 먼저 두고 맨 아래 부칙에 한 번 더 적는다. 처음 연 사람이 15,000px을 내려가야 시행일을 보는 구조는 피한다.
- 목차 3열 → 우리 본문 폭 760px에서는 2열.

### 쓰지 않을 것

- 모바일에서 2열 표를 2열 그대로 두는 것. 한 칸 12~14자로 줄바꿈이 많고 표 하나가 화면 서너 개 높이가 된다.
- 회색 안내 상자, 캐릭터 말풍선, 컬러 라벨링 아이콘 6개. 우리 DESIGN.md는 장식을 거의 쓰지 않는다.
- 본문 폭 약 1,160px.

  - 화면보다 긴 표는 머리글을 고정한다.
- Baymard, Avoid Horizontal Tabs — https://baymard.com/research-articles/avoid-horizontal-tabs
  - 상품 상세 페이지 연구다. 모바일에서 탭 네 개 중 두 개쯤만 보이는 경우가 있고, 탭을 보려고 가로로 밀게 만들면 안 된다고 적는다. 모바일 탭은 제목 길이에 따라 두세 개까지가 현실적이라고 한다.
  - 우리 묶음 탭은 문서 사이 이동이라 쓰임이 다르지만, "가로로 밀어야 보이는 탭을 만들지 않는다"는 부분만 가져와 모바일 선택 상자의 근거로 삼았다.

## 이 유형에 그대로 쓸 수 있는 문장

1. 견적서는 회색 바탕 위에 흰 종이 한 장으로 두고, 종이 위에 고정 띠를 둔다. 띠 왼쪽에 문서 이름("견적서 미리보기" 또는 "견적서"), 오른쪽에 "닫기"와 "다운로드"를 두고, 모바일에서는 두 버튼을 화면 아래에 고정한다.
2. 미리보기 문서는 제목 옆에 "미리보기" 배지를 붙이고 종이 위에 한 줄 안내 띠를 둔다. 정식 견적서에서는 배지와 띠를 없애고 공급자 칸에 직인을 넣는다. (제안)
3. 종이 머리는 PC에서 2단으로 나눈다. 왼쪽에 수신처·담당자·견적일자·유효기간·견적금액을 라벨-값 줄로, 오른쪽에 공급자 정보와 직인을 둔다. 모바일에서는 견적금액 → 수신처 묶음 → 공급자 묶음 순서로 한 열에 쌓는다. (직인 위치는 제안)
4. PC 품목 표는 상품명·옵션·사이즈별 수량·수량·단가·금액·비고 7열로 두고, 세로선 없이 행 아래 1px 선만 긋고, 수량·단가·금액은 오른쪽 정렬한다.
5. 모바일 품목은 표 머리글을 없애고 품목마다 묶음으로 쌓는다. 첫 줄 상품명(굵게), 둘째 줄 옵션, 셋째 줄 사이즈별 수량("S 10 · M 20 · L 30"), 넷째 줄 왼쪽 "수량 60 · 단가 15,000원"과 오른쪽 끝 금액. 비고는 값이 있을 때만 마지막 줄에 적는다. (사이즈별 수량 줄은 제안)
6. 총 합계는 품목 아래 오른쪽(모바일은 전체 폭)에 라벨-값 줄 묶음으로 두고 마지막 "합계" 줄만 굵고 크게 쓴다.
7. 약관 4종(이용약관·취소/환불 정책·개인정보처리방침·비회원 개인정보처리방침)은 문서 제목 위 탭 한 줄로 오가고, 지금 문서 탭만 검정으로 칠한다. 모바일에서는 탭을 문서 이름이 적힌 선택 상자 하나로 바꾼다.
8. 정책 문서 제목 바로 아래에 버전 선택 상자("시행일 - 현재") + "현행" 배지 + "적용기간 · 고지일"을 한 줄로 둔다. 지난 버전을 고르면 배지를 회색 "이전 버전"으로 바꾼다. 문서 맨 아래 부칙에 시행일을 한 번 더 적는다.
9. 목차는 서문 아래·조항 위에 회색 상자로 한 번만 둔다(PC 2열, 모바일 1열, 화면에 고정하지 않음). 항목은 번호 + 조항 제목 그대로 쓰고, 조항은 접지 않고 모두 펼쳐 둔다. 화면 오른쪽 아래에 "맨 위로" 버튼을 둔다.
10. 보관 기간·쿠키 목록 표는 PC에서 3열(항목 | 목적 | 기간)에 행 아래 1px 선만 긋는다. 모바일에서는 3열을 좁히지 않고 행마다 항목 이름(굵게) 아래 "목적 | 값", "기간 | 값" 줄로 바꿔 쌓는다.
