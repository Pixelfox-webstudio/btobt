- 본 날짜: 2026-11-17
- 대상 페이지: 고객센터(메뉴·상담 연결, 자주 묻는 질문, 주문방법, 1:1 문의 내역, 비회원 문의 확인, 문의 작성, 공지 목록·상세), 구매후기 목록·상세, 이벤트 목록·상세, 납품사례
- 캡처: `_capture.py`(Playwright, PC 1440 / 모바일 390). 모든 그림은 직접 열어 확인했다.
- 범위: 구조·흐름·조작 방식만 적었다. 색·글꼴·모서리·그림자는 DESIGN.md 값을 쓴다. 레퍼런스의 사진·문구·로고는 가져오지 않는다.

## 1. 오프린트미 고객센터·공지사항

- 주소: https://www.ohprint.me/cs/faq , https://www.ohprint.me/cs/qna , https://www.ohprint.me/notice (모바일은 m.ohprint.me 로 넘어간다)
- 본 날짜: 2026-11-17
- 캡처: `ohprint-cs-faq-pc.jpg`, `ohprint-cs-faq-m.jpg`(질문 한 개 펼친 상태), `ohprint-cs-qna-pc.jpg`, `ohprint-cs-qna-m.jpg`, `ohprint-notice-pc.jpg`, `ohprint-notice-m.jpg`(공지 한 개 펼친 상태)

### 관찰한 사실

- 정보 순서(고객센터): 가운데 제목 "무엇을 도와드릴까요" → 회색 띠 한 줄(전화 아이콘, "전화문의", 번호, 운영시간) → 탭 2개(자주 묻는 질문 / 1:1 문의, 폭을 반씩 나눔) → 탭 내용.
- 탭마다 주소가 다르다(`/cs/faq`, `/cs/qna`). 주소를 바로 열면 그 탭이 선택된 채로 열린다. 제목·전화 띠·탭 줄은 두 주소에서 같은 자리에 있다.
- 선택된 탭은 검정 글자 + 아래 검정 줄, 선택 안 된 탭은 회색 글자 + 옅은 줄이다.
- FAQ 탭 순서: 분류 칩 11개 한 줄(TOP10, 배송, 결제, 주문취소, 반품/환불, 상품, 편집기, 회원정보, 쿠폰/머니, 고객리뷰, 기타. 선택된 칩만 검정 채움) → 검색창(전체 폭, 돋보기 아이콘, 안내 글자) → 질문 행 10개.
- 질문 행: 왼쪽 질문 한 줄, 오른쪽 끝 화살표, 행 사이 1px 선. 한 개를 누르면 그 행 바탕이 회색으로 바뀌고 화살표가 위로 뒤집히며, 바로 아래에 답이 열린다. 나머지 행은 아래로 밀린다.
- 답 아래에 회색 상자 "궁금하신 내용이 해결 되었나요?" + 예/아니오 선택 + "평가하기" 버튼이 붙는다.
- 1:1 문의 탭: 가운데 회색 카드 한 장(아이콘, 두 줄 제목, 안내 세 줄, 검정 알약 버튼 "채팅 상담하기"). 1:1 문의를 종료했다는 안내이고, 탭을 없애지 않고 대신 갈 곳을 버튼으로 준다.
- 공지사항: 왼쪽 제목 → 행 10개(왼쪽 "[공지]/[안내] 제목", 오른쪽 날짜 + 화살표) → 쪽 번호 1~5 + "페이지당 10개" 선택. 행을 누르면 FAQ와 같은 방식으로 그 자리에서 본문이 열린다. 상세 페이지로 넘어가지 않는다. 중요 공지를 따로 고정하지 않고 제목 앞 말머리로만 구분한다.
- PC와 모바일 차이:
  - 전화 띠가 두 줄(번호 / 운영시간)로 바뀐다.
  - 분류 칩 줄은 줄바꿈하지 않고 가로로 밀어 넘긴다. 오른쪽 끝 칩이 잘려 보인다.
  - 긴 질문은 두 줄로 줄바꿈된다. 공지 제목은 한 줄에서 말줄임되고 날짜·화살표는 오른쪽에 남는다.
  - 공지의 "페이지당 10개" 선택이 전체 폭 한 줄로 쪽 번호 위에 온다.
  - 하단에 고정 탭(홈·카테고리·프로젝트·마이페이지·장바구니)이 붙는다.

### 가져올 것

- 탭마다 주소를 따로 주는 방식. 이유: 담당자가 "주문방법은 여기 보세요" 하고 주소를 메신저로 넘길 때 같은 탭이 열려야 한다. 우리 고객센터 네 부분(주문방법·공지사항·자주 묻는 질문·1:1 문의)에 그대로 쓴다.
- 탭 위의 전화·운영시간 띠 한 줄. 이유: 상담 연결 정보가 어느 탭에서나 같은 자리에 보인다. 우리는 전화 + 카카오톡 상담을 같은 띠에 둔다.
- 분류 칩 → 검색창 → 질문 행 순서, 행 전체가 눌리고 오른쪽에 화살표가 있는 펼침. 이유: 분류를 먼저 좁히고 그래도 못 찾으면 검색하는 순서가 질문 수가 수십 개인 우리 규모에 맞다.
- 공지와 FAQ가 같은 행 펼침 부품을 쓰는 것. 이유: 부품 하나로 FAQ·공지(짧은 글)·1:1 문의 내역을 모두 만들 수 있다.
- 모바일 칩 줄의 가로 밀기 + 끝 칩 잘림. 이유: 줄바꿈하면 칩이 세 줄을 차지해 질문 목록이 첫 화면 밖으로 밀린다.

### 바꿔서 쓸 것

- 탭 2개 → 4개. 폭을 4등분하면 "자주 묻는 질문"이 모바일에서 두 줄이 되므로, 우리는 DESIGN.md의 `.bh` 탭(글자 폭만큼, 가로 밀기)으로 둔다.
- "TOP10" 칩 → "전체" 칩을 첫 칸에 두고 자주 찾는 질문을 맨 위에 둔다. 이유: 우리 질문 수가 적어서 따로 순위 묶음을 만들 필요가 없다.
- 1:1 문의 탭의 안내 카드 → 비회원이 탭을 열었을 때의 화면으로 바꿔 쓴다(가운데 카드 한 장에 "주문번호와 연락처로 문의 확인" 입력과 "로그인" 버튼). 이유: 탭을 숨기지 않고 다음 행동을 버튼으로 주는 구조가 같다.
- 공지 행 펼침은 짧은 공지에만 쓰고, 이미지가 있거나 긴 공지는 상세 주소로 연다(컬리 방식). 이유: 공지 상세도 주소로 공유할 수 있어야 한다.

### 쓰지 않을 것

- 답 아래 "해결 되었나요?" 평가 상자. 이유: 평가를 받아 처리할 운영 흐름이 없다. 대신 답 아래에 "1:1 문의하기" 링크 한 줄만 둔다.
- "페이지당 10개" 선택. 이유: 공지 수가 적어 쪽 번호만으로 충분하다.
- 맨 위 홍보 띠. 이유: 고객센터에서는 본문을 한 줄 밀어낼 뿐이다.

- 주소: https://www.kurly.com/board/notice , https://www.kurly.com/board/notice/detail/2323 , https://www.kurly.com/board/faq (모바일에서 FAQ는 `/mypage/faq` 로 넘어간다)
- 본 날짜: 2026-11-17
- 캡처: `kurly-notice-pc.jpg`, `kurly-notice-m.jpg`, `kurly-notice-detail-pc.jpg`, `kurly-notice-detail-m.jpg`, `kurly-faq-pc.jpg`, `kurly-faq-m.jpg`(질문 한 개 펼친 상태)

### 관찰한 사실

- PC는 두 칸이다. 왼쪽(약 200px): "고객센터" 제목 → 테두리 있는 세로 메뉴 4개(공지사항 / 자주하는 질문 / 1:1 문의 / 대량 주문 문의, 각 행 오른쪽에 > 표시, 현재 항목은 글자색과 옅은 바탕으로 구분) → 회색 바로가기 카드 한 장("취소·반품접수 >" + 한 줄 설명). 오른쪽(약 820px): 제목과 한 줄 설명이 같은 줄 → 목록.
- 메뉴 항목마다 주소가 다르다(`/board/notice`, `/board/faq`).
- 공지 목록: 위에 굵은 선 → 머리 행(번호 / 제목 / 작성자 / 작성일) → 15행. 맨 위 3행은 번호 칸에 숫자 대신 "공지"가 적혀 있고 날짜가 오래됐는데도 맨 위에 있다(고정 공지). 그 아래는 번호가 큰 순서다. 쪽 이동은 이전/다음 네모 버튼 2개뿐이고 쪽 번호는 없다.
- 공지 상세(PC): 왼쪽 메뉴가 사라지고 제목이 가운데로 온다. 굵은 선 아래에 제목 / 작성자 / 작성일 세 행(왼쪽 이름 칸은 회색 바탕) → 본문 → 선 → 오른쪽 아래 "목록" 버튼.
- FAQ(PC): 제목 줄 오른쪽 끝에 분류 선택 상자("전체"). 표는 번호 / 카테고리 / 제목 세 칸, 15행. 행을 누르면 바로 아래에 답 행이 열린다(작은 A 표식 + 본문). 검색창은 없다.
- PC와 모바일 차이:
  - 공지 목록이 표에서 두 줄 행으로 바뀐다. 첫 줄: 왼쪽 "공지" 또는 번호(회색), 오른쪽 날짜. 둘째 줄: 굵은 제목 한 줄(넘치면 말줄임). 작성자 칸은 없다.
  - 모바일 공지 목록에는 쪽 버튼이 보이지 않고 아래로 계속 이어진다(캡처 때 문서 높이 13,607px).
  - 왼쪽 메뉴가 없다. 위에 뒤로 가기 화살표 + 가운데 제목 + 장바구니가 있는 머리 줄이 붙는다.
  - 공지 상세: 제목 한 줄 → 작성자(왼쪽)·날짜(오른쪽) 한 줄 → 본문. 본문 안의 표는 폭에 맞춰 줄어들어 글자가 작게 보인다.
  - FAQ: 왼쪽 위 X가 있는 전체 화면 한 장으로 열린다. 맨 위에 분류 선택 상자(전체 폭) → 행마다 동그란 Q 표식 + 질문. 번호·카테고리 칸은 없다. 펼치면 회색 바탕 칸에 동그란 A 표식 + 답.

### 가져올 것

- 번호 칸에 "공지"를 넣고 맨 위에 고정하는 중요 공지 구분. 이유: 색 띠나 아이콘 없이 글자 하나로 구분되고 표 구조가 그대로다. 우리는 "중요" 글자를 쓴다.
- 모바일 공지 행의 두 줄 구성(첫 줄 표식·날짜, 둘째 줄 제목). 이유: 390px에서 표를 유지하면 제목이 12자 안팎에서 잘린다.
- 공지 상세의 순서(제목 → 작성일 → 본문 → 목록 버튼)와 상세마다 따로 있는 주소. 이유: 공지 하나를 주소로 넘길 수 있다.
- Q 행 아래에 회색 바탕 A 칸이 열리는 모바일 FAQ 구성. 이유: 1:1 문의 내역의 "내 문의 → 답변" 펼침에 그대로 맞는다(문의 내용 흰 바탕, 답변 회색 바탕 + "답변" 표식).
- 고객센터 메뉴 옆의 바로가기 카드 한 장. 이유: 가장 잦은 용건(우리는 "견적·시안 요청")을 메뉴와 따로 한 번 더 보여 준다.

### 바꿔서 쓸 것

- 왼쪽 세로 메뉴 → 위쪽 가로 탭. 이유: DESIGN.md가 고객센터를 `.sub-head` 아래 `.bh` 탭으로 정했고, 모바일에서 같은 부품을 그대로 쓸 수 있다. 메뉴마다 주소가 다른 점만 가져온다.
- 공지 상세에서 메뉴가 사라지는 것 → 우리는 상세에서도 탭 줄을 남긴다. 이유: 상세 주소로 바로 들어온 사람이 FAQ·문의로 옮겨 갈 길이 있어야 한다.
- 작성자 칸 → 뺀다. 이유: 글쓴이가 항상 우리 회사라서 정보가 없다. 번호·제목·날짜 세 칸만 둔다.
- 이전/다음 버튼만 있는 쪽 이동 → 쪽 번호를 함께 둔다. 이유: 공지가 몇 쪽인지 알 수 없다.
- 본문 안 표가 모바일에서 줄어드는 것 → 표는 가로로 밀어 보게 하고 글자 크기는 줄이지 않는다.

### 쓰지 않을 것

- FAQ 분류를 선택 상자 하나로만 고르는 방식. 이유: 어떤 분류가 있는지 눌러 봐야 보인다. 분류 칩 줄(오프린트미)이 한눈에 보인다.
- FAQ의 번호 칸. 이유: 질문 번호는 찾는 데 쓰이지 않는다.
- 모바일 공지 목록의 끝없는 이어 보기. 이유: 푸터의 사업자 정보·고객센터 번호에 닿지 못한다.
- 모바일 FAQ를 전체 화면 한 장으로 따로 여는 것. 이유: 탭 줄이 사라져 다른 부분으로 옮길 수 없다.

### 관찰한 사실

- 리뷰 목록(PC) 순서: 제목 "상품 리뷰 (145,209)"(개수를 제목에 붙임) → 한 줄에 왼쪽 분류 칩 11개(전체, 가족·반려동물, 일러스트, 팬굿즈, 커플·우정, 스포츠, 커뮤니티, 스몰 브랜드, 프로모션, 공공기관, 단체/기업 사례), 오른쪽 "모든 상품 ▾" 선택 + "포토리뷰" 켜고 끄는 스위치 → 4열 카드.
- 카드 한 장: 정사각 사진(일부는 왼쪽 위 "Hot" 표식) → 별점(왼쪽)·가린 아이디·날짜(오른쪽) 한 줄 → 본문 두 줄(넘치면 "Read more") → 구매 품목 한 줄(작은 그림 + 품목명 + 옵션) → 품목 분류 링크("쿠션/방석 더보기"). 카드 사진은 한 장이고 카드 안에서 사진을 넘기는 표시는 보이지 않는다.
- 리뷰 상세(PC) 순서: 위치 줄("실시간 리뷰 > 리뷰 상세보기") → 가운데 카드 한 장(폭 약 640px)을 좌우로 나눔: 왼쪽에 표식·별점·옵션·아이디·날짜·본문, 그 아래 품목 카드(작은 그림, 품목명, 가격, 평점·후기 수, 검정 알약 버튼), 오른쪽에 정사각 사진 → 테두리 알약 버튼 "9,074개 쿠션/패브릭 후기 더보기" → "다른 고객이 함께 본 상품" 4열.
- 이벤트 목록(PC): 제목 "이벤트 전체보기" → 4열 × 3행 12개. 카드: 정사각 이미지 → 제목 한 줄(넘치면 말줄임) → 기간(시작 일시 ~ 끝 일시). 끝난 이벤트는 제목 끝에 "(마감)"이 붙어 있고 진행/종료 탭이나 필터는 없다.
- PC와 모바일 차이:
  - 리뷰 목록: 4열 → 2열. 카드에서 본문·구매 품목·분류 링크가 빠지고 사진 + 별점 + 아이디·날짜만 남는다. 칩 줄은 가로로 밀고, 그 아래 줄에 "모든 상품 ▾"(왼쪽)과 "포토리뷰" 스위치(오른쪽)가 온다.

  - 이벤트: 4열 → 1열. 이미지가 전체 폭 정사각이 된다.
  - 하단 고정 탭 5개 가운데 하나가 "리뷰"다. 오른쪽 아래에 상담 버튼이 떠 있다.

### 가져올 것

- 제목에 후기 개수를 붙이고, 같은 줄에 분류 칩과 "사진 후기만" 스위치를 두는 구성. 이유: 우리 칩(전체·글 후기·납품 사진)과 같은 역할이고, 스위치 하나로 사진 있는 후기만 추릴 수 있다.
- 카드 정보 순서(사진 → 별점·작성자·날짜 → 본문 두 줄 → 구매 품목 한 줄). 이유: 구매 담당자가 "어떤 품목에 대한 후기인가"를 카드에서 바로 확인한다.
- 상세의 두 칸 구성(글과 품목 카드 한쪽, 사진 한쪽)과 그 아래 "이 품목 후기 더 보기" 버튼. 이유: 후기에서 해당 품목 상세나 같은 품목 후기로 이어지는 길이 한 화면에 있다.
- 이벤트 카드의 구성(이미지 → 제목 한 줄 → 기간)과 모바일 1열. 이유: 이벤트 이미지 안에 글자가 들어 있어 2열로 줄이면 읽히지 않는다.

### 바꿔서 쓸 것

- 4열 → 후기는 3열(PC)·2열(모바일). 이유: DESIGN.md의 `.rv__list`가 3열/2열이고, 본문 두 줄을 읽으려면 카드 폭이 필요하다.
- 사진 한 장 카드 → 사진이 여러 장인 후기는 카드 사진 오른쪽 아래에 "1/4" 장수 표시를 두고, PC에서는 사진 위에 올렸을 때 좌우 화살표, 모바일에서는 손가락으로 민다. 이유: 납품 사진은 한 후기에 여러 장이다. 이 부분은 마플에서 본 것이 아니라 아래 Baymard 근거에 따른 것이다.
- 모바일에서 본문을 모두 빼는 것 → 본문 두 줄은 남기고 구매 품목 줄만 뺀다. 이유: 우리 후기는 사진 없는 글 후기도 있다.
- 품목 카드의 버튼("커스텀하기") → "견적문의" 또는 "상품 보기". 이유: 우리 흐름은 장바구니 → 견적 요청이다.
- 이벤트 끝남 표시를 제목 글자("(마감)")로 하는 것 → 진행 중을 앞에, 끝난 것을 뒤에 두고 끝난 카드는 이미지 위에 "종료" 표식을 얹는다. 이유: 제목이 말줄임되면 "(마감)"이 잘려 보이지 않는다(캡처 4번째 카드가 그렇다).
- 기간의 시·분 표기 → 날짜만 적는다. 이유: 우리 이벤트는 날짜 단위다.

### 쓰지 않을 것

- "Hot" 표식. 이유: 기준을 밝힐 수 없는 표식은 쓰지 않는다(DESIGN.md 문구 원칙).
- 가린 아이디만 적는 작성자 표기. 이유: B2B 후기는 업종·단체 종류(예: "제조업 · 80벌")가 더 쓸모 있다.
- 상세 아래 "함께 본 상품" 4열. 이유: 후기 상세의 목적은 그 품목으로 보내는 것이고 품목 카드 한 장이면 된다.
- 카드마다 붙는 분류 링크("쿠션/방석 더보기"). 이유: 위의 칩 필터와 역할이 겹친다.

## 4. 채널톡 고객사례 (블로그 안의 묶음)

- 본 날짜: 2026-11-17
- 캡처: `channel-cases-pc.jpg`, `channel-cases-m.jpg`, `channel-cases-filter-pc.jpg`, `channel-cases-filter-m.jpg`(업종 필터를 연 상태), `channel-cases-detail-pc.jpg`, `channel-cases-detail-m.jpg`

### 관찰한 사실

- PC는 두 칸이다. 왼쪽(약 240px): "블로그" 제목 → 세로 메뉴 8개(홈, 이벤트, 성공사례, 채널톡 사용팁, 비즈 인사이트, 워크북, 개념허브, 뉴스룸. 현재 항목은 옅은 바탕) → 선 → 바깥 링크 한 개 → 검색창. 이벤트·사례·읽을거리를 한 메뉴로 묶었다.
- 오른쪽 순서: 큰 제목 "고객사례" → 한 줄 설명(필터 쓰는 법) → 선 → 필터 버튼 2개("업종", "기능") → 대표 사례 한 장(왼쪽 큰 사진, 오른쪽 제목·업체명·날짜) → 3열 카드.
- 카드 한 장: 가로형 사진 위 가운데에 업체 로고(흰색)가 얹혀 있고 오른쪽 위에 작은 표식 → 제목 두 줄 → "[성공 사례] 업체명" 한 줄 → 날짜·글쓴이.
- 필터(PC): 버튼 바로 아래에 작은 패널이 열린다. 체크 상자 10개(패션, 뷰티, F&B, 라이프스타일, 홈리빙, 교육, B2B, 여행, 엔터테인먼트, 기타) → 맨 아래 전체 폭 "적용" 버튼. 여러 개를 고른 뒤 한 번에 적용한다.
- 상세(PC): 왼쪽 메뉴는 그대로, 본문 폭 약 660px. 순서: 대표 사진(로고 얹음) → 제목 → 업체명 → 글쓴이·날짜 → 태그 칩 → 회색 요약 상자("[사례 요약]": 이름, 업종, 고민, 활용 기능, 성과를 항목으로) → "1. 고객사 소개" 사진 + 항목 → "2. 도입 배경" → "3. …" 번호 붙은 절. 오른쪽 위에 "공유하기".
- PC와 모바일 차이:
  - 왼쪽 메뉴가 "블로그 ⌄" 한 줄(펼침 선택)과 돋보기 아이콘으로 접힌다.
  - 대표 사례는 사진 아래로 제목이 내려온다. 그 아래 목록은 3열 카드가 아니라 한 줄 행(왼쪽 제목 두 줄·업체명·날짜, 오른쪽 작은 사진 약 90px)으로 바뀐다.
  - 필터는 화면 아래에서 올라오는 패널이다. 뒤 화면은 어두워지고, 항목이 세로로 나열되며 맨 아래에 "적용" 버튼이 있다.
  - 상세는 같은 순서의 한 칸이다.

### 가져올 것

- 사진 위에 업체 로고를 얹은 사례 카드. 이유: "어느 업체의 사례인가"와 "어떤 모습인가"를 카드 한 장에서 함께 본다. 우리 납품사례(1:1 사진 + 업체명 + 품목)에 로고가 있는 업체는 사진 왼쪽 아래에 로고를 얹는다.
- 상세 맨 위의 요약 상자. 이유: 구매 담당자는 본문을 다 읽지 않는다. 우리는 "업체 · 업종 · 품목과 수량 · 인쇄 방식 · 납기"를 항목으로 둔다.
- 종류가 다른 콘텐츠를 한 메뉴로 묶고 현재 항목만 바탕색으로 표시하는 방식, 모바일에서 그 메뉴를 제목 줄의 펼침 선택 한 줄로 접는 방식. 이유: 납품사례·구매후기·이벤트·파트너십 네 개를 오갈 때 같은 자리에 메뉴가 있다.
- 모바일 필터 패널(아래에서 올라옴, 맨 아래 "적용"). 이유: 품목·업종 필터가 칩 한 줄에 다 들어가지 않을 때 쓴다.
- 대표 사례 한 장을 목록 위에 크게 두는 것. 이유: 가장 보여 주고 싶은 납품 한 건을 먼저 보여 준다.

### 바꿔서 쓸 것

- 왼쪽 세로 메뉴 8개 → 묶음 메뉴 4개(납품사례·구매후기·이벤트·파트너십)는 제목 아래 가로 탭 한 줄로 둔다. 이유: 항목이 4개뿐이라 왼쪽 240px를 쓰면 사진 격자가 3열로 줄어든다.
- 필터 버튼을 눌러야 보이는 선택지 → 품목 칩을 바로 한 줄로 보여 준다(DESIGN.md `.chips`). 이유: 우리 품목 분류는 10개 이하이고, 눌러야 보이는 필터는 "기타 업종도 있나"를 알 수 없다. 칩이 한 줄을 넘는 모바일에서만 패널을 쓴다.
- 모바일 목록의 작은 사진 행 → 우리는 모바일에서도 사진 카드 2열을 유지한다. 이유: 납품사례는 글보다 사진이 내용이다.
- 가로형 사진 → 1:1 사진. 이유: DESIGN.md의 납품사례 카드 규칙.
- 번호 붙은 긴 본문 → 사진 여러 장 + 두세 문단. 이유: 우리 사례는 인터뷰 글이 아니라 납품 기록이다.

### 쓰지 않을 것

- 카드의 글쓴이 이름, 오른쪽 위 기능 표식. 이유: 우리 사례에는 해당 정보가 없다.
- 상세의 태그 칩 줄. 이유: 위의 품목 칩과 겹친다.
- 맨 위 노란 홍보 띠와 떠 있는 상담 말풍선. 이유: 모바일에서 말풍선이 필터 패널의 "적용" 버튼을 가렸다(첫 캡처에서 확인).

## 5. 쏘카 이용 안내

- 주소: https://www.socar.kr/guide
- 본 날짜: 2026-11-17
- 캡처: `socar-guide-pc.jpg`(질문을 펼치지 않은 상태), `socar-guide-m.jpg`(질문 한 개 펼친 상태)

### 관찰한 사실

- PC 문서 높이가 푸터까지 2,060px이다. 여섯 단계 안내가 첫 화면에서 한 번만 내리면 끝난다.
- 순서: 큰 제목 "이용 안내" → 좌우 두 칸. 왼쪽(약 600px): 작은 제목 → 방법 카드 2장이 나란히("웹", "앱". 카드마다 할 수 있는 일 4~5줄 + 전체 폭 버튼 하나. 웹 카드는 채운 버튼, 앱 카드는 옅은 버튼) → 번호 단계 6개(①~⑥. 굵은 제목 한 줄 + 회색 설명 한두 줄) → 테두리 링크 버튼 한 개(요금 안내로 이동). 오른쪽(약 600px): 세로로 긴 사진 한 장이 방법 카드부터 마지막 단계까지의 높이를 채운다.
- 단계마다 화면 예시 그림은 없다. 그림은 오른쪽 사진 한 장뿐이다.
- 그 아래 전체 폭: "자주 묻는 질문" 펼침 행 5개 → 회색 상자(한 줄 문장 + 가운데 버튼 "웹에서 예약하기").
- 단계 제목은 모두 "~하기"로 끝나는 행동 이름이다(가입하기, 운전면허 등록하기, 결제수단 등록하기, 예약·결제하기, 차량 찾기·이용하기, 반납하기).
- PC와 모바일 차이: 오른쪽 사진이 없어진다. 방법 카드 2장이 세로로 쌓인다. 단계는 같은 순서로 쌓이고 설명이 두세 줄이 된다. 문서 높이 3,206px. 펼친 질문의 답은 회색 둥근 상자 안에 나온다. 위에 뒤로 가기 화살표 + 제목 + 메뉴 아이콘 머리 줄이 붙는다.

### 가져올 것

- "방법 두 가지 카드 → 번호 단계 → 자주 묻는 질문 → 시작 버튼" 순서. 이유: 우리 주문방법도 "주문 종류 두 가지 → 5단계 → 주문 관련 질문 → 견적 요청"으로 같은 뼈대다.
- 단계마다 제목 한 줄 + 설명 두 줄 이내로 끊는 분량. 이유: 5단계 전체가 스크롤 한 번 안에 들어온다.
- 단계 제목을 행동 이름으로 쓰는 것. 이유: "1단계" 같은 번호만으로는 무엇을 하는지 알 수 없다. 우리는 "상품 담기", "인쇄 시안 요청하기", "견적 받기", "입금·제작 확인하기", "배송 받기" 식으로 쓴다.
- 주문방법 페이지 안에 관련 질문 5개를 함께 두는 것. 이유: 주문 단계에서 생기는 질문(최소 수량, 시안 수정 횟수, 납기)을 FAQ 탭으로 옮기지 않고 그 자리에서 푼다.
- 모바일에서 꾸밈 사진을 빼는 것. 이유: 단계 글이 먼저 보인다.

### 바꿔서 쓸 것

- 방법 카드 2장(웹/앱) → "인쇄 있는 주문 / 인쇄 없는 주문" 두 칸 선택으로 바꾸고, 고른 쪽의 단계만 아래에 보여 준다. 이유: 두 종류의 단계를 모두 펼치면 길이가 두 배가 된다. 선택 값은 주소에 남겨 공유할 수 있게 한다.
- 오른쪽의 꾸밈 사진 한 장 → 화면 예시 한 칸. 왼쪽 단계 목록에서 고른 단계의 화면 예시만 오른쪽 칸에 보여 준다(처음에는 1단계). 이유: 화면 예시를 단계마다 세로로 쌓으면 5장 × 두 종류로 길어진다. 쏘카가 왼쪽 글·오른쪽 그림 한 칸으로 높이를 맞춘 구조를 화면 예시에 쓴다. 이 조작(단계를 고르면 그림이 바뀜)은 쏘카에 있는 것이 아니라 우리가 더하는 것이다.
- 모바일에서 그림을 없애는 것 → 단계마다 "화면 예시 보기"를 접어 두고 누르면 그 단계 아래에 그림이 열리게 한다. 이유: 화면 예시는 꾸밈이 아니라 안내 내용이라 없앨 수 없다.
- 단계 6개 → 5개.

### 쓰지 않을 것

- 방법 카드 안의 기능 나열 4~5줄. 이유: 우리 두 종류의 차이는 "인쇄 시안 단계가 있다/없다" 한 줄이다.
- 맨 아래 회색 상자의 큰 버튼 하나만 두는 마무리. 이유: 우리는 "견적 요청"과 "카카오톡 상담" 두 길을 함께 둔다.

- 1:1 문의 내역, 비회원 문의 확인, 문의 작성 양식: 로그인·제출을 하지 않아 실제 화면을 보지 못했다. 위의 제안은 공개된 FAQ·공지의 행 펼침을 옮겨 쓴 것이다.

- 화면 예시가 단계마다 붙고 주문 종류가 두 가지인 주문 안내: 같은 구성을 가진 곳을 찾지 못했다. 쏘카의 뼈대에 우리가 조작을 더한 제안이다.
- 업체 로고만 모아 둔 목록: Notion(로고 한 줄)과 비즈하우스(로고 두 줄)에서 보았지만 남기지 않았다.

## 이 유형에 그대로 쓸 수 있는 문장

1. 고객센터는 제목 아래에 전화번호·카카오톡·운영시간을 적은 회색 띠 한 줄을 두고, 그 아래에 탭 네 개(주문방법·공지사항·자주 묻는 질문·1:1 문의)를 한 줄로 둔다. 탭마다 주소 값을 따로 주어 그 주소를 열면 같은 탭이 선택된 채로 열리게 한다.
2. 자주 묻는 질문은 분류 칩 한 줄("전체"가 첫 칸) → 검색창 → 질문 행 순서로 놓는다. 질문 행은 행 전체가 눌리고 오른쪽 끝에 화살표가 있으며, 누르면 행 바로 아래에 답이 열리고 다른 행은 닫히지 않는다. 모바일에서 칩 줄은 가로로 밀고 오른쪽 끝 칩이 잘려 보이게 둔다.
3. 공지 목록은 PC에서 번호·제목·날짜 세 칸 표로 두고, 중요 공지는 번호 칸에 "중요" 글자를 넣어 날짜와 상관없이 맨 위에 고정한다. 모바일에서는 한 행을 두 줄로 바꿔 첫 줄에 "중요" 또는 번호와 날짜, 둘째 줄에 제목 한 줄을 둔다.
4. 공지 상세는 따로 주소가 있는 페이지로 열고, 제목 → 날짜 → 본문 → "목록" 버튼 순서로 둔다. 상세에서도 고객센터 탭 줄은 그대로 남긴다.
5. 1:1 문의 내역은 FAQ와 같은 행 펼침을 쓴다. 닫힌 행에는 답변 상태("답변 대기"/"답변 완료")·제목·날짜를 두고, 펼치면 내 문의 내용(흰 바탕) 아래에 답변(회색 바탕, "답변" 표식과 답변 날짜)이 열린다. 비회원이 이 탭을 열면 목록 자리에 "주문번호와 연락처로 문의 확인" 입력 카드 한 장과 "로그인" 버튼을 둔다.
6. 주문방법은 맨 위에 "인쇄 있는 주문 / 인쇄 없는 주문" 두 칸 선택을 두고 고른 쪽의 5단계만 보여 준다. PC에서는 왼쪽에 번호 단계 5개(행동 이름 제목 한 줄 + 설명 두 줄 이내), 오른쪽 한 칸에 고른 단계의 화면 예시 한 장을 둔다. 모바일에서는 단계를 세로로 쌓고 화면 예시는 단계마다 "화면 예시 보기"로 접어 둔다. 단계 아래에 주문 관련 질문 5개와 "견적 요청"·"카카오톡 상담" 버튼을 둔다.
7. 구매후기 목록은 제목에 후기 개수를 붙이고, 그 아래 한 줄에 분류 칩(왼쪽)과 "사진 후기만" 스위치(오른쪽)를 둔다. 카드는 PC 3열·모바일 2열이고 사진 → 별점·작성자·날짜 → 본문 두 줄 → 구매 품목 한 줄 순서다. 사진이 여러 장인 카드는 사진 오른쪽 아래에 "1/4" 장수를 적고 PC는 화살표, 모바일은 밀기로 넘긴다.
8. 후기 상세는 PC에서 두 칸(왼쪽 별점·작성자·본문·구매 품목 카드, 오른쪽 사진과 작은 그림 줄), 모바일에서 본문 → 사진 → 구매 품목 카드 순서의 한 칸으로 두고, 아래에 "이 품목 후기 더 보기" 버튼을 둔다. 사진을 누르면 열리는 큰 화면에서는 다음 후기의 사진까지 이어서 넘길 수 있게 한다.
9. 이벤트 목록은 PC 4열·모바일 1열의 이미지 카드로 두고, 이미지 아래에 제목 한 줄과 기간(시작일 ~ 종료일)을 적는다. 진행 중인 이벤트를 앞에 두고, 끝난 이벤트는 뒤로 보내 이미지 위에 "종료" 표식을 얹는다.
10. 납품사례·구매후기·이벤트·파트너십은 제목 아래 가로 탭 한 줄로 묶어 네 페이지에서 같은 자리에 둔다. 납품사례는 품목 칩 → 사진 카드 격자(1:1 사진 왼쪽 아래에 업체 로고, 아래에 업체명·품목) 순서로 두고, 상세 맨 위에 요약 상자(업체·업종·품목과 수량·인쇄 방식·납기)를 둔다. 모바일에서 칩이 한 줄을 넘으면 아래에서 올라오는 패널로 바꾸고 맨 아래에 "적용" 버튼을 고정한다.
