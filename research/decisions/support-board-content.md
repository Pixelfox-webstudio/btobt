# 구매후기 · 이벤트 · 납품사례 구조 결정

대상: `reviews.html`(구매후기 목록), `review-view.html`(구매후기 상세), `event.html`(이벤트 목록), `event-view.html`(이벤트 상세), `delivery-cases.html`(납품사례)
본 캡처: `research/refs/support-board/`의 마플 후기 목록·상세·이벤트, 채널톡 고객사례 목록·상세·필터 (PC 1440 · 모바일 390). 기록은 같은 폴더의 `notes.md`.
자료: 후기 = `js/reviews.js`(실제 후기 23건, 사진 `img/reviews/`). 이벤트·납품사례 자료는 없다.

## 캡처에서 확인한 사실

| 곳 | PC | 모바일 |
|---|---|---|
| 마플 후기 목록 | 제목 옆에 후기 수, 4열 카드. 카드 = 정사각 사진 한 장 → 별점·아이디·날짜 한 줄 → 본문 두 줄 → 구매 품목 한 줄. 카드 안에서 사진을 넘기는 표시는 없다 | 2열. 본문과 품목 줄이 빠지고 사진 + 별점 + 아이디만 남는다 |
| 마플 후기 상세 | 가운데 폭 약 640px 카드 한 장을 좌우로 나눔(왼쪽 별점·본문·품목 카드, 오른쪽 정사각 사진). 아래에 같은 품목 후기 더 보기 버튼 | 한 칸: 별점 → 본문 → 전체 폭 사진 → 품목 카드 |
| 마플 이벤트 목록 | 4열 × 3행. 카드 = 정사각 이미지 → 제목 한 줄 → 기간. 진행/종료 탭 없음 | 1열, 이미지 전체 폭 |
| 채널톡 고객사례 | 큰 제목 → 한 줄 설명 → 3열 카드(사진 위에 업체 로고) | 대표 사례 사진 아래 제목, 나머지는 작은 사진 행 |
| 채널톡 사례 상세 | 본문 폭 약 660px. 대표 사진 → 제목 → 업체명 → 회색 요약 상자(이름·업종·고민·성과) → 번호 절 | 같은 순서 한 칸 |
| 채널톡 묶음 메뉴 | 이벤트·성공사례 등 8개를 왼쪽 세로 메뉴로 묶음. 현재 항목만 바탕색 | "블로그 ⌄" 한 줄로 접힘 |

## 요소 목록이 요구하는 것(요약)
- 다섯 페이지 모두: 경로, 페이지 제목, 묶음 메뉴(납품사례·구매후기·이벤트·파트너십).
- 후기 목록: 한 쪽 12건, 최신 등록순, 카드마다 사진 최대 5장(넘겨 보기 + 원하는 사진 바로 보기), 평가 수치(최고 5, 소수, 숫자 함께), 내용 일부, 회사명, 업종. 쪽 번호는 2쪽 이상일 때 모든 번호. 빈 상태.
- 후기 상세: 회사명·업종·등록일, 사진(넘겨 보기, 잘리지 않게 전체), 평가 수치, 전체 내용, 목록으로(항상), 찾을 수 없음.
- 이벤트 목록: 대표 이미지 + 제목, 최신순, 빈 상태. 이벤트 상세: 제목·등록일·이미지(본문), 목록으로(항상), 찾을 수 없음.
- 납품사례: 업체 목록(로고·업체명) → 업체를 고르면 그 업체 사례(로고·업체명·설명(있을 때)·사진 목록) → 사진 크게 보기·닫기. 빈 상태.
- 목록에 없는 것: 후기 분류 칩·"사진 후기만" 스위치, 이벤트 기간·종료 표시, 납품사례 품목 필터와 요약 상자. 레퍼런스 기록이 제안했지만 넣지 않는다.

## 구조 후보

1. **채널톡식 왼쪽 세로 메뉴 + 오른쪽 내용**: 네 페이지를 왼쪽 240px 메뉴로 묶는다. 항목이 4개뿐이라 왼쪽 칸이 대부분 비고, 후기 카드가 3열에서 2열로 줄어 홈의 `.rv__list`(3열)와 크기가 달라진다.
2. **마플식 카드 목록 + 상세 페이지, 묶음 메뉴는 제목 아래 밑줄 탭**: 목록은 홈 부품(후기 카드 `.rv__card`, 사진 16px 카드)을 그대로 키워 쓰고, 상세는 따로 주소가 있는 페이지로 연다. 납품사례는 업체 로고 벽 → 고른 업체 사례를 같은 페이지 아래에 연다.
3. **목록에서 팝업으로 상세 보기**(홈의 "후기 전체 보기" 팝업처럼): 요소 목록이 후기 상세·이벤트 상세를 따로 주소가 있는 페이지로 두고 "목록으로 돌아가기"와 "찾을 수 없음" 안내를 요구하므로 맞지 않는다.

## 결정: 2번

### 공통 골격
- 순서: `.sub-head`(경로 → 제목 → 한 줄 설명) → 묶음 메뉴 `.stab`(밑줄 탭 네 개, 지금 페이지에 `aria-current="page"`) → `.sub-body`.
  - 근거: 채널톡이 종류가 다른 콘텐츠를 한 메뉴로 묶고 네 페이지에서 같은 자리에 둔다. 항목이 4개라 왼쪽 메뉴 대신 가로 탭 한 줄로 둔다(후보 1을 버린 이유). 탭은 공용 `.stab`이고 폰에서는 옆으로 민다.
- 상세 페이지의 제목(h1)은 요소 목록대로 "구매후기" · "이벤트"로 두고, 후기 회사명 · 이벤트 제목은 본문의 h2로 둔다.

### 구매후기 목록
- 탭 아래부터 화면 끝까지 회색 구역(`#F5F5F6`)을 깔고 그 안에 흰 후기 카드를 놓는다. 홈 구매 후기 구역과 같은 바탕·카드(`.rv__card`, 모서리 16, 아주 옅은 그림자)라서 같은 부품으로 보인다. 회색 구역은 푸터까지 이어 붙인다(홈도 후기 구역 바로 아래가 푸터다).
- 구역 맨 위 한 줄: 왼쪽 "후기 23건", 오른쪽 "최신 등록순". 정렬은 바꿀 수 없으니 글자로만 적는다.
- 격자: PC 3열 · 1024 이하 2열(홈 `.rv__list`와 같음) · 폰 2열(홈의 옆으로 밀기 대신 2열. 쪽 번호가 있는 목록이라 옆으로 밀면 12건을 다 보기 어렵다). 한 쪽 12건이면 PC 4줄, 폰 6줄이다.
- 카드: 사진(PC 3:2, 폰 1:1) → 평가(별 다섯 개 + 숫자, 오른쪽 끝에 업종 칩) → 회사명 | 품목(홈과 같은 `rv__meta`) → 내용 일부(PC 세 줄 · 폰 두 줄에서 자름). 같은 줄 카드 높이는 격자가 맞춘다.
  - 근거: 마플 카드의 정보 순서(사진 → 별점 → 본문 → 품목) 중 B2B에 필요 없는 아이디·날짜를 빼고 업종을 넣었다. 홈 카드의 "회사명 | 품목" 한 줄은 그대로 둔다.
- 카드 사진 넘기기: 한 장씩 옆으로 넘기는 칸(최대 5장). 아래에 장수만큼 가는 막대(누르면 그 사진으로 바로 감), 오른쪽 위에 "1/5". PC는 마우스를 올리면 좌우 화살표가 나오고, 폰은 손가락으로 민다. 막대 대신 점을 쓰지 않는 근거: 기록의 Baymard 글(점은 색상 선택으로 오해한다, 장수 숫자를 함께 보인다). 홈 상품 카드도 사진 위 막대(`.pc__bars`)를 쓴다.
- 사진이나 글을 누르면 그 후기 상세로 간다. 사진 칸은 넘기기 동작과 겹치지 않게 사진 자체만 링크로 둔다.
- 쪽 번호: 공용 `.pager`, `SUBDATA.pager(cur,total,true)`로 모든 번호를 보인다. 2쪽 이상일 때만 나온다. 바꾸면 주소가 `?page=2`로 바뀌고 목록 맨 위로 올라간다.
- 빈 상태: 격자 자리에 `.empty` 한 덩어리 + 납품사례 보기 · 견적문의 버튼.

### 구매후기 상세
- PC 두 칸(사진 7 : 글 5), 폰 한 칸(사진 → 글). 마플 상세의 좌우 나눔을 그대로 쓰되 사진을 크게 둔다(우리 후기는 사진이 주 내용이다).
- 사진 칸: 정사각 회색 바탕 위에 사진을 잘리지 않게(`object-fit:contain`) 놓고 옆으로 넘긴다. 아래에 작은 그림 줄(누르면 그 사진으로 감), 사진 위 좌우 화살표, 아래 가운데 "3 / 8". 작은 그림 줄을 쓰는 근거: 기록의 Baymard 글(더 있는 사진은 작은 그림으로 알린다). 사진이 한 장이면 화살표·장수·작은 그림 줄을 숨긴다.
- 글 칸: 평가(별 + 숫자 "4.5 / 5") → 회사명(h2) → 정보 줄 `dl`(업종 · 품목 · 등록일 · 사진 장수) → 후기 전체 내용 → "목록으로" 버튼.
- 찾을 수 없음: 같은 자리에 `.gate`(회색 표식 + 제목 + 설명 + 목록으로).

### 이벤트 목록 · 상세
- 목록: PC·1024 2열, 폰 1열의 큰 이미지 카드(16:9, 모서리 16) + 제목 한 줄. 견본 4건이라 2열 2줄이 된다. 마플의 4열은 우리 이벤트 수가 적어 카드가 작아지기만 하고, 폰 1열은 마플과 같다(이미지 안 글자가 읽혀야 한다). 요소 목록에 없는 기간·종료 표시는 넣지 않는다.
- 상세: 폭 860px 한 칸. 위 1px 검정 선 → 제목(h2) → 등록일 → 아래 1px 선 → 이벤트 이미지(본문, 원래 비율 그대로) → 가운데 "목록으로". 컬리 공지 상세의 제목 → 날짜 → 본문 → 목록 순서를 따른다.
- 이미지는 현장 연출 사진이라 `data-slot="event-이미지"` + `data-temp="ai"` + 사진 위 "연출 이미지입니다."를 붙인다. 제목은 할인·혜택 없이 사실만 쓴다.

### 납품사례
- 위: 업체 로고 벽. PC 8열 3줄(23곳), 1024~601 6열 격자, 600 이하는 2줄 가로 밀기(칸 130px 고정 = 390 화면에서 2.6칸, 높이를 2줄로 고정해 폰에서 길어지지 않게). 칸 = 흰 바탕 1px 선 상자(모서리 12, 홈 브랜드 로고 칸과 같은 값) 안에 로고 자리 + 사진 장수.
  - 가로 밀기 줄에서 고른 업체는 칸 왼쪽을 줄의 왼쪽 여백에 맞춰 늘 다 보이게 한다(첫 화면 · 업체를 고를 때 · 화면 폭이 바뀔 때). 붙임(scroll-snap)은 proximity · 칸 왼쪽 기준이라 맞춘 자리와 같다. 칸 폭을 % · vw로 주면 Chromium이 화면을 다시 그릴 때 스크롤 위치가 잘려 고른 칸이 밀려났기 때문에 px로 고정했다.
  - 로고 파일이 없어 로고 자리에 업체 이름을 글자 로고처럼 굵게 두고 `data-slot="client-logo"`를 붙인다. 로고 파일이 오면 이 자리에 그림을 넣고 업체명은 칸 아래 한 줄로 내린다.
  - 사례(설명이나 사진)가 있는 업체만 버튼이다. 없는 업체는 같은 칸이지만 누를 수 없고 장수 줄이 없다.
- 아래: 고른 업체의 사례. 위 1px 검정 선 → 머리(로고 칸 + 업체명 h2 + 정보 줄(납품 품목 · 사진 장수) + 설명(있을 때)) → 사진 격자(PC 4열 · 폰 3열, 1:1, 모서리 16). 사진을 누르면 어두운 바탕 위에 잘리지 않은 사진이 크게 열리고 좌우 화살표·장수·닫기, 키보드 ←/→/Esc를 쓴다.
  - 근거: 채널톡의 "사진 위 로고 + 업체" 카드를 그대로 쓰면 업체마다 사진이 한 장씩만 보인다. 요소 목록은 업체를 고르면 그 업체의 사진 목록을 보여 달라고 하므로, 로고 벽에서 고르고 아래에 사진 목록을 연다. 채널톡의 요약 상자는 요소 목록에 없어 정보 줄 두 칸만 둔다.
- 처음에는 첫 업체가 골라진 채로 열린다. 업체를 고르면 주소가 `?co=업체키`로 바뀌고, 폰이나 사례가 화면 아래에 있으면 사례 머리까지 내려 준다.
- 업체와 사진은 `js/reviews.js`의 업체 이름과 사진만 쓴다. 새 고객사 이름을 만들지 않는다.

## 자료에 없는 값(견본)
- 후기 평가 수치·업종·등록일: 자료에 없어 견본 값(`data-sample`). 업종은 요소 목록이 모든 후기에 요구하므로 23건 모두 채운다. 이름에서 분명한 13곳 외 10곳은 이름·품목·글에서 짐작한 견본이라 실제 업종으로 바꿔야 한다(`spec/questions/content.md`). 값을 비우면 칩·줄을 그리지 않는다.
- 폰 2열 후기 카드: 평가 줄과 업종 칩을 위아래 두 줄(20 + 6 + 24px)로 고정해 옆 카드와 회사명 줄 높이를 맞춘다. 본문 여백 16px 18px 20px, 글 14.5/1.75(홈 후기 카드 폰 값 그대로).
- `reviews.js`의 `temp: 1` 글은 고객 글이 아닌 화면 확인용 임시 글이라 그 글 칸에 `data-sample`을 붙인다. 글이 없는 후기는 홈처럼 "납품 사진" 칩만 두고 글을 지어 넣지 않는다.
- 이벤트 4건, 납품사례 설명은 견본(`data-sample`).

## 가져오지 않는 것
- 마플의 "Hot" 표식, 가린 아이디, 함께 본 상품 4열, 분류 칩·사진 후기 스위치: 요소 목록에 없다.
- 채널톡의 업종·기능 필터, 글쓴이, 태그 칩, 번호 붙은 긴 본문: 요소 목록에 없고 우리 사례는 납품 기록이다.
- 이벤트 기간과 "종료" 표식: 요소 목록에 없다.
