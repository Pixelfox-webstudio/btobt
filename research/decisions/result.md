대상: `order-complete.html`(주문 완료), `nicepay-return.html`(카드 결제 처리)
본 캡처: `research/refs/cart-checkout/`의 `govuk-confirmation-pc.jpg` · `govuk-confirmation-m.jpg`(접수 완료), `govuk-check-answers-m.jpg`(값만 보이는 요약 목록), `mardi-orderform-pc.jpg` · `-m.jpg`(주문서의 결제정보 요약), `apple-checkout-fulfillment-pc.jpg` · `-m.jpg`(유의사항 글머리표), `ssf-cart-pc.jpg` · `-m.jpg`(결제정보 상자), `ikea-cart-m.jpg`. 기록은 같은 폴더의 `notes.md`.

## 레퍼런스에 없는 것

- 결제 주문 완료 화면: 레퍼런스 폴더에 캡처가 없다(실제 주문이 필요해 찍지 못했다고 `notes.md` 5장에 적혀 있다). 요청 접수 완료(GOV.UK) 화면을 넓혀 쓴다.
- 카드 결제 처리 중 화면과 결제 실패 안내 화면: 캡처가 없다. `notes.md` 6장의 NN/g 진행 표시 글(무엇을 하는 중인지 글자로 적는다)과 요소 목록, `DESIGN.md`의 `.gate`(한 가지 결과만 알리는 화면) 부품으로 정했다.

## 구조 후보

1. **가운데 한 열(GOV.UK 순서)**: 완료 표시 → 제목 → 안내 한두 줄 → 정보 줄(번호·유형·금액·결제수단) → "다음 순서" 짧은 목록 → 주문내역 버튼. 폭 560px.
2. **PC 2열(왼쪽 완료 문구·다음 순서, 오른쪽 주문 정보 상자)**: 주문서 요약 상자(SSF샵·Mardi)의 틀. 내용이 정보 줄 4~5개라 오른쪽 상자가 짧고 왼쪽과 높이가 맞지 않는다. 폰에서는 결국 1번과 같은 한 열이 된다.
3. **페이지 머리(경로 + 왼쪽 제목) + 주문 상품 표(영수증형)**: 요소 목록의 주문 완료 절에 상품 목록이 없다. 표를 넣으면 목록에 없는 내용을 새로 만드는 것이 된다.

## 결정: 1번

- **틀**: 공용 `.gate`(가운데 정렬 표식 · 제목 · 안내) 아래에 폭 560px 본문(`.rs__body`, 왼쪽 정렬)을 둔다. 헤더·푸터는 그대로, 빠른 상담은 감춘다(`"nocs": true`, 요소 목록 L72 "주문서·바로주문·주문 완료 화면에서는 빠른 상담 없음").
  - 근거: (가) GOV.UK 완료 화면이 한 열이고 폰 한 화면에 번호와 다음 순서가 다 들어온다. (나) 주문 완료 절의 보여 주는 정보는 5줄, 할 수 있는 일은 "마이페이지(주문내역)로 이동" 하나, 카드 결제 처리 절은 "별도 내용 없이 처리 중 상태와 안내만 있다". 결과 하나만 알리는 화면이다. (다) 지침 6.6의 `.gate` 부품과 이미 만든 `unsubscribe.html`이 같은 틀이라 사이트 안에서 결과 화면이 한 모양으로 보인다.
  - `.gate__box`(440px) 대신 560px을 쓰는 이유: 요청 유형 · 입금 계좌 · 안내 메일처럼 값 아래에 보조 설명이 붙는 줄과 "다음 순서" 문장이 440px에서는 두세 줄로 접혀 세로로 길어진다. GOV.UK도 본문 폭을 가운데 영역의 약 2/3로 넓게 쓴다.
- **블록 순서**(모든 상태 공통): 둥근 표식(`.smark`) → 제목(h1, 상태별 문구) → 안내 한두 줄 → 정보 줄(`dl.dl`, 위 1px 검정 선) → 회색 상자(`.cbox--tint`) 안의 "다음 순서" 번호 목록 → 마이페이지 안내 한 줄 → 주문내역 버튼(`.bt--ink` 전체 폭).
  - 번호는 22px 원 안의 작은 숫자로 순서만 알린다(장식용 큰 번호 금지, `.stp`의 번호와 같은 크기).
  - 버튼은 하나만 둔다. 요소 목록의 할 수 있는 일이 주문내역 이동 하나뿐이다. GOV.UK 기록에서 제안된 "쇼핑 계속하기"는 넣지 않는다(목록에 없음, 헤더 로고로 홈에 갈 수 있다). 파란 버튼은 쓰지 않는다.
- **정보 줄 내용**(요소 목록에 적힌 값 + 그 값을 설명하는 서버 동작에서 나온 값만):
  - 요청 접수(시안 · 견적): 요청번호 / 요청 유형(시안 요청이면 "인쇄 상품이 있어 시안 확인을 겸합니다", L541 · L307) / 진행 상태 "접수 대기"(L909의 상태 이름) / 안내 메일 받는 곳(L542 "고객에게 주문 접수 안내 메일").
  - 결제 주문(카드 · 무통장 · 후불): 주문번호 / 결제금액 / 결제수단(후불이면 결제 희망일을 같은 줄 아래에) / 무통장이면 입금 계좌 줄(계좌번호 굵게 + 예금주, 폰에서 한 줄에 들어가게 결제수단과 나눈다) / 진행 상태(카드 "상품 준비중", 무통장 "입금 대기", 후불 "후불 요청" — L544) / 안내 메일(L545).
  - 견본 값은 지침 7.4: 시안 요청 `R-20261112-0031`, 견적 요청 `R-20261110-0027`, 주문 `O-20261115-0007`, 결제금액 6,760,600원(공급가 6,146,000원 + 부가세, `cart-checkout.md`의 주문서 결제 버튼 금액과 같게), 계좌 부산은행 101-2000-0000-00. 모두 `data-sample`.
- **다음 순서 목록**(요소 목록에 있는 안내만, 3줄):
  - 시안 요청: 담당자가 요청 내용과 인쇄 파일을 확인한 뒤 시안을 올린다(L485) → 마이페이지 주문내역의 시안확인에서 승인하거나 수정을 요청한다(L893 · L909 · L911) → 승인하면 견적을 받고 주문내역의 결제진행에서 결제한다(L913 · L378).
  - 견적 요청: 담당자가 확인한 뒤 견적서를 보낸다(L485) → 견적서는 안내 메일 링크와 주문내역에서 볼 수 있다(L759) → 결제진행에서 결제한다(L378).
  - 카드: 결제 완료 메일(L545) → 상품 준비(L544) → 제작 기간 인쇄 없는 상품 3~4일 · 인쇄 상품 4~7일, 주말 제외(L335, 지침 7.4).
  - 무통장: 계좌로 입금 → 입금이 확인되면 상태가 바뀐다(L544 입금 대기) → 세금계산서는 결제 확인 후 영업일 1~3일 안에 담당자 이메일로(L394).
  - 후불: 후불결제 요청 완료 메일(L545) → 결제 희망일에 맞춰 주문내역의 결제진행에서 결제(L378) → 후불결제는 관공서·공공기관·학교만(L393).
- **카드 결제 처리 · 처리 중**: 표식 자리에 도는 원(`.rs__spin`), 제목 "결제를 확인하고 있습니다", 안내 "이 화면을 닫지 말고 잠시 기다려 주세요." 그 아래 회색 상자에 처리 단계 3줄(카드 인증 확인 완료 · 카드 승인 진행 중 · 주문 확정 대기)을 두고, 정보 줄에 주문번호 · 결제금액 · 결제수단을 둔다. 맨 아래 한 줄로 "완료되면 주문 완료 화면으로, 열 수 없으면 마이페이지 주문내역으로 이동합니다."
  - 근거: 절 설명 "카드 결제 인증 결과를 받아 승인 후 주문을 확정한다"의 세 동작을 그대로 단계로 쓴다. NN/g 글(기록 6장): 진행 표시 옆에 지금 하는 일을 글자로 적는다. 버튼은 두지 않는다(누를 것이 없는 화면).
  - 처리 중 화면은 시안에서 자동으로 넘어가지 않는다. 검수할 때 화면이 사라지지 않게 하려는 것이다. 성공 뒤 화면은 `order-complete.html?state=card`로 따로 본다.
- **카드 결제 처리 · 실패 7종**: 같은 틀에 빨간 표식, 상태별 제목·안내, 정보 줄 마지막에 "결제 상태" 칩(승인 완료 · 결제 안 됨 · 확인 필요)을 둔다. 돈이 빠져나갔는지가 구매 담당자가 가장 먼저 묻는 것이기 때문이다. 결제 세션을 확인할 수 없는 경우는 주문을 특정할 수 없으므로 주문번호 · 결제금액 줄을 빼고 결제수단과 결제 상태만 둔다. 다음 순서 2줄 → "주문내역으로 이동" 버튼(요소 목록 L470 · L471).
- **주문 완료 · 비로그인 / 찾을 수 없음**: 정보 줄과 다음 순서 없이 표식 · 제목 · 안내 · 버튼만(로그인 / 주문내역으로 이동). 보여 줄 주문 정보가 없는 화면이다.
- **폰**: 같은 순서 한 열. 정보 줄은 이름 칸 96px(공용 `.dl`), 버튼은 화면 폭 전체. 시안 요청 기본 상태 기준으로 본문이 한 화면 반 안쪽이 되게 다음 순서를 3줄로 제한한다.

## 가져오지 않는 것

- GOV.UK의 초록 완료 상자(큰 면 색)와 서비스 의견 링크: 큰 색 면은 `DESIGN.md`(파랑은 포인트로만, 큰 면 금지)와 맞지 않고, 의견 링크는 요소 목록에 없다.
- 영수증처럼 주문 상품 표를 다시 보여 주는 구성, "쇼핑 계속하기" 버튼, 처리 중 화면의 자동 이동: 요소 목록에 없거나 검수를 방해한다.
- 처리 단계를 큰 번호로 늘어놓는 장식: 사장님이 싫다고 한 "장식용 단계 번호".
