# 상품 상세 구조 결정

대상: `product.html`(상품 상세). 기본 상품 `c463` 세이프티 방한 패딩(`?id=463`), 색상 없는 상품 `c504` 키즈 매쉬 볼캡(`?id=504`), 협력브랜드 상품 `b3026` 케이투 JK-F6101(`?id=3026&brand=k2`).
본 캡처: `research/refs/product/`의 AS Colour, Merchology, 오프린트미, 마플, Apple 한국, 무신사, Vistaprint (PC 1440 · 모바일 390). 기록은 같은 폴더의 `notes.md`.

## 캡처에서 확인한 사실

| 곳 | 본 것 | 우리 문제와의 관계 |
|---|---|---|
| AS Colour 대량 주문 표 | 색상 행 × 사이즈 열(9열) 표, 칸마다 숫자를 직접 치는 칸, 맨 아래 사이즈별 합계 줄, 표 밖 아래에 `Total Quantity: 97` + 버튼. 숫자가 든 칸은 빈 칸과 다르게 칠해진다. 모바일은 색상 하나만 보이고 사이즈 칸을 3열로 놓는다 | 색상 여러 개 × 사이즈별 수량을 한 화면에 넣고 합계를 보는 구조 |
| Merchology | 구매 칸 순서가 색상 → 장식 묶음(방식·위치·로고 파일) → 사이즈별 수량 → `Total Qty`·`Minimum` → 버튼 → 수량 구간표. 사이즈 칸은 위·아래 화살표가 붙은 숫자 칸 | 인쇄 선택 묶음과 수량을 한 칸에 위→아래로 놓는 순서 |
| 오프린트미 | 가격 옆 `수량 별 최대 31% 할인`과 눈금 막대, 구간표(수량 \| 가격 8줄), 구매 칸 아래 7칸 탭이 화면 위에 붙는다. 유의사항 탭은 주의 문장 → 세탁 → 상품정보고시 2열 표 | 할인 구간 표시, 상세 정보 구성 |
| 마플 모바일 | 화면 아래에 두 줄짜리 고정 바(윗줄 수량·금액, 아랫줄 버튼). 본문을 내리면 탭 줄(위)과 고정 바(아래)가 함께 붙는다 | 따라오는 요약 |
| Apple 한국 | 선택 4가지를 세로로 늘어놓고 "이름. 한 줄 설명" 제목, 고른 값을 제목 옆에 다시 적음, "안 함"도 카드 한 장. PC는 왼쪽 사진이 붙어 따라오고 오른쪽 선택만 내려간다. 단계 번호·완료 표시는 없다 | 단계 구조, 사진 고정 |
| 무신사 | PC 세로 작은 사진 + 큰 사진(`1 / 5`), 모바일 좌우 넘김 + `1 / 6` | 사진 여러 장 |
| Vistaprint | 인쇄 방식·위치를 "이름 + 두 줄 설명" 카드로 고르고, 고를 수 없는 카드에는 이유를 적는다 | 인쇄 선택 표시 |

## 구조 후보

1. **사진 7 : 정보 5 두 단, 정보 칸에 모든 선택**(DESIGN.md 초안). 1440에서 정보 칸이 약 510px이라 사이즈 7~9개짜리 수량 표가 들어가지 않는다. 표를 세로 목록으로 바꾸면 색상이 둘만 되어도 수량 입력이 화면 두 개를 넘는다.
2. **위 두 단(사진 + 기본 정보·색상) + 아래 전체 폭 주문 구성 + 오른쪽 붙는 요약 칸**. 표 폭은 넉넉하지만 수량을 넣을 때 사진이 화면 밖으로 지나가고, 요약이 오른쪽 칸과 따라오는 바 두 곳에 겹친다. 폰에서는 PC와 순서가 달라진다(Merchology에서 본 문제).
3. **사진 5 : 구매 6 두 단. 사진 칸은 화면에 붙어 따라오고, 구매 칸에 단계를 위→아래로, 구매 칸 끝에 요약·버튼, 그 요약이 화면을 벗어나면 화면 아래 바가 따라온다**(Apple의 사진 고정 + Merchology의 순서 + AS Colour의 표 + 마플의 바). 1440에서 구매 칸이 약 668px이라 사이즈 9열 표까지 들어간다.

## 결정: 3번

### 틀
- PC(1100 이상): `사진 5fr : 구매 6fr`, 사이 56px. 769~1099: `2fr : 3fr`, 사이 36px. 폰: 한 단(경로 → 사진 → 기본 정보 → 단계 → 요약 → 상세 정보).
  - 근거: 요소 목록의 핵심은 "색상마다 사이즈별 수량 + 색상별 소계"다. 구매 칸이 넓어야 AS Colour식 표가 들어간다. 사진은 수량을 넣는 동안에도 보이게 PC에서 `position:sticky`로 붙인다(Apple).
- 사진: 1:1 큰 사진 + 아래 작은 사진 줄. 칸은 상품마다 같은 1:1이고, 협력브랜드 사진(원본 3:2)은 스튜디오 바탕(#F2F2F2) 위에 `object-fit:contain`으로 앉힌다(검수: 3:2 칸이면 상품마다 갤러리 높이가 달라 보이고 PC 왼쪽 아래가 빈다). 폰의 작은 사진 줄은 한 줄 6칸, 넘치면 옆으로 넘긴다. 이전·다음은 끝없이 돌고(마지막 → 첫 장), 오른쪽 아래에 `1 / 6`. 큰 사진은 가로 스크롤 맞춤(scroll-snap)이라 손가락으로 넘긴다. 폰에서는 화면 끝까지 붙이고(모서리 0) 작은 사진 줄은 남긴다(원하는 장으로 이동). 사진 순서는 대표(`catalog -f`) → 뒤(`-b`) → 상세 갤러리(`products -1~4`), 같은 파일은 한 번만.

### 구매 칸 순서 (PC·폰 같은 순서)
1. 분류(작은 글자) → 상품명 h1(30/800, 빠른 보기 상품명 `.qv__name` 값. 폰 22) + 관심상품 하트 → 가격(24/800 `59,000원~`, "1벌 기준") + 수량 할인 한 줄(10벌 5% · 30벌 10% · 50벌 15%) → 소재·시즌·사이즈·색상 정보 줄 → 제작 기간 상자(인쇄 없음 3~4일 · 인쇄 있음 4~7일, 주말 제외)와 "유의사항 · 배송/포장안내" 이동 링크.
2. 진행 머리: "주문 내용 선택" + `3 / 5 단계 완료` + 굵기 4px 진행 막대. 요소 목록의 "선택 단계별 완료 표시와 진행 정도". Apple에는 없어서 우리 요구로 더했다.
3. 단계 묶음(번호 22px 원 → 끝나면 검정 체크). 제목 오른쪽에 고른 값("블랙 외 1색", "42벌", "기본 포장", "인쇄 없음")을 다시 적는다(Apple).
   - ① 옵션(값이 둘 이상인 옵션만, 알약 선택 `.seg`)
   - ② 색상: 견본 + 이름 칩(`.fchip` + `.chip__sw`)을 여러 개 누를 수 있다. 다시 누르면 수량이 0인 색은 빠지고, 수량이 있는 색은 그 색 줄로 이동해 테두리를 깜박인다.
   - ③ 사이즈별 수량: **색상마다 묶음**(모든 폭 같은 모양). 묶음 머리에 색상 견본·이름 · 색상별 소계 · 빼기(×, 44px), 몸에 사이즈 칸(사이즈 이름 위 + `− 숫자 +`, 단추 44×44, 숫자는 바로 치는 칸 — NN/g 입력 조절기 글: 큰 값은 직접 입력, 길게 누르면 연속). 사이즈 칸은 폭에 맞춰 줄을 나눈다(최소 128px, 1440 구매 칸에서 한 줄 4칸 → 7사이즈 두 줄). 숫자가 든 칸은 검정 테두리 + 굵은 숫자. 색상이 둘 이상이면 묶음 아래 회색 한 줄에 사이즈별 합계(수량 있는 사이즈만)와 합계 벌수(AS Colour 표의 합계 줄).
     - 처음 시안은 PC에서 AS Colour식 색상 행 × 사이즈 열 표였다. 7~9사이즈면 칸이 약 58px라 숫자 칸 오른쪽에 10px 안팎의 ▲▼만 들어가 1366 가로 태블릿 같은 터치 화면에서 누르기 어렵고, 1024 이하의 `− +`와 모양이 달랐다(검수). 그래서 PC도 1024 이하의 묶음을 쓴다.
     - 폰: 같은 묶음이 접힌다. 머리를 누르면 펴고 접으며, 접힌 묶음 머리에 "100 6 · 105 5"처럼 넣은 값을 적는다(NN/g 모바일 표 글: 접이식으로 묶기). 사이즈 칸은 2열. 합계 줄은 길이를 줄이려고 뺀다(요약에 총수량이 있음).
     - 색상 없는 상품: 색상 열 없이 한 줄. 사이즈가 없으면 "FREE" 칸 하나.
     - 협력브랜드에 등록 사이즈·색상이 없으면: 글 칸(500자) + "적은 수량 12벌" 실시간 합계(숫자 뒤 "벌"을 더한다). 비었거나 "벌"이 붙은 숫자가 없으면 입력칸 테두리를 오류로 바꾸고 입력칸 바로 아래에 안내를 붙인다(L240).
   - ④ 포장 방식: 카드 2장(`.opts--2`, 기본 포장 / 개별 폴리백). 첫 카드가 기본.
   - ⑤ 인쇄: 카드 2장(인쇄 없음 · 제작 3~4일 / 인쇄 있음 · 제작 4~7일). "인쇄 없음"도 카드 한 장(Apple). 인쇄 있음일 때만 아래가 펼쳐진다(Merchology의 묶음을 열고 닫는 방식으로 바꿈): 인쇄방법(알약) → 인쇄 부분 안내(그림 자료가 없어 상품 앞·뒤 사진 위에 번호 표식을 얹음, `data-slot="print-guide"`, 고르면 검정) + 인쇄 부분 칩(여러 개) → 인쇄 설명(1,000자) → 인쇄 파일(공용 첨부 `.upl` + `.files`, `2 / 10개`).
4. 요약(`.pd-sum`): 총수량 · 할인율 · 총액(할인 전 금액 취소선) 한 줄 → 구간 4칸 막대(1~9벌 / 10벌~ 5% / 30벌~ 10% / 50벌~ 15%, 칸마다 1벌 단가, 지금 구간 검정) + "8벌 더 담으면 15% 할인됩니다." → 주문하기(`.bt--ink`, 전체 폭) + 장바구니 담기(`.bt--line`) → 남은 단계 한 줄 → 대량 주문·맞춤 제작 상담(전화 · 카카오톡).
   - 버튼은 막지 않는다. 누르면 빠진 단계마다 안내가 붙고 첫 항목으로 간다(요소 목록이 미선택 안내 7종을 요구하므로 AS Colour의 "버튼을 막고 글자로 알리기" 대신 "남은 단계" 한 줄로 미리 알린다).
   - 구간표를 따로 창으로 띄우지 않는다(마플은 10구간이라 창, 우리는 3구간이라 바로 적는다).

### 따라오는 바
- 요약(`.pd-sum`)이 화면에 없으면 화면 아래에 바를 띄운다.
  - PC(72px 한 줄): 사진 48 + 상품명·진행 정도 | 총수량·총액 | 전화 상담 · 카카오톡 | 장바구니 담기 · 주문하기.
  - 폰(두 줄): 윗줄 "총 42벌 · 10% 할인 · 2,230,200원 · 5/5", 아랫줄 전화(44) · 카카오톡(44) · 장바구니 담기 · 주문하기(마플).
  - 폰에서는 이 페이지에서만 공통 상담 바(`.mbar`)를 감춘다(`body[data-nocs]`). 전화·카카오톡이 바에 들어가므로 상담 수단은 그대로 있다.
  - PC 우측 플로팅(`.side-cs`): 바가 떠 있는 동안에는 상담·카카오 원을 감추고 맨 위로 원만 바 위(bottom 100px)에 남긴다. 바에 전화·카카오톡이 있어 같은 화면에 카카오 버튼이 둘 뜨지 않게 한다(검수: 1024에서 원 세 개가 '5 / 5 단계 완료'·'남녀공용'을 덮고, 1440에서 노란 원과 바의 카카오톡 알약이 함께 보임). 요약이 화면에 들어와 바가 사라지면 원 세 개가 돌아온다(그때는 요약 안에 전화·카카오톡이 있음).
  - 원은 right 24 + 52 = 76px를 차지하므로, 좌우 여백(`--gut`)이 80px보다 좁은 폭(1440 미만)에서는 본문(`.pd`) 오른쪽을 `80px − 여백`만큼 비우고 바도 같은 오른쪽 끝에 맞춘다(1024에서 24px). 1440 이상은 여백이 80이라 그대로다.
  - 나타날 때 움직임은 짧게(.25s), 줄인 움직임 설정에서는 끈다(NN/g 고정 머리 글).

### 상세 정보
- PC(769 이상)는 탭으로 숨기지 않고 네 부분을 모두 펼친다. 위에 4칸 이동 줄(공용 `.stab` 알약 탭)을 헤더 아래 10px에 붙이고, 지금 보고 있는 부분을 검정 알약으로 표시한다(Baymard 가로 탭 글, 오프린트미의 붙는 탭 줄을 4칸으로 줄임). 붙어서 떠 있을 때만 DESIGN.md "떠 있는 알약 줄" 그림자를 준다.
- 폰(768 이하)은 같은 이동 줄을 탭으로 써서 고른 부분 하나만 보인다. 네 부분을 다 펼치면 390 화면에서 상세 정보만 약 2,200px이 되어(첫 시안 캡처 6,570px) 지침 7.2의 "모바일에서 끝없이 긴 스크롤"에 걸린다. 탭으로 바꾼 뒤 4,700px. 폰의 이동 줄은 화면 폭을 채우고 글자 13px(`.fchip--s`와 같은 값).
- 각 부분은 PC에서 왼쪽 제목 칸 220px + 오른쪽 내용, 부분 사이 1px 선. 폰은 내용만(제목은 탭과 같아 낭독용으로만 남김).
  - 상품정보: 상품 사진 2×2(상세 갤러리) + 상품 정보 표. 상품별 그림이 들어갈 자리이므로 `data-slot`. 폰에서는 사진 두 장만 보이고 "상품정보 더 보기"로 편다.
  - 배송/포장 안내: 그림 자료가 없어 아이콘 4칸(배송 방법 · 배송비 · 제작 기간 · 포장)과 표로 짠다(`data-slot`).
  - 반품/교환 안내: 2열 표(신청 · 단순 변심 · 사이즈 · 색상 · 자세한 기준 = 취소/환불 정책 링크, `data-slot`). 문장은 고객센터 주문방법의 "주문 전 확인 사항"과 취소/환불 정책 페이지의 연락 문장에서만 가져왔다.
  - 유의사항: 제작 소요 기간 표 + 주문 전 확인 사항 목록(고객센터 주문방법 요소 목록의 공통 확인 사항).
- 같은 분류 상품·후기 줄은 넣지 않는다(요소 목록에 없다).

### 파랑을 쓰는 곳
- 할인율·할인 금액 숫자에만 쓴다: 가격 아래 수량 할인 구간, 요약의 적용 할인율, 지금 구간 칸의 할인율, "8벌 더 담으면 15%" 안내, 바의 "10% 할인".
- 쓰지 않는 곳: 완료 문구("필요한 내용을 모두 골랐습니다", 검정), 필수 표시 `*`(검정), 할인 없음 "없음"(회색), 지금 구간이 아닌 칸의 할인율(회색), 되살림 안내(회색 면 `surface-tint` + 검정 체크). 검수에서 한 화면에 파란 글자가 6~8군데 흩어져 강조가 약하다는 지적을 받았다.

### 상태
`?state=`로 본다: 처음 연 화면 / 인쇄 있음 / 필수 미선택 / 고른 색상 없음 / 첨부 오류 / 장바구니 담음 확인(팝업) / 주문 진행 중 / 주문 실패 / 비로그인(로그인 안내 팝업) / 로그인 뒤 되살림(파일 일부 빠짐 → 첨부 칸으로 이동·강조) / 인쇄 불가·포장 없음 / 인쇄방법·인쇄 부분 없음 / 상세 정보 없음(사진 없음 포함) / 상품 없음. 상품은 `?id=504`(색상 없음), `?id=3026&brand=k2`(협력브랜드·글로 적기), `?id=3026&brand=k2&state=need`(협력브랜드·글로 적은 수량에 "벌"이 없어 미입력 안내), `?id=3026&brand=k2&state=sized`(협력브랜드·사이즈 등록 견본).
- 상품 없음: 안내(표식·제목·설명·버튼 셋) 아래에 `var(--sec)` 띄우고 "대신 둘러보기 좋은 **추천 단체복**" 섹션(`.vh` 제목 + 전체 보기 링크 + `.pgrid` 4열, 폰 2열)을 붙인다. 상품은 홈 '상품 랭킹'과 같은 자료(`B2BT_RANK` 전체 탭, 상품 목록 추천순 2026-11-11 진열 순서)의 앞 4개다. 판매량 순위가 아니므로 "많이 찾는"·"인기" 대신 "추천"이라고 쓴다. 검수: 1440 첫 화면에 내용이 300px뿐이라 빈약하다.
