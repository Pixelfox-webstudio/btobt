# 장바구니·결제형 구조 결정

대상: `cart.html`(장바구니), `order.html`(주문서 작성·결제), `order-now.html`(주문 정보 입력 후 접수)
본 캡처: `research/refs/cart-checkout/`의 SSF샵 · AS Colour · Mardi Mercredi · Apple 한국 · IKEA 한국 · Meridian(데모 상점) · GOV.UK 패턴 예시 (PC 1440 · 모바일 390). 기록은 같은 폴더의 `notes.md`.

## 캡처에서 확인한 사실

| 곳 | PC | 모바일 |
|---|---|---|
| SSF샵 장바구니 | 왼쪽 목록 약 65% + 오른쪽 "결제정보" 상자 약 28%. 목록 머리줄에 "전체 선택 · 선택 삭제". 상품 줄은 체크 → 사진 → 이름·옵션 → 오른쪽 위 X. 요약 상자 맨 아래 버튼 글자에 건수("1건 주문하기") | 1열. 화면 아래에 "총 구매금액 + 1건 구매하기" 띠가 붙어 있다. 옵션/수량 변경은 아래에서 올라오는 판 |
| AS Colour 장바구니 | 왼쪽 목록 + 오른쪽 요약. 상품 → 색상 → 사이즈 줄로 묶고, 사이즈 줄마다 "− 수량 +"가 있어 창을 열지 않고 고친다. 제목 옆 숫자가 총 수량("Your Cart (33)"). 배송비는 "Calculated at Checkout" 문장 | 같은 묶음을 1열로. 사이즈 줄 한 줄에 사이즈 · 단가 · − 수량 + |
| Mardi 장바구니 | 제목 아래 "1. 장바구니 > 2. 주문서작성 > 3. 주문완료". 왼쪽 목록 + 오른쪽 요약(총 상품금액 · 배송비 · 결제예정금액 · 버튼) | 1열, 맨 아래 버튼 두 개가 한 번 더 붙어 있다 |
| Mardi 주문서 | 한 화면에 배송지 → 주문상품 → 할인 → 결제정보 → 결제수단 → 현금영수증 → 약관 → "₩85,000 결제하기". 결제수단을 고르면 그 수단의 추가 입력이 바로 아래에 붙는다. 현금영수증은 "신청 / 신청안함"을 고른 뒤에야 "개인 / 사업자"와 번호 칸이 나온다 | 구역 순서가 같고 세로 길이가 화면 약 3.4개. 라벨 왼쪽 · 입력 오른쪽이라 입력칸이 좁다 |
| Apple 결제 첫 단계 | 받는 방법을 큰 선택 버튼 2개로 묻고, 배송 방법은 카드형 선택지(왼쪽 이름·설명, 오른쪽 요금). 고른 것만 테두리가 진하다 | 선택 버튼 2개가 한 줄에 그대로, 카드형 선택지는 화면 폭 |
| IKEA 장바구니 | 요약에 "배송비는 결제 시 계산됩니다." — 모르는 금액을 0원이 아니라 문장으로 적는다 | 결제 화면 맨 위에 요약을 한 줄로 접는다 |
| GOV.UK 확인·오류 화면 | 고칠 수 없는 값은 입력칸이 아니라 "항목 이름 · 값" 목록으로 보여 준다. 오류는 화면 위 요약 상자(문장마다 해당 칸으로 가는 링크)와 칸 바로 옆 두 곳에 같은 문장 | 목록 한 줄이 이름 → 값 두 줄로 쌓인다 |

채우지 못한 화면: 인쇄 방법·부위·첨부파일을 보여 주는 장바구니, 세금계산서·후불·포인트가 있는 한글 주문서, 잔금 결제 주문서. 이 셋은 요소 목록과 `DESIGN.md` 부품으로 정했다.

## 장바구니(`cart.html`) 구조 후보

1. **표(체크 · 상품 · 수량 · 금액 열) + 아래 합계 띠**: 국내 쇼핑몰에서 흔하지만 한 상품에 사이즈가 4개면 수량 칸이 한 열에 들어가지 않는다. 폰에서는 표를 다시 풀어야 한다.
2. **한 열 목록 + 목록 아래 요약**(Apple): 사진이 크고 여유롭지만 상품 3건에 화면 두 개 반을 쓴다. 요약과 주문 버튼이 스크롤 끝에 있다.
3. **왼쪽 상품 목록(상품마다 사이즈별 수량 칸) + 오른쪽에 따라오는 주문 요약, 폰은 한 열 + 화면 아래 주문 띠**(SSF샵의 틀 + AS Colour의 사이즈 줄).

## 결정: 3번

- **틀**: PC는 왼쪽 목록(나머지 폭) + 오른쪽 주문 요약 380px. 요약은 헤더 아래에 붙어 따라온다(`position:sticky`, `top: var(--bh-top) + 24px`). 1024px 이하는 한 열(목록 → 요약). 폰은 화면 아래에 "선택 3개 · 총 112벌 + 요청 버튼" 띠를 고정한다.
  - 근거: SSF샵 · Mardi · AS Colour · IKEA · Meridian 다섯 곳이 모두 PC 2열이다. 폰 아래 띠는 SSF샵 · Mardi가 쓴다. 요소 목록이 "상품이 있을 때는 사이트 공통 상담 연결 요소를 감춤"이라고 적었으므로 폰 하단 상담 바 자리가 비고, 그 자리에 주문 띠를 둔다.
- **상품 한 건**: 체크 → 사진(104px, 폰 72px) → 분류 · 상품명 · 색상/인쇄/포장 한 줄 → 사이즈별 수량 칸 → "총 수량 70벌 · 59,000원 × 70벌 · 4,130,000원" 한 줄. 삭제(휴지통)는 오른쪽 위.
  - 사이즈별 수량은 **사이즈 이름과 − 수량 + 를 한 칸으로 묶어 격자로 나열**한다(PC 한 줄에 3~4칸, 폰 2칸). AS Colour처럼 사이즈마다 한 줄을 쓰면 사이즈 4개에 4줄이라 폰이 길어진다. 창을 열지 않고 줄에서 바로 고치는 방식은 AS Colour에서 가져왔다.
  - 수량이 모두 0이 되면 "삭제할까요?"를 한 번 묻고 지운다(요소 목록: 합이 0이면 그 상품 삭제. 길게 누르다 실수로 지워지는 일을 막는다). 취소하면 직전 수량으로 되돌린다.
  - 인쇄 여부는 칩(`.stag`)으로 둔다. 인쇄 상품이 하나라도 있으면 요청 종류가 달라지므로 목록에서 바로 구분되어야 한다.
- **목록 머리줄**: 왼쪽 "전체 선택 (3/3)", 오른쪽 "선택 삭제"(SSF샵 · Mardi). 일부만 고르면 전체 선택 체크가 가로줄(일부 선택)로 바뀐다. "선택 삭제"는 선택을 한 번 바꾸기 전에는 흐리게 두고, 눌러도 지우지 않고 이유를 알린다.
- **주문 요약**: 선택한 상품마다 "상품명 · 벌수 · 금액" 한 줄 → 선택한 상품 수 · 총 수량 → 정해지지 않은 금액 안내 문장 → 버튼.
  - 합계 금액은 적지 않는다. 요소 목록의 주문 요약에 총 금액이 없고, 견적문의 상품이 섞이면 합계가 확정 금액처럼 읽힌다. IKEA처럼 "인쇄비·배송비와 견적문의 상품의 금액은 견적서에서 안내합니다."를 문장으로 적는다.
  - 버튼 글자에 선택 건수와 요청 종류를 넣는다("3개 상품 견적·시안 요청" / 인쇄 상품이 없으면 "2개 상품 견적 요청"). SSF샵의 "1건 주문하기"와 같은 방식이다. 이 화면의 파란 버튼은 이것 하나다(`DESIGN.md`: 장바구니 견적 버튼은 강조색). 폰에서는 요약 안의 버튼을 감추고 아래 띠의 버튼만 남긴다.
- **단계 표시**: 페이지 머리 오른쪽에 "1 장바구니 → 2 견적·시안 요청 → 3 견적 확인·결제"(`.stp`). Mardi에서 가져왔다. 이 장바구니가 결제로 끝나지 않는다는 것을 첫 화면에서 알린다. 폰(768 이하)에서는 감춘다. 공용 `.stp`가 폰에서 현재 단계 이름만 남겨 나머지가 뜻 없는 번호 원이 되기 때문이다(검수 지적, 7.2 "장식용 단계 번호"). 폰에서는 요약의 "결제는 견적을 확인한 뒤 주문서에서 진행합니다" 문장이 같은 정보를 준다.
- **상품 정보 자세히 보기**: 상품명(또는 "자세히 보기")을 누르면 오른쪽에서 나오는 옆 패널(`.side`, 폰은 화면 가득). 사진·상품명 → 상품 옵션 · 색상 · 사이즈 · 사이즈별 수량 · 포장 · 인쇄 여부 → 인쇄 방법 · 부위 · 설명 → 첨부파일(파일명 · 용량 · 내려받기) → 닫기.
  - 목록 안에서 펼치는 방식은 쓰지 않는다. 항목이 10줄이 넘어 목록과 요약이 밀리고 폰이 길어진다. 옆 패널은 장바구니를 떠나지 않는다(SSF샵의 옵션 변경 창과 같은 이유).
- **빈 장바구니**: 목록 · 머리줄 · 요약 · 아래 띠 없이 안내 한 덩어리와 "쇼핑 계속하기". 이때는 빠른 상담을 다시 보여 준다.
- **안내**: 삭제할 상품을 고르지 않았을 때는 아래 알림, 처리 실패(수량 변경·삭제)는 목록 위 한 줄. 주문할 상품 미선택과 주문 요청 저장 실패는 아래 "결과 문장 규칙"을 따른다.
- **결과 문장 규칙(세 페이지 공통)**: 요청·결제 버튼을 누른 결과 문장(미선택, 저장 실패, 서버가 거절한 경우)은 한 화면에 한 곳만 둔다. 769px 이상은 요약 상자 안 버튼 바로 위(`.co-sum__msg`), 폰은 본문 맨 위(`.co-srv`). 폰은 버튼이 화면 아래 띠에 있고 요약 상자가 페이지 맨 끝이라 그 안의 문장은 보이지 않는다. 아래 띠 위에 붙이면 2~3줄 문장이 화면을 계속 가리므로 맨 위로 정했다. 누르는 순간에는 아래 알림이 함께 뜬다. (처음에는 GOV.UK처럼 위와 버튼 위 두 곳에 같은 문장을 두었으나 한 화면에 같은 문장이 두 번 보인다는 검수 지적으로 바꿨다. 입력 칸 오류는 GOV.UK 방식 그대로 위 요약 상자 + 칸 바로 아래.)

## 주문서(`order.html`) 구조 후보

1. **단계를 나눈 주문서**(Apple · IKEA: 받는 방법 → 상세 → 결제): 한 화면이 짧지만 결제수단을 바꾸면 증빙·포인트 조건이 함께 바뀌는 우리 주문서에서는 앞뒤를 오가야 한다.
2. **PC도 한 열**(Mardi): 구역이 9개라 총 결제금액과 결제 버튼이 맨 아래에만 있다.
3. **한 화면, PC는 왼쪽 입력 + 오른쪽에 따라오는 결제 요약, 폰은 한 열 + 화면 아래 결제 띠**.

## 결정: 3번

- **왼쪽 순서**: 주문 상품(수정 불가) → 견적정보(요청번호 · 최종 견적금액 · 견적서 보기 · 등록된 견적서 파일) → 주문정보 → 배송정보 → 포인트 → 결제수단(+ 결제 희망일 · 증빙서류) → 주문시 유의사항.
  **오른쪽 요약**: 총 상품금액 · 배송비(견적서에 포함) · 포인트 사용 · 총 결제금액 → 취소/환불 정책 동의 → "6,760,600원 결제하기"(공급가 6,146,000원 + 부가세).
  - 근거: 기록의 Baymard 결제 글(요약을 결제 단계 내내 보이게 한다)과 요소 목록의 "총 결제금액 요약". 포인트를 넣거나 결제수단을 바꾸면 오른쪽 숫자와 버튼 글자가 바로 바뀐다. 버튼 글자에 금액을 넣는 것은 Mardi("₩85,000 결제하기")에서 가져왔다.
  - 동의와 버튼을 한 상자에 둔다. 동의를 빠뜨리면 버튼 바로 위에서 안내가 뜬다.
- **선택지는 모두 펼쳐 둔다**(드롭다운 없음): 배송지 지정 방식 3종과 증빙서류 3종은 알약 3칸(`.seg--fill`), 배송방법 4종과 결제수단 3종은 카드형 선택지(`.opts` — 이름 + 조건 한 줄). 고른 선택지의 추가 입력은 바로 아래에 나온다.
  - 결제수단: 카드 → 안내 한 줄 / 무통장입금 → 증빙서류 / 후불결제 요청 → 결제 희망일(필수) + 증빙서류, 포인트는 0으로 잠김.
  - 증빙서류: 세금계산서 → 사업자등록번호 · 계산서 이메일 / 현금영수증 → 발행 용도(개인 · 사업자) → 휴대폰 번호 또는 사업자등록번호 / 미발행 → 추가 입력 없음. Mardi의 현금영수증 구역과 같은 방식(고른 값에 따라 칸이 나타남)이다.
  - 근거: Apple의 선택 버튼 · 카드형 선택지, Mardi의 결제수단 아래 추가 입력.
- **새로운 배송지 → 저장된 배송지 고르기**: 가운데 팝업(`.pop`)에 배송지 카드 목록(배송지명 · 받는 분 · 기본배송지 칩 · 주소 · 휴대전화 · "선택"), 아래에 "배송지 관리"와 "닫기". 고르면 배송정보 칸에 채우고 닫는다.
- **잔금 결제(수정 불가)**: 주문정보 · 배송정보를 입력칸이 아니라 "항목 이름 · 값" 목록(`dl.dl`) 두 개로 바꾸고, 위에 "원 주문 정보이며 수정할 수 없습니다" 한 줄을 둔다. 후불결제 요청 선택지는 빠지고, 증빙서류는 원 주문 값을 글자로만 보여 주며, 정책 동의는 체크된 채 잠긴다.
  - 근거: GOV.UK 확인 화면. 비활성 입력칸을 흐리게 늘어놓으면 고칠 수 있는 칸과 섞여 보인다.
- **오류**: 결제하기를 누르면 틀린 칸마다 바로 아래에 문장이 붙고(공용 양식 검사), 왼쪽 맨 위에 "입력을 확인해 주세요 (n개)" 상자가 생겨 문장을 누르면 그 칸으로 간다. 고치면 칸의 표시와 상자의 줄이 바로 사라진다. 근거: GOV.UK 오류 요약, 기록의 NN/g 글(위쪽 요약만으로 알리지 않는다).
- **서버가 거절한 경우**(견적 금액 변경 · 결제할 수 없는 견적 · 이미 저장된 주문 · 결제·배송방법 확인 · 결제창 불러오기 실패 · 결제 진행 실패 · 저장 실패): 장바구니에 적은 결과 문장 규칙대로 한 곳(769 이상 결제 버튼 위, 폰 맨 위)에 `.msg--err`. 견적 금액 변경에는 "새로고침" 버튼을 붙인다.
  - 결제할 수 없는 견적 · 이미 저장된 주문은 다시 눌러도 결제가 되지 않으므로 결제 버튼(요약 상자와 폰 아래 띠 둘 다)을 없애고 다음에 할 일을 선 버튼으로 둔다: "담당자에게 문의"(1:1 문의) / "주문내역 보기". 결제 동의 칸도 감춘다. 숨긴 결제 버튼은 `disabled`라 입력칸에서 Enter로 보내지지도 않는다.
- **터치 대상**: 폰에서 누르는 것은 모두 44px 이상. 글자 버튼(상품명, "자세히 보기", "쇼핑 계속하기", "견적서 보기", 동의 "보기", 문장 안 링크)은 줄 높이는 그대로 두고 `min-height:44px` + 같은 크기의 음수 margin으로 누르는 영역만 넓힌다. 체크·라디오는 입력을 줄 전체에 덮어 줄(44px) 어디를 눌러도 바뀐다. 보조 버튼은 `.sb--m`(44). 수량 조절만 홈 토큰 40px 그대로다.
- **날짜 칸**: 비어 있으면 브라우저 기본 표시(영문 mm/dd/yyyy 등) 대신 "날짜를 고르세요"를 덧씌우고, 칸 어디를 눌러도 달력이 열린다(`showPicker`).
- **비정상 접근 · 비로그인**: 양식 없이 결과 한 가지만 알리는 화면(`.gate`)과 돌아갈 버튼.
- **폰 길이 줄이기**: 주문 상품은 접어서 "방한 후드 패딩 외 2건 · 112벌" 한 줄로 두고 누르면 펼친다. 주문시 유의사항은 펼침 목록(`.qlist`)으로 접는다. 결제 띠("총 결제금액 6,760,600원 + 결제하기")는 화면 아래에 고정한다. 라벨은 입력칸 위에 둔다(Mardi 폰 화면은 라벨이 왼쪽이라 주소 칸이 화면 폭의 2/3로 좁았다).
- 주문서에는 빠른 상담(하단 상담 바 · 우측 플로팅)을 두지 않는다. 폰 아래 자리는 결제 띠가 쓴다.

## 주문 정보 입력 후 접수(`order-now.html`)

주문서와 같은 틀을 쓴다. 다른 점만 적는다.
- 왼쪽: 주문 상품(상품마다 "자세히 보기"와 삭제) → 견적정보(고객 견적서 파일 첨부 1개) → 주문정보 → 배송정보(배송지 지정 방식 · 희망배송일 · 배송방법 · 배송메세지) → 납품사례 활용 동의(안내 3항목 + 동의 / 동의하지 않음).
- 오른쪽 요약: 상품금액 "견적문의" · 배송비 "견적서에 포함" · 총 결제금액 "상담 후 결정"(금액 대신 문장) → "견적·시안 요청 접수" 버튼. 결제가 아니므로 금액을 큰 숫자로 두지 않는다.
- 접수가 끝나면 가운데 확인 팝업(요청번호 + "마이페이지에서 주문내역과 시안을 확인할 수 있습니다")을 띄우고 확인을 누르면 마이페이지 주문내역으로 간다.
- 상품 정보 자세히 보기는 장바구니와 같은 옆 패널을 쓴다.

## 가져오지 않는 것

- SSF샵의 배송 유형 탭 · "바로구매" · "품절상품 삭제", Mardi의 상품별 "주문하기" · 간편결제 묶음: 요소 목록에 없다.
- AS Colour의 "장바구니 전체 비우기": 선택 삭제가 있고, 실수로 전부 지우는 버튼은 두지 않는다.
- 옵션/수량 변경 창(SSF샵): 요소 목록의 수정은 사이즈별 수량뿐이라 줄에서 바로 고친다. 색상·인쇄·포장 변경은 요소 목록에 없다.
- Apple · IKEA의 여러 단계 결제, 결제 화면에서 위 메뉴를 빼는 구성: 빌드가 헤더·푸터를 그대로 붙이고, 주문서는 한 화면으로 정했다.
- 합계 금액을 제목으로 올리는 방식(Apple): 견적 전 금액을 확정 금액처럼 보이게 한다.
