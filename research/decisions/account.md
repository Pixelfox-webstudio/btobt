대상: `mypage.html` 한 파일(13부분, `?section=orders|inquiries|safety|wishlist|points|addresses|profile|password|withdraw`). 같은 유형의 `draft-preview.html`, `inquiry-draft.html`은 이 문서의 범위가 아니다(마이페이지에서는 새 창으로 여는 링크만 둔다).

## 구조 후보

1. **무신사형 한 단(요약 → 메뉴 목록 → 각 부분은 따로 들어감)**: 모바일에서는 익숙하지만 PC 1440에서 960px 한 단은 양옆이 빈다. 기본 주소가 `?section=orders`라 메뉴 목록만 있는 첫 화면이 주소 체계에 없다. 모바일 첫 화면이 메뉴 7줄 + 요약으로 길어진다.
2. **PC 옆 메뉴 + 본문 2단, 모바일은 옆 메뉴를 서랍(펼침 판) 뒤로 숨김**: 화면은 짧지만 Flowbite 모바일처럼 다른 부분으로 가는 길이 첫눈에 안 보이고, 새 소식 수도 숨는다.
3. **PC 옆 메뉴(회원 요약 + 메뉴 묶음 + 새 소식 수) + 본문 2단, 모바일은 요약을 두 줄로 줄이고 메뉴를 본문 위 한 줄 가로 밀기 탭으로**: 레드프린팅의 PC 옆 메뉴 → 모바일 가로 탭 전환, YoPrint의 "탭에도 건수" 방식.

## 결정: 3번

- **PC 틀**: `.wrap` 안에 옆 메뉴 264px + 사이 56px + 본문(1440에서 960px). 1024 이하에서는 옆 메뉴 216px · 사이 32px. 옆 메뉴는 화면을 내려도 따라오게 sticky.
  - 근거: (가) 레드프린팅·Flowbite·YoPrint 세 곳이 PC에서 옆 메뉴 2단이다. (나) 요소 목록 "회원 요약"이 메뉴 묶음·새 소식 수·회원 요약을 한 덩어리로 요구한다(L1205~L1211). (다) 본문을 `.wrap` 안에 두는 `DESIGN.md` 규칙.
- **옆 메뉴 순서**: 회원 요약(이름 첫 글자 원 · 회원 구분 칩 · 이름 · 기업명 → 보유 포인트 · 누적 주문금액 두 줄 → "회원정보 수정") → 묶음 제목 "쇼핑 정보"(주문 내역, 견적문의 내역, 안전용품 제작 문의, 관심상품) → 선 → "계정 관리"(포인트 내역, 배송지 관리, 회원정보 수정) → 맨 아래 작은 "회원 탈퇴".
  - 무신사의 "묶음을 선으로 나눔"에 제목을 붙인다(요소 목록 L1210이 묶음 이름을 정해 준다). 현재 위치는 레드프린팅처럼 굵기 + 왼쪽 2px 검정 선. 새 소식 수(`.nb`)는 YoPrint처럼 처리할 일이 있는 줄에만 붙이고 0이면 지운다. 99를 넘으면 "99+".
  - 비밀번호 변경·회원 탈퇴는 메뉴 줄로 따로 두지 않고 회원정보 수정의 하위 화면으로 둔다(요소 목록 메뉴 묶음에 없다). 그 두 화면에서도 옆 메뉴는 "회원정보 수정"이 선택 상태다.
- **모바일 틀**: 옆 메뉴를 그리지 않는다. 회원 요약을 (이름 줄) + (포인트 · 누적 주문금액 두 칸) 두 줄로 줄여 맨 위에 두고, 그 아래 메뉴 7개를 페이지 안 메뉴(`.stab`, 46px 알약이 든 선 1px 알약 줄. 폰 44px) 한 줄로 가로로 민다. 지금 부분이 가운데 오도록 줄을 밀어 둔다. 탭에도 새 소식 수를 붙인다. 각 부분 제목(h1)은 탭 아래.
  - 근거: (가) 레드프린팅 모바일은 분류를 한 줄 가로 탭으로 바꿨고, YoPrint 휴대폰 화면은 메뉴를 탭으로 꺼내며 건수를 유지했다. Flowbite 모바일처럼 메뉴가 사라지면 다른 부분으로 갈 길이 없다(기록 2-4). (나) 무신사형 메뉴 목록을 매 부분 위에 두면 요약 + 메뉴 7줄만으로 약 500px이 된다. 사장님이 싫다고 한 "모바일에서 끝없이 긴 스크롤"을 피한다.
- **주문 내역(기본 부분) 순서**: 제목 + "새 견적 문의" → 진행 단계 띠 → 견적 문의 요약 → 도구 막대(빠른 기간 · 시작일~종료일 · 조회 · 상태 고르기) → 적용 조건 한 줄 → 주문 카드 목록(쪽 번호 없음) → 안내 상자.
  - 진행 단계 띠: 회색 상자 안 6칸(결제전 · 결제완료 · 상품준비중 · 배송중 · 배송완료 · 구매확정), 칸마다 이름 아래 건수, 1건 이상이면 검정 굵게 · 0이면 회색. 칸을 누르면 조회 버튼 없이 그 단계만 보이고 다시 누르면 풀린다. 상자 아랫줄에 취소 · 교환 · 반품 건수. 근거: shadcn의 "이름 + 건수" 띠, KRDS의 즉각 표시, 요소 목록 L1228·L1229·L1246. 모바일에서는 3칸 × 2줄(가로 밀기 대신. 건수가 모두 한눈에 보여야 한다).
  - 견적 문의 요약: 종류 3줄(견적 문의 / 안전용품 제작 문의 / 맞춤작업복 견적문의), 줄마다 건수와 상태별 건수(접수완료·검토중·견적완료·답변완료), 확인할 견적이 있으면 `확인할 견적 N` 칩. 줄을 누르면 해당 부분으로 간다(L1230·L1251).
  - 도구 막대: 빠른 기간 3개(1주일 · 1개월 · 3개월, 누르면 바로 조회)와 날짜 두 칸 + "조회"(날짜를 직접 고쳤을 때만)를 한 줄에, 오른쪽에 상태 고르기(전체~반품 10개, 선택 칸). 근거: KRDS 범위 필터와 즉각/일괄 구분, Flowbite의 기간 선택. 모바일은 빠른 기간 줄 / 날짜 줄 / 상태 줄로 나눈다.
  - 적용 조건 한 줄: "결제전 · 2026-10-17 ~ 2026-11-17 · 5건"(KRDS의 적용 조건 + 건수).
  - 주문 카드: 1px 선 상자(16px). 머리 줄(회색 바탕)에 접수일 · 주문번호(누르면 주문 상세) · 새 소식 점 · 상태 칩 · 보조 상태 칩, 오른쪽 끝에 "주문 상세"(모든 상태에서 같은 자리). 몸통은 대표 상품 사진 72px · 상품명 "외 N건" · 색상과 사이즈별 수량 · 상태를 풀어 쓴 한 줄 | 견적금액 또는 결제금액 | 버튼 칸. 근거: Flowbite 카드 4줄과 "Order details" 고정 자리, Shopify "결제가 필요하면 결제 버튼 하나만 강조".
  - 버튼 규칙: 한 주문에 검정 버튼 하나(입금 대기 → 입금 안내 보기, 시안·견적 완료 → 시안 확인, 견적 완료 → 결제진행, 시안 완료 → 시안 확인, 배송중 → 배송조회, 배송 완료·후불 미결제 → 결제진행, 배송 완료 → 구매확정, 구매확정·후기 없음 → 리뷰 쓰기). 보조 버튼은 선 버튼(견적서 확인 · 견적서 보기 · 내가 쓴 리뷰 보기). 해당하지 않는 버튼은 그리지 않는다. PC 1100 이상은 버튼을 카드 오른쪽 칸에 세로로, 769~1100은 카드 아래 한 줄에 오른쪽 정렬로 나란히(Flowbite 모바일의 세로 3단 쌓기를 피한다).
  - 폰 주문 카드(줄여 보이기): 머리 줄 = 주문번호(누르면 주문 상세) · 새 소식 점 · 상태 칩 · 오른쪽 끝 44px 화살표(주문 상세). 몸통 = 사진 56px + 상품명·색상·사이즈별 수량 → 그 아래 한 줄에 왼쪽 "접수일 / 금액" 두 줄, 오른쪽 버튼 하나. 버튼이 둘인 주문(시안 확인 + 견적서 확인, 결제진행 + 견적서 보기)은 금액 줄 아래 버튼 줄에 반씩. 상태를 풀어 쓴 문장은 폰 카드에서 빼고 주문 상세의 "현재 상태" 아래에 둔다(운송장 대기·결제 불가 안내 줄은 카드에 남긴다). 카드 한 장이 약 185px(버튼 둘 약 245px)이라 기본 1개월 12건을 접지 않고 다 보여 주고, 조건별 버튼 9가지가 모두 목록에 한 번씩 나온다. 12건을 넘으면(3개월 등) 열 건 뒤를 "나머지 주문 N건 더 보기"로 접는다(쪽 나눔이 아니라 같은 목록을 펼치는 것).
  - 근거: (가) shadcn 모바일은 한 건을 "번호·상태 / 날짜·금액" 두 줄로 줄였고, Flowbite 모바일은 버튼을 세로로 쌓아 한 건이 화면 절반을 넘었다. (나) 요소 목록 L1231 "전체를 한 번에, 나누어 보기 없음"과 조건별 처리 L1255~L1263. (다) 사장님이 싫다고 한 "모바일에서 끝없이 긴 스크롤" — 카드 높이를 줄여 대응한다.
  - 값이 없는 금액은 "-"와 "견적금액을 정하는 중"(KRDS 빈 값 규칙).
- **팝업과 옆 패널**: 주문 상세는 큰 팝업(`.pop__box--l`, 폰 화면 가득) — 상품별 사진·옵션·인쇄 정보가 표처럼 넓다. 입금 안내는 작은 팝업(금액·계좌 복사가 핵심). 후기 쓰기·내가 쓴 후기는 중간 팝업. 배송지 추가·수정은 중간 팝업(Flowbite 수정 창: 항목 7개, 이름표 위, PC 2칸, 저장 → 취소). 회원정보 수정은 항목이 많아 팝업이 아니라 부분 화면.
- **견적문의 내역 · 안전용품 문의**: 한 건 = 상태 칩 · 문의번호 · 새 소식 점 · 접수일 → 제품명(맞춤작업복은 칩) · 옵션 → 요청수량 · 연결 주문 상태 → 오른쪽 버튼(견적서 보기 · 시안 확인 · 이 견적서대로 주문하기) → 맨 아래 "담당자 답변 보기" 줄. 누르면 레드프린팅처럼 바로 아래에 펼친다(문의 원문 → 답변 일시 · 내용 · 첨부 파일 내려받기). 안전용품은 제품 내용이 길어 두 줄에서 자르고 펼친 영역에 원문 전체를 둔다.
- **관심상품**: 홈 카드 `.pc`를 그대로(`SUBDATA.card(p,{liked:true})`), 본문 폭에서 PC 3열(카드 폭 약 305px, 홈 4열 카드와 같은 크기) · 769~1024 2열(본문 폭이 약 660px라 3열이면 카드가 홈 폰 카드보다 작아진다) · 폰 2열. 하트를 끄면 그 카드가 바로 빠지고 수가 줄며, 0개가 되면 "전체 삭제"가 사라지고 빈 상태가 나온다.
- **포인트 내역**: 숫자 3칸(보유 · 선택 기간 적립 · 선택 기간 사용) → 주문과 같은 도구 막대 → 표(날짜 · 내용 · 적립·사용 · 잔여). 모바일에서는 표 한 줄을 두 줄(내용 + 금액 / 날짜 + 잔여)로 접는다(Flowbite 표형 모바일에서 열이 잘린 것을 피함).
- **배송지 관리**: PC 2열 카드(기본 배송지 칩 · 배송지명 · 받는 분 · 주소 · 휴대전화 + 수정 · 기본 배송지로 · 삭제), 폰 1열. Flowbite "Preferred address" 카드 + Edit 버튼 구조. 모든 카드는 같은 1px 선(line) · 16px 모서리이고 기본 배송지는 선 색만 검정으로 바꾼다. 같은 줄 카드는 높이를 맞추고 버튼 줄(44px)은 카드 맨 아래에 붙인다. 폰에서는 버튼 2~3개를 한 줄에 같은 너비로 둔다.
- **회원정보 수정 · 비밀번호 변경 · 회원 탈퇴**: 회원정보 수정과 비밀번호 변경은 페이지 안 메뉴(`.stab` 알약) 두 개로 오간다. 양식은 `fieldset.fset` 묶음(기업 정보 / 담당자 정보 / 주소), PC 2칸 · 폰 1열. 탈퇴는 경고 상자 → 지금 계정에 남아 있는 것(진행 중 주문·답변 대기 문의·포인트·배송지 수) → 비밀번호(간편 가입이면 확인 문구) → 취소 / 탈퇴하기 → 확인 창(버튼 이름은 결과로: "탈퇴하기" / "계속 이용하기", NN/g 근거는 기록 5장).
- **비로그인**: 2단 틀 대신 가운데 결과 화면(`.gate`) 하나 — 로그인 · 회원가입.

## 가져오지 않는 것
- 무신사·Flowbite의 홍보 띠, 요금제·설문 카드, 쿠폰 칸: 요소 목록에 없다.
- Flowbite의 "Actions" 펼침 버튼 뒤에 행동을 숨기는 방식: 상태별 버튼을 바로 보여야 한다.
- YoPrint의 "확인할 일" 목록, 최근 활동: 요소 목록에 없다(같은 역할은 새 소식 수와 진행 단계 띠가 한다).
- 옆 메뉴의 고객센터 전화·운영 시간 줄(레드프린팅): 요소 목록의 회원 요약에 없다. 빠른 상담(하단 바·우측 플로팅)이 이미 있다.
- 레퍼런스의 색·글꼴·모서리·그림자·문구·사진.
