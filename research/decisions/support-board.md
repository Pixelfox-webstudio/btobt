# 고객센터 구조 결정

대상: `customer-center.html` 한 파일(메뉴·상담 연결, 자주 묻는 질문, 주문방법, 1:1 문의 내역, 비회원 1:1 문의 확인, 1:1 문의 작성, 공지사항 목록, 공지사항 상세)
본 캡처: `research/refs/support-board/`의 오프린트미 고객센터·공지, 컬리 공지·공지 상세·FAQ, 쏘카 이용 안내 (PC 1440 · 모바일 390). 기록은 같은 폴더의 `notes.md`.

## 캡처에서 확인한 사실

| 곳 | PC | 모바일 |
|---|---|---|
| 오프린트미 고객센터 | 가운데 제목 → 회색 띠 한 줄(전화 아이콘·번호·운영시간) → 탭 2개(반씩 나눔, 선택은 검정 글자 + 검정 밑줄) → 분류 칩 11개 한 줄 → 전체 폭 검색창 → 질문 행. 행을 누르면 행 바탕이 회색이 되고 바로 아래에 답이 열린다. 탭마다 주소가 다르다 | 전화 띠가 두 줄(번호 / 운영시간). 칩 줄은 가로로 밀고 끝 칩이 잘려 보인다. 긴 질문은 두 줄 |
| 오프린트미 공지 | 행 10개(말머리 + 제목, 오른쪽 날짜 + 화살표). 행을 누르면 그 자리에서 본문이 열린다. 쪽 번호 1~5 | 제목 한 줄 말줄임, 날짜는 오른쪽에 남음 |
| 컬리 공지 | 왼쪽 메뉴 4개(메뉴마다 주소) + 오른쪽 표(번호·제목·작성자·작성일, 15행). 맨 위 3행은 번호 칸에 "공지"가 적힌 고정 공지 | 한 행이 두 줄: 첫 줄 "공지"/번호와 날짜, 둘째 줄 굵은 제목. 끝없이 이어짐(문서 13,607px) |
| 컬리 공지 상세 | 굵은 선 아래 제목·작성자·작성일 세 줄 → 본문 → 선 → 오른쪽 아래 "목록" 버튼. 상세는 주소가 따로 있다 | 제목 → 작성자·날짜 한 줄 → 본문 |
| 컬리 FAQ | 제목 줄 오른쪽 분류 선택 상자, 표 15행. 행 아래로 A 칸이 열린다 | Q 표식 + 질문, 펼치면 회색 칸에 A 표식 + 답 |
| 쏘카 이용 안내 | 왼쪽에 방법 카드 2장 → 번호 단계 6개(행동 이름 제목 + 회색 설명 한두 줄), 오른쪽에 세로로 긴 사진 한 장이 단계 목록 높이를 채운다. 문서 높이 2,060px | 사진이 빠지고 같은 순서로 쌓인다. 문서 높이 3,206px |

## 구조 후보

1. **왼쪽 세로 메뉴 + 오른쪽 내용** (컬리): 메뉴가 늘 보이지만 내용 칸이 1280에서 약 1000px로 줄고, 모바일에서는 메뉴를 다른 모양으로 바꿔야 한다. 주문방법의 화면 예시가 작아진다.
2. **부분마다 따로 된 페이지** (예전 방식): 주소 공유는 되지만 요소 목록 L1575("부분을 바꿔도 페이지를 다시 불러오지 않고")를 지키지 못한다.
3. **제목 → 상담 연결 띠 → 페이지 안 메뉴 4개 → 탭 내용** (오프린트미의 순서 + 탭마다 주소): 상담 연결 정보가 어느 부분에서나 같은 자리에 있고, 메뉴 줄은 공용 부품 `.stab`을 그대로 쓴다. 모바일에서도 같은 부품이 390 폭 안에 네 칸 모두 들어간다.

## 결정: 3번

### 머리와 상담 연결 (L1564~L1582)
- 순서: 경로(홈 / 고객센터 / 지금 부분 이름) → `h1` 고객센터 → 한 줄 설명 → 상담 연결 띠 → 탭 줄. 근거: 오프린트미가 제목과 탭 사이에 전화 띠를 두고, NN/g 펼침 글이 "꼭 봐야 하는 정보(전화·운영시간)는 접지 않는다"고 한다.
- 상담 연결 띠는 회색 바탕(`--tint`, 모서리 16) 한 칸을 넷으로 나눈다: 대표전화(번호 22/800 + 운영시간 두 줄, 누르면 전화) · 카카오톡 상담(새 창) · 1:1 문의 · 견적문의. 칸 사이는 1px 선. 홈 푸터가 고객센터 번호를 22/800으로 쓰는 값을 그대로 가져온다. 폰에서는 전화 칸이 한 줄을 다 쓰고 나머지 셋은 아이콘 + 이름만 있는 3칸 버튼으로 줄인다.
- 메뉴는 `.stab` 4개: 자주 묻는 질문 · 주문방법 · 1:1 문의 · 공지사항. 순서는 요소 목록 그대로. 각 칸은 `?tab=faq|order-guide|qna|notice` 주소를 가진 링크이고 `data-views="tab"`으로 다시 불러오지 않고 바꾼다. `.stab`은 2026-11-17에 공용 쪽에서 DESIGN.md `tab-pill`(46px 알약, 선택은 검정 바탕 흰 글자 700, 선 1px 알약 줄 안)로 바뀌었다. 선택 표시가 바탕색과 굵기 두 가지라 NN/g "선택 표시 두 가지 이상"도 그대로 맞는다. 홈의 떠 있는 `.bh`(그림자, 화면 위에 붙음)는 쓰지 않는다: 이 줄은 상담 연결 띠 바로 아래의 평면 메뉴이고 지침 공용 부품 표가 고객센터 네 부분을 `.stab`으로 정했다.
- 탭을 바꿀 때 공용 `sub.js`는 화면을 맨 위로 올린다. 고객센터는 메뉴 줄이 머리·상담 띠 아래(PC 약 400px)에 있어, 아래로 내려 읽던 사람이 탭을 바꾸면 메뉴 줄 바로 위까지만 올린다(`js/sub-center.js`).
- 탭 안에서 다시 나뉘는 화면도 주소로 둔다: 문의 작성 `?tab=qna&view=write`, 공지 상세 `?tab=notice&id=3`, 주문방법 종류 `?tab=order-guide&type=noprint`, 공지 검색어·쪽 `&q=…&page=2`. 탭을 바꾸면 다른 탭의 값(view·id·type·q·page)은 주소에서 지운다.

### 자주 묻는 질문 (L1588~L1599)
- 순서: 제목 줄(왼쪽 "자주 묻는 질문 + 개수", 오른쪽 검색 칸 320px) → 분류 칩 한 줄(`.fchip`, "전체"가 첫 칸, 칩마다 질문 수) → 펼침 목록(`.qlist`) → 맨 아래 "찾는 답이 없으면 1:1 문의" 한 줄. 근거: 오프린트미의 칩 → 검색 → 행 순서. 검색은 제목 줄 오른쪽으로 올려 한 줄을 줄인다.
- 검색은 입력하는 즉시 질문과 답 전체에서 대소문자 없이 거른다(L1594). 분류와 함께 걸린다(L1595). 개수 자리에 "검색 결과 N개"로 바뀐다.
- 행에는 질문 앞에 작은 분류 이름을 둔다(컬리 표의 카테고리 칸을 한 줄로 줄인 것). "전체"에서 어느 분류 질문인지 보인다. 폰에서는 분류 이름을 질문 위 작은 줄로 옮긴다.
- 여러 개를 동시에 열 수 있다(`details`, NN/g "다른 항목을 자동으로 닫지 않는다", L1591).
- 질문이 하나도 없으면 검색·칩·목록을 모두 빼고 빈 상태만 둔다(L1598). 검색 결과가 없으면 목록 자리에 빈 상태 + "검색어 지우기" · "1:1 문의하기"(L1599).
- 쓰지 않는 것: 오프린트미의 "해결 되었나요?" 평가 상자(요소 목록에 없다), 컬리의 분류 선택 상자(눌러 봐야 분류가 보인다).

### 주문방법 (L1605~L1643)
- 순서: 제목 → 안내 종류 고르기(큰 카드 2장 `.opt--l`: 인쇄 있는 주문 / 인쇄 없는 주문, 기본은 인쇄 있는 주문, L1643) → 고른 종류의 도입 한 줄 → 5단계 → 주문 전 확인 사항 · 결제 안내(두 종류 공통, 나란히 두 칸). 근거: 쏘카의 "방법 카드 → 번호 단계" 뼈대. 두 종류를 모두 펼치면 길이가 두 배가 되므로 고른 쪽만 보여 주고, 고른 값은 `?type=noprint`로 주소에 남긴다.
- 5단계는 PC에서 왼쪽 단계 목록(380px: 번호 22px 원 + 행동 이름 제목 + 한 줄 요약) + 오른쪽 한 칸(고른 단계의 설명 · 화면 예시 · 세부 순서). 쏘카가 왼쪽 단계 목록과 오른쪽 그림 한 칸으로 높이를 맞춘 구조를 화면 예시에 쓴다. 단계를 고르면 오른쪽 칸이 바뀐다. 이 조작은 쏘카에 없는 것이고 화면 예시 22장을 세로로 쌓지 않으려고 더한다.
- 한 단계에 화면 예시가 여러 장이면(3·4·5단계) 오른쪽 칸 안에서 옆으로 넘긴다: 그림 아래에 이전·다음 원 버튼(40px)과 "2 / 5", 그 아래에 세부 순서 목록(① ② …)을 두고 누르면 그 그림으로 간다. 세부 순서 글은 모두 펼쳐 둔다(그림을 넘기지 않아도 순서를 읽을 수 있다). 자동으로 넘기지 않는다.
- 폰에서는 단계를 세로로 쌓은 펼침으로 바꾸고 한 번에 한 단계만 연다(처음에는 1단계). 열린 단계 안에서 그림은 손가락으로 민다. 화면 예시를 빼지 않는다(쏘카는 꾸밈 사진이라 뺐지만 우리는 안내 내용이다).
- 단계 번호는 순서만 알린다(22px 원, 회색 선 / 고른 단계 검정). 큰 장식 번호는 쓰지 않는다.
- 화면 예시는 `img/guide/*.webp`(1200×750, 16:10, 모서리 16, 1px 선)이고 `data-slot="guide-…"`를 붙인다. 지금은 임시 그림이라 나중에 실제 시안 화면으로 바꾼다.
- 주문 전 확인 사항 6개는 굵은 핵심어 + 짧은 설명 목록, 결제 안내는 `dl`(결제수단 · 후불결제 요청 · 세금계산서 · 선발행·날짜 지정 · 발행 누락) 표 줄. 사실은 요소 목록 L1628~L1640과 주문서 절 L393~L394 그대로.

### 1:1 문의 (L1649~L1739)
- 회원: 제목 줄(왼쪽 "1:1 문의 + 건수", 오른쪽 검정 "문의 작성") → 기간 줄(1주일·1개월·3개월 칩 + 날짜 두 칸 + 조회) → 목록. 처음 열면 답변이 달린 가장 최근 문의 하나를 펼쳐 둔다(답변·첨부 내려받기가 어디에 붙는지 바로 보이게). 목록은 컬리 FAQ의 "행 → 아래 칸" 펼침을 쓴다. PC 닫힌 행은 문의번호 · 제목 · 접수일 · 상태 칩 네 칸(머리 줄 있음), 폰은 두 줄(상태 칩·접수일·번호 / 제목). 펼치면 흰 바탕에 내 문의 내용, 그 아래 회색 칸에 "답변" 표식 + 답변일 + 답변 + 첨부 내려받기. 답변 전이면 회색 칸에 확인 중 안내(L1673). 다시 누르면 접힌다(L1655).
- 비회원(같은 탭): 왼쪽 "비회원 문의 확인" 상자(이름 · 비밀번호 · 문의 확인), 오른쪽 "회원 문의는 로그인 후 확인"(로그인 버튼) + "새 문의 남기기". 조회하면 아래에 결과: PC 두 칸(왼쪽 목록: 제목 · 작성일시 · 상태, 오른쪽 고른 문의의 상세: 제목 · 문의번호 · 상태 · 작성일 · 답변일 · 내용 · 답변), 폰은 목록 → 상세 순서. 오프린트미가 1:1 문의 탭을 숨기지 않고 한 장짜리 안내 상자로 다음 행동을 준 구조를 비회원 조회에 쓴다.
- 문의 작성은 같은 탭 안 `view=write`. 폭 760px 한 열(로그인·가입 양식과 같은 폭 규칙), `.fset` 두 묶음(문의자 정보 / 문의 내용). 회원은 이름·휴대전화·이메일이 회원 정보로 채워진 읽기 전용 칸, 비회원은 입력 칸 + 문의 비밀번호 + 자동등록방지 + 개인정보 동의. 버튼은 취소(회색) + 문의 등록(검정). 등록하면 1:1 문의 목록으로 돌아가 접수 완료 안내를 띄운다(L1738).
- 오류는 항목 아래 빨간 안내(`.fld.is-err`) + 양식 위 한 줄 요약(`.msg--err`). 서버가 돌려주는 오류(제목·내용 확인, 문의자 정보 확인, 숫자 불일치, 회원 정보 확인 불가, 잘못된 요청, 등록 실패)는 요약 줄 문구로 보여 준다.

### 공지사항 (L1745~L1775)
- 목록: 제목 줄(왼쪽 "공지사항 + 건수", 오른쪽 검색 칸 + 검색 버튼) → 표(`.tbl`: 구분 · 제목 · 등록일) → 쪽 번호. 중요 공지는 구분 칸에 검정 "중요" 칩, 일반은 "일반" 글자. 중요 공지를 먼저, 그다음 최신순, 한 쪽 15건(L1746). 근거: 컬리의 번호 칸 "공지" 고정 방식. 작성자 칸은 뺀다(글쓴이가 늘 회사).
- 쪽 번호는 2쪽 이상일 때만, 모든 쪽 번호를 보이고 검색어를 유지한다(L1757). 컬리의 이전·다음 두 버튼만 있는 방식은 쓰지 않는다.
- 폰에서는 한 행을 두 줄로 바꾼다(첫 줄 구분 · 날짜, 둘째 줄 제목). 컬리 모바일 그대로. 끝없이 이어 보기는 쓰지 않고 쪽 번호를 남긴다.
- 상세: 같은 탭 안 `id=`. 구분 칩 → 제목(24/700) → 등록일 → 1px 선 → 본문(글만, 15/1.75, 폭 760) → 1px 선 → 가운데 "목록" 버튼. 탭 줄은 그대로 남긴다(상세로 바로 들어온 사람이 다른 부분으로 옮겨 갈 수 있게). 없는 번호면 목록을 대신 보이고 한 줄 안내를 둔다(L1775).
- 오프린트미의 공지 행 펼침은 쓰지 않는다: 요소 목록이 공지 상세를 따로 요구하고 주소로 넘길 수 있어야 한다.

## 가져오지 않는 것
- 오프린트미·컬리 맨 위 홍보 띠, 오프린트미의 "페이지당 10개" 선택: 요소 목록에 없다.
- 쏘카의 꾸밈 사진 한 장, 방법 카드 안 기능 나열: 우리 두 종류의 차이는 "시안 확인 단계가 있다/없다" 한 줄이다.
- 컬리 공지 상세의 작성자 줄, 모바일 FAQ를 전체 화면으로 따로 여는 방식(탭 줄이 사라진다).
