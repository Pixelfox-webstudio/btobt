# 로그인·회원가입형 구조 결정

대상: `login.html`(로그인), `signup.html`(회원 유형 선택), `signup-general.html` · `signup-business.html`(가입 방법 선택), `signup-general-info.html` · `signup-business-info.html`(정보 입력, 대표 페이지는 기업 회원 정보 입력)
본 캡처: `research/refs/auth/`의 Printful 로그인·가입, 교보문고 가입·법인 인증, 컬리 가입(빈 양식·입력 중), 삼성전자 비즈니스 파트너 신청, 나비엠알오 유형 선택, 마플·29CM 로그인, 아이마켓 가입, 네이버 클라우드 1단계, Apple 계정 생성, Ant Design Upload (PC 1440 · 모바일 390). 기록은 같은 폴더의 `notes.md`.

## 캡처에서 확인한 사실

| 곳 | PC | 모바일 |

## 구조 후보

### 로그인 · 유형 선택 · 가입 방법 선택
1. **가운데 한 열만** (교보문고·마플·29CM): 단순하지만 요소 목록이 세 화면 모두에 요구하는 "대표 사진 + 회사 소개 문구"를 둘 자리가 없다. 사진을 양식 위에 두면 폰에서 입력칸이 첫 화면 밖으로 밀린다.
2. **사진을 화면 가득 깔고 양식을 위에 띄우기**: 사진이 크게 보이지만 그림자 있는 떠 있는 상자가 생기고(`DESIGN.md`는 그림자를 떠 있는 것에만 쓴다), 사진 위 글과 양식 글이 겹쳐 읽기 어렵다.
3. **좌우 2열: 왼쪽 양식, 오른쪽 사진 칸** (Printful): 세 화면이 같은 틀이고 오른쪽 사진·문구만 바뀐다. 폰에서는 양식 → 사진 순서로 쌓는다.

### 정보 입력(일반·기업)
1. **컬리식 한 열 + 왼쪽 라벨**: 기업 회원은 입력 19개라 PC에서도 화면 4장 분량이 된다.
2. **단계를 나눠 여러 화면으로**(교보문고 법인 인증을 먼저): 요소 목록의 단계는 "3단계 중 현재 단계(정보 입력)" 하나로 정해져 있어 화면을 더 나누면 단계 표시와 어긋난다.
3. **한 화면 양식(짧은 짝은 2칸) + 오른쪽에 붙어 따라오는 "가입 전 확인" 요약과 가입 완료 버튼**: 요소 목록의 "가입 완료(필수값·중복확인·사업자번호 확인·파일 첨부·자동등록방지가 모두 되어야 가능)"를 항목별 체크로 그대로 보여 준다.

## 결정: 2열 틀(3번) + 한 화면 양식과 확인 요약(3번)

### 공통 틀(로그인 · 유형 선택 · 가입 방법 선택)
- PC(769px 이상)는 `.wrap` 안을 같은 폭 2칸(사이 80px)으로 나눈다. 왼쪽 칸 가운데에 폭 440px 양식, 오른쪽 칸에 사진(모서리 16, 높이 = 양식 칸 높이, 최소 640px).
  - 근거: Printful 로그인·가입이 같은 틀에서 오른쪽만 바꾼다(가). 요소 목록이 세 화면 모두에 대표 사진·회사 소개 문구를 요구한다(나). 사진·카드 모서리 16, 버튼 알약(다).
- 사진 위 왼쪽 아래에 소개 문구를 둔다. 제목은 홈 배너처럼 "앞말(가늘게) + 이름(굵게)": 로그인·유형 선택·기업 가입 방법은 "많은 기업이 선택한 **산업현장 공급 파트너**" + "단체복부터 산업용품까지", 일반 가입 방법은 "단체복 **납품 전문**" + "유니폼부터 맞춤 제작 상품까지"(요소 목록 문구 그대로). 글 쪽에 아래쪽 어둠 그라데이션, 오른쪽 위에 "연출 이미지입니다."(`data-temp="ai"`).
- 폰(768px 이하)은 양식 → 사진 순서. 사진은 화면 끝까지 붙이고(모서리 0) 4:3으로 낮춘다. 근거: Printful 모바일도 양식이 먼저다(가). 폰에서 입력칸이 첫 화면 안에 있어야 한다.
- 사이트 머리말·바닥글은 빌드가 붙이는 그대로 둔다(29CM도 머리말 안에 로그인이 있다). 따로 지우지 않는다.

### 로그인
- 순서: 제목 "로그인" + 설명 → (상태 안내 한 줄) → 아이디 또는 이메일 → 비밀번호(칸 안 보기 전환) → [로그인 상태 유지 30일 | 아이디·비밀번호 찾기] 한 줄 → "로그인" 검정 전폭 버튼 → "간편 로그인" 작은 제목 + 같은 폭 3칸 한 줄(Google · 카카오 · 네이버) → 간편 가입 회원 안내 두 줄 → 회원가입 줄.
  - 근거: 마플의 아이디 → 버튼 → 찾기 → 간편 로그인 → 가입 순서(가). 사업자 회원은 아이디로 들어오므로 아이디가 첫 줄. 간편 로그인은 3개뿐이라 아이콘만 두지 않고 이름을 적는다(교보문고 2단 버튼이 글자를 적은 것과 같은 이유).
- 간편 로그인 버튼은 흰 바탕 선 알약 + 로고 표식(Google·네이버는 잉크 한 색, 카카오만 토큰 `#FEE500` 원 안에 `#191919` 표식). 브랜드 색 hex를 새로 만들지 않는다.
- 상태 안내(불일치·시도 초과·간편 로그인 실패 4가지·이용 불가 계정·통신 오류)는 양식 바로 위 `.msg--err` 한 줄. 미입력은 칸마다 칸 아래 한 줄. 처리 중은 버튼 안 회전 표시 + "로그인하는 중".
- 아이디·비밀번호 찾기는 기능이 있는지 정해지지 않아(요소 목록 "존재 여부 불확실") 팝업 안내(고객센터 번호·상담 시간)로 둔다.
- 이미 로그인한 회원은 양식 대신 결과 한 덩어리(`.gate`: 표식 → "이미 로그인되어 있습니다" → 이동할 곳 → 버튼). `unsubscribe.html`과 같은 뼈대.
- 보던 페이지(`?return=`)가 있으면 양식 위에 "로그인하면 장바구니로 돌아갑니다."를 보이고, 회원가입·간편 로그인 링크에도 같은 값을 붙여 넘긴다.

### 회원 유형 선택
- 같은 높이 카드 2장(PC 좌우, 폰 세로, 기업 회원이 먼저·기본 선택). 카드 = 유형 이름 + 누구인지 한 줄("기업·관공서·단체 고객용" / "개인 고객용") + 가입할 때 필요한 것 3줄. 카드 전체가 라디오.
  - 근거: 나비엠알오 모바일의 "유형 이름 + 누구인지" 카드와 PC의 같은 줄 수 비교(가). 3줄 내용은 요소 목록의 입력 항목에서만 가져온다(기업: 사업자등록번호 확인 · 사업자등록증 첨부 · 관리자 승인 없이 바로 이용 / 일반: 이름·생년월일·성별 · 휴대전화·이메일·주소 · 단체명은 선택). 혜택 문구는 만들지 않는다.
- 카드 아래: "가입하기"(검정 전폭, 고른 유형의 가입 방법 선택으로) → "고른 유형으로 바로 가입" 작은 제목 + 간편 가입 3칸 → "이메일로 계속하기"(선 전폭, 정보 입력으로) → "이미 회원이신가요? 로그인".

### 가입 방법 선택(일반·기업)
- 맨 위 단계 표시(1 회원 유형 → 2 가입 방법, 끝난 단계는 링크) → 유형 칩 + 제목 "간편 회원가입" → 간편 가입 3줄(전폭, 로고 + "Google로 가입") → "또는" 구분선 → "쇼핑몰 회원가입"(검정 전폭, 직접 입력) → 회원 유형 변경 링크.
  - 근거: 교보문고가 수단을 크기로 단을 나눈다(가). 제목이 "간편 회원가입"이라 간편 수단을 먼저 쌓고, 직접 입력은 구분선 아래 주 버튼 하나로 둔다. 단계 표시는 네이버 클라우드처럼 숫자 + 이름(나비엠알오의 막대만으로는 몇 단계인지 알 수 없다).

### 정보 입력(일반·기업)
- 머리: 단계 표시(1 회원 유형 ✓ → 2 가입 방법 ✓ → 3 정보 입력) → 제목 → 설명 한 줄. 왼쪽 정렬(양식 첫 칸과 같은 세로선).
- PC: 양식 칸(남는 폭) + 오른쪽 340px "가입 전 확인" 칸(헤더 아래에 붙어 따라온다). 확인 칸 = 항목별 체크(필수 입력 n/N · 아이디 중복확인 · 사업자등록번호 확인 · 사업자등록증 첨부 · 주소 검색 · 자동등록방지) + "가입 완료" 검정 전폭 버튼 + 바로 이용 안내. 폰에서는 이 칸이 양식 맨 아래로 내려온다(붙어 따라오지 않음).
  - 근거: 요소 목록의 가입 완료 조건 다섯 가지(나)를 버튼 바로 위에 두면, 무엇이 남았는지 오류가 나기 전에 보인다. 삼성처럼 버튼이 양식 끝에만 있으면 긴 양식을 다 내려가야 버튼이 보인다(가).
- 묶음은 소제목 + 검정 가로선(삼성). 기업: 회사정보 → 개인정보 → 광고성 정보 수신 동의 → 자동등록방지. 일반: 개인정보 → 주소정보 → 광고성 정보 수신 동의 → 자동등록방지.
  - 기업에서 회사정보를 먼저 두는 근거: 교보문고·삼성 모두 사업자번호를 먼저 확인한다(가). 유효하지 않거나 이미 가입된 사업자를 계정 정보를 다 쓰기 전에 알린다.
- 짝이 되는 짧은 칸만 한 줄 2칸(회사명 | 대표자명, 업태 | 업종, 비밀번호 | 비밀번호 확인, 휴대전화 | 전화번호, 이름 | 이메일). 폰은 모두 1열. 근거: 19칸을 한 열로 두면 PC가 화면 4장이 된다. 짝 칸은 NN/g가 예외로 둔 "짧고 서로 관련된 칸".
- 버튼이 딸린 칸(사업자등록번호 + 확인, 아이디 + 중복확인, 우편번호 + 주소 검색)은 PC·폰 모두 한 줄. 결과는 칸 바로 아래 한 줄이고, 값을 고치면 결과를 지운다(삼성·아이마켓 + 요소 목록 "바꾸면 초기화").
- 규칙이 있는 칸은 규칙을 처음부터 칸 아래에 둔다. 비밀번호 규칙은 4개 칩(영문 · 숫자 · 특수문자 · 8~72자)이고 충족하면 체크로 바뀐다(Apple). 비밀번호 확인은 같은 자리에 "일치합니다 / 다릅니다". 안내 줄 높이를 미리 잡아 아래 칸이 밀리지 않게 한다(컬리에서 본 밀림을 피한다).
- 사업자등록증: 첨부 칸 → 첨부하면 칸 아래 한 행(그림이면 64px 미리보기, PDF면 PDF 표식 + 파일 이름 + 크기 + 크게 보기 + 삭제). 새 파일을 고르면 기존 파일을 바꾼다(Ant Design의 1개 제한 동작). 형식·용량이 맞지 않으면 기존 파일을 그대로 두고 칸 아래에 이유를 적는다.
- 주소 검색은 외부 우편번호 서비스라 시안에서는 버튼을 누르면 견본 주소(48058 부산광역시 해운대구 센텀중앙로 97)가 들어가고 상세주소 칸으로 간다.
- 자동등록방지는 묶음 맨 끝(가입 버튼 바로 앞 묶음). 숫자 그림 + 입력칸 + 새로 받기(Apple). 숫자가 틀리거나(`bad`) 그림의 유효 시간이 지나면(`capexp`) 그림을 자동으로 바꾸고 라벨 옆에 "새 그림" 칩 + 그림 테두리를 보인다. 안내 끝에 "여러 번 틀리면 잠시 입력할 수 없습니다"를 붙이고, 여러 번 틀리면(`caplock`) 입력칸과 새로 받기를 잠근다. 횟수·시간은 정해지지 않아 숫자로 적지 않는다.
- 확인 완료 표시(중복확인·사업자번호·첨부·생년월일 문구, 비밀번호 규칙 칩, 필수 *)는 파랑을 쓰지 않는다. 문구는 검정 + 앞에 체크, 규칙 칩 통과는 선택 상태와 같은 검정 바탕 흰 글자, 간편 가입 "카카오 계정" 칩은 회색 태그칩(`DESIGN.md`: 파랑은 랭킹·왕관·견적 버튼·숫자 강조·포커스에만).
- 약관 동의 묶음은 두지 않는다. 요소 목록의 묶음 이름이 개인정보 / 회사정보(주소정보) / 광고성 정보 수신 동의 / 자동등록방지 넷뿐이다(질문 기록에 적음).
- 간편 가입 중: 맨 위 안내 줄("카카오 계정으로 가입하는 중입니다") + 이름·이메일 미리 채움 + 비밀번호 두 칸 대신 "비밀번호 없이 가입합니다" 한 줄.
- 가입 완료: 양식 대신 결과 한 덩어리(`.gate`: 표식 → 감사 문구 → 가입 정보 요약 표 → 다음 행동). 직접 입력은 자동 로그인이 안 된다는 줄과 [로그인] [메인화면으로], 간편 가입은 로그인된 상태로 [보던 페이지로 / 메인화면으로]. 버튼은 가입 정보 상자와 같은 폭(440)으로 세로로 쌓고, 주 동작은 같은 흐름의 다른 화면처럼 화살표 칸이 있는 `.bt--ink`(위), 메인화면으로는 같은 높이의 `.bt--line`(아래).
- 단계 표시의 끝난 단계는 번호 원과 이름을 함께 링크로 감싸고 터치 영역을 44px로 잡는다. 폰은 끝난 단계 이름을 낭독용으로만 남겨(보이지 않게) 링크가 0 크기가 되지 않게 한다. 번호는 본문 글꼴 700(Barlow는 순위·배너 번호 전용).

## 가져오지 않는 것
- Printful·29CM의 판촉 문구, 교보문고의 혜택 말풍선: 확인되지 않은 혜택 문구다.
- 컬리의 성별·생년월일을 뺀 구성, 추천인: 우리 요소 목록에는 일반 회원 생년월일·성별이 필수로 있고 추천인은 없다.
- 삼성의 관심 업종·직원수 설문, 약관 전문 상자: 요소 목록에 없다.
- Apple의 "소리로 듣기": 요소 목록에 없다.
- 나비엠알오의 그림·말투형 머리띠, 진행 막대만 있는 단계 표시.
