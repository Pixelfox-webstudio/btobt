# 시안 확인 화면 구조 결정

대상: `draft-preview.html`(시안확인(주문)), `inquiry-draft.html`(견적문의 시안 보기)
본 캡처: `research/refs/account/`의 YoPrint 도움말 고객 화면(`yoprint-approval-customer-pc.jpg`, `yoprint-approval-phone-m.jpg`), YoPrint 소개 그림(`yoprint-artwork-proof-pc.jpg`, `yoprint-quote-approval-pc.jpg`), Sticker Mule 도움말(`stickermule-proof-help-pc.jpg`). 기록은 같은 폴더의 `notes.md` 2-5절과 3절.

## 캡처에서 확인한 사실

| 곳 | 본 것 |
|---|---|
| YoPrint 시안 확인 창(PC, 도움말 실제 화면) | 머리에 작업 이름 · 주문번호 · 작업번호 · 요청일. 그 아래 3단: 왼쪽 "Reviewed 0 / 2"와 시안 목록(썸네일 + 파일 이름), 가운데 시안 이름 → 가게 메모 한 줄 → 큰 시안 이미지(회색 바탕 위 가운데), 오른쪽 질문 "Do you approve this artwork?"와 선택 카드 2개(Approve artwork / Request changes). 아래 오른쪽 끝에 "Next artwork" 버튼 하나 |
| YoPrint 수정 요청 | "Request changes"를 고르면 카드 바로 아래 "Describe the changes" 입력 칸이 생긴다. 비우고 넘어가면 칸 테두리가 빨갛게 바뀌고 칸 바로 아래에 "Describe the requested changes before continuing."이 붙는다. 다른 곳에 알림을 띄우지 않는다 |
| YoPrint 휴대폰 | 창이 화면 전체. 위에서부터 닫기 → "Back to artwork list" → 시안 이름 → 메모 → 이미지 → 질문 → 선택 카드 2개 세로 → 화면 아래에 가로를 다 쓰는 "Next artwork". 시안 한 장이 한 화면 |
| YoPrint 견적 승인 | 시안 승인과 같은 질문 + 선택 2개 구조. 승인 쪽에는 약관 한 덩어리("승인하면 수량·작업 방식·납기가 확정된다")가 붙는다 |
| YoPrint 주문 상세 | 오른쪽 좁은 열에 금액(수량, 소계, 세금, 합계)을 따로 두고, 왼쪽 넓은 열에 작업·시안을 둔다 |
| Sticker Mule 시안 | 시안을 번호(1~7)가 붙은 격자로 늘어놓고 그 아래에 버튼 하나. 글에 "모든 시안이 승인되기 전에는 제작하지 않는다"는 한 줄 |

## 요소 목록이 요구하는 것(L893~L942)
- 시안확인(주문): 견적 요약(금액 부가세 포함, 품목명·옵션·수량)은 시안과 견적을 함께 받은 건만 / 시안 이미지는 품목이 2개 이상이면 품목명별로 묶고 품목에 연결되지 않은 시안도 함께 / 수정 요청 입력(1000자)과 보내기는 함께 받은 건만 / 승인은 시안 완료 상태일 때만, 함께 받은 건은 승인 뒤 바로 결제할지 묻고 주문 결제로 / 견적서 보기 / 닫기 / 안내 9가지.
- 승인과 수정 요청은 **주문 한 건 전체**에 대한 동작이다. YoPrint처럼 시안마다 따로 결정하는 기능은 목록에 없다.
- 견적문의 시안 보기: 제목(견적문의 시안 / 맞춤작업복 시안), 문의번호 · 상품명, 시안 이미지 목록, 크게 보기(원본 열기), 닫기. 승인·수정 요청은 없다.

## 구조 후보

1. **YoPrint 3단 그대로(목록 | 큰 이미지 한 장 | 결정)**: 한 번에 시안 한 장만 크게 보고 다음으로 넘긴다. 시안마다 결정을 받는 흐름에 맞춘 구조라 우리 요소(주문 전체를 한 번 승인)와 맞지 않고, "품목명별로 묶어서"를 왼쪽 좁은 목록에서만 보여 주게 된다. 폰에서는 시안 사이를 오가는 별도 목록 화면이 하나 더 생긴다.
2. **한 단 세로 쌓기(요약 → 시안 → 결정)**: 폰과 같지만 PC 1440에서 시안 격자 아래로 결정 칸이 한참 밀린다. 견적 금액을 보면서 시안을 고르기 어렵다.
3. **2단: 왼쪽 넓은 칸에 품목별로 묶은 시안 격자, 오른쪽 좁은 칸에 견적 요약 → 시안 검토(승인 · 수정 요청)** (Sticker Mule의 번호 붙은 격자 + YoPrint 주문 상세의 오른쪽 금액 열 + YoPrint 시안 창의 오른쪽 결정 칸). 폰은 요약 → 시안 → 검토 순 한 단.

## 결정: 3번

- **창의 틀**: 따로 열리는 창 공용 머리줄(`.win__bar`)에 로고 · 문서 이름(h1 "시안 확인") · 오른쪽 `닫기` + `견적서 보기`(함께 받은 건만). 폰은 같은 두 버튼을 화면 아래 `.win__foot`에 붙인다. 바탕은 회색(#F5F5F6), 내용 덩어리는 흰 카드(모서리 16, 그림자 없음)로 나눈다. 상품 사진 바탕(#F2F2F2)이 회색 바탕에 묻히지 않게 시안 격자도 흰 카드 안에 둔다.
- **머리 한 줄**: 본문 맨 위에 상태 칩(시안 완료) · 요청번호 · 요청일 · 품목 수를 한 줄로 둔다. YoPrint 창 머리의 "작업 이름 · 주문번호 · 요청일" 한 줄과 같은 역할이다.
- **시안 격자(왼쪽, 폭 1fr)**: 카드 제목 "시안 이미지 N장"과 "이미지를 누르면 크게 볼 수 있습니다." 그 아래 품목마다 묶음 하나: 묶음 머리에 품목명(17/700) + 옵션 · 수량 한 줄 + 오른쪽 "시안 N장". 묶음 안은 PC 2열 · 폰 2열 정사각 칸(사진 바탕 #F2F2F2, 이미지는 잘리지 않게 `contain`). 칸 왼쪽 위에 전체 일련번호(1, 2, 3…, Sticker Mule처럼), 아래에 "시안 1"과 파일 이름. 품목에 연결되지 않은 시안은 마지막 묶음 "공통 시안"으로 둔다. 품목이 하나면 묶음 머리를 그리지 않는다.
  - 2열 근거: PC 왼쪽 칸이 약 860px라 2열이면 한 칸 400px 안팎으로 시안의 글자·자수 위치가 읽힌다. 3열(270px)은 YoPrint 가운데 칸 이미지(약 350px)보다 작다.
  - 번호 근거: 수정 요청이 주문 전체에 대한 글 한 칸이라, 어느 시안을 고칠지 글로 가리킬 수단이 필요하다. 입력 칸 예시 문구를 "시안 2: …"로 쓴다.
- **크게 보기**: 칸을 누르면 큰 팝업(`.pop__box--xl`, 폰은 화면 가득)에 한 장씩 띄운다. 머리에 "시안 2 · 방한 후드 패딩"과 "2 / 5", 가운데 큰 이미지와 좌우 화살표(키보드 ←→도), 아래에 파일 이름과 `원본 보기`(새 창으로 원본 파일). YoPrint 휴대폰의 "시안 한 장이 한 화면"을 이 팝업으로 푼다. 견적문의 시안 보기의 "원본 이미지 열기"도 같은 팝업의 `원본 보기`다.
- **오른쪽 칸(폭 380px)**: 위에 견적 요약 카드, 아래에 시안 검토 카드. 붙어 따라오지 않게 둔다(두 카드를 합치면 PC 900px 화면보다 높아 아래 버튼이 가려진다).
  - 견적 요약: "견적 금액" 이름표 → 금액(가격 글자 규칙 24/800) → "부가세 포함 · 공급가 N원" → 품목 목록(품목명 굵게, 옵션 한 줄, 오른쪽 끝 수량) → 오른쪽 위 `견적서 보기` 글자 링크. YoPrint 주문 상세의 오른쪽 금액 열 위치를 따른다.
  - 시안 검토: 제목 → 설명 "시안과 견적을 확인한 뒤 승인하거나 수정을 요청해 주세요. 시안을 승인한 뒤에 결제할 수 있습니다."(Sticker Mule의 제작 조건 문장 자리. 우리 주문방법 안내의 "시안 승인 뒤 결제"와 같은 사실) → 강조 버튼 하나 `시안·견적 승인`(파랑, 화면에 하나) → 가는 선과 "수정할 곳이 있으면" → 수정 요청 입력 칸(1000자, 글자 수) → 선 버튼 `수정 요청 보내기` → 보낸 뒤 바뀌는 점 한 줄.
  - YoPrint의 "선택 카드 2개 → 다음" 대신 버튼 둘을 바로 둔다: 결정이 주문 전체 한 번뿐이라 고르는 단계와 누르는 단계를 나눌 까닭이 없고, 정적 시안에서 입력 칸이 처음부터 보여야 사장님이 확인할 수 있다. 입력 칸 오류 표시 방식(칸 테두리 + 칸 바로 아래 문장)은 YoPrint를 그대로 따른다.
  - 승인과 수정 요청은 모두 확인 창을 거친다(요소 목록 "확인 후"). 확인 창 버튼은 결과로 적는다(`승인하기`, `수정 요청 보내기`).
- **시안만 받은 건**: 견적 요약 카드와 `견적서 보기`, 수정 요청 칸이 없다. 검토 카드에는 `시안 승인` 버튼과 "승인하면 담당자가 이 시안으로 견적을 준비합니다."만 둔다. 이 경우 수정 요청 수단이 화면에 없으므로 고객센터 전화번호 한 줄을 둔다(질문 기록 참고).
- **결과 화면**: 수정 요청을 보내면 주문이 접수 대기로 돌아가 시안이 보이지 않는 상태가 되므로(L919), 보낸 뒤 화면은 시안 없이 결과 하나만 알리는 카드(`.gate` 구성: 표식 → 제목 → 설명 → 요청번호·상태·보낸 내용 → 버튼)로 둔다. 승인 완료 두 가지, 등록된 시안 없음, 찾을 수 없음, 잘못된 요청, 비로그인도 같은 카드다. 시안·견적 승인 완료는 카드 위에 "바로 결제할까요?" 확인 창을 띄우고 `결제하기`가 `order.html`로 간다.
- **견적 변경 · 승인 불가**: 시안은 그대로 보이고 검토 카드만 바뀐다. 견적 변경은 카드 맨 위에 빨간 한 줄 안내와 `새로 고침` 버튼, 승인 버튼은 누를 수 없게. 승인 불가는 버튼 자리를 상태 칩 + 안내 문장으로 바꾼다. 사라지는 알림 대신 화면에 남는 안내로 둔다(notes 5장 Shopify 안내).
- **폰(≤768)**: 한 단. 머리 한 줄 → 견적 요약 → 시안 격자(2열) → 시안 검토. `닫기` · `견적서 보기`는 화면 아래 고정 줄. 시안 격자를 2열로 두어 5장이 세 줄 안에 들어오게 한다.
- **견적문의 시안 보기**: 같은 2단을 쓰되 오른쪽 칸은 문의 정보 카드 하나(문의 종류 · 문의번호 · 상품명 · 시안 수)와 "이 화면에서는 시안을 보기만 할 수 있습니다" 안내. 승인 버튼 자리를 비우지 않고 안내 문장으로 채운다. 맞춤작업복 시안은 제목과 번호 체계(C-)만 다르다.

## 가져오지 않는 것
- YoPrint의 시안마다 승인/수정 결정, "Reviewed N / M" 숫자, 이름을 쳐서 서명하는 칸, 3D 미리보기, 맞춤/100% 확대 단계: 요소 목록에 없다.
- Sticker Mule의 활동 기록(시안 차수 이력): 요소 목록에 "시안 이력에 기록"은 서버 동작으로만 있고 보여 주는 정보에는 없다.
- 가게 메모(시안별 설명 글): 요소 목록에 없다. 파일 이름만 보인다.
