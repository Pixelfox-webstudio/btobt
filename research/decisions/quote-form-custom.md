# 맞춤작업복 견적문의 · 파트너 제휴 구조 결정

대상: `custom-intro.html`(맞춤작업복 견적문의, 회원 전용 긴 양식), `partnership.html`(파트너 제휴, 로그인 없이 쓰는 짧은 양식)
본 캡처: `research/refs/quote-form/`의 LG전자 B2B 온라인 견적(PC · 모바일 두 장 · 안내 팝업), GOV.UK 오류 요약 · 답 확인(PC · 모바일), 샵다나와 PC견적(PC), 숨고 수량 질문(모바일). 기록은 같은 폴더의 `notes.md`.
같은 유형의 일반 견적문의(`quote-intro` · `quote`)는 다른 작업자가 `quote-form.md`로 정한다. 이 문서는 위 두 페이지만 다룬다.

## 캡처에서 확인한 사실

| 곳 | PC | 모바일 |
|---|---|---|
| LG 온라인 견적 | 제목 + 설명 두 줄(가운데) → 배너 3개 → "제품 카테고리 선택" → "기업정보" → "설치 현장 정보" → 약관 → 버튼 2개. 기업정보는 회색 라벨 열(약 210px) + 입력 열의 표. 휴대전화는 `010 선택 − 칸 − 칸` 3칸, 이메일은 `아이디 @ 도메인 + 직접입력 선택`, 칸 아래에 도움말 한 줄. 표마다 아래에 "* 표시는 필수 입력 항목입니다." 약관 본문 5개를 펼쳐 두어 약관만 약 2,000px | 라벨이 칸 위로 올라가고 한 열. 섹션 제목은 어두운 띠. 연락처 3칸은 한 줄 유지, 이메일 3조각도 한 줄이라 칸 하나가 약 70px. 버튼 2개는 반반 |
| GOV.UK 오류 요약 | 제목 위에 테두리 상자("There is a problem" + 오류 문장, 문장마다 해당 칸 링크). 해당 칸 위에 같은 문장, 비어 있는 칸만 테두리 색이 바뀌고 넣은 값은 남는다 | 같은 구조, 문장만 줄바꿈 |
| GOV.UK 답 확인 | 묶음 제목 아래 "항목 이름 · 값 · 변경" 줄, 줄 사이 1px 선 | 세 칸이 세로로 쌓인다 |
| 샵다나와 | 왼쪽 넓은 열에서 고르고 오른쪽 약 400px 요약. 로그인은 요약 머리의 한 줄 안내로만 권한다 | 요약이 따로 떨어진 화면 |
| 숨고 | 위쪽 고정 띠 + 진행률, 질문 카드 하나씩 | 수량 줄의 −/+ 약 32px |

## 맞춤작업복 견적문의

### 구조 후보
1. **가운데 좁은 한 열(760px)**: 사진 배너 → 입력 칸을 한 줄에 하나씩. NN/g · Baymard가 권하는 모양이지만 1440 화면에서 양옆이 비어 "밋밋하다"는 평을 다시 받기 쉽고, 대표 사진과 소개가 양식 위에 한 덩어리로만 쌓인다.
2. **왼쪽 양식 + 오른쪽 따라오는 요약(다나와)**: 요약에 넣을 것이 없다. 이 양식은 상품을 여러 개 담는 구조가 아니고, 요소 목록에 "입력 진행"이나 "요약" 요소가 없다. 요약을 만들면 목록에 없는 기능을 새로 넣게 된다.
3. **위: 사진 7 · 소개 5의 두 칸 / 아래: 묶음 제목을 왼쪽 열(PC)에 둔 양식**: 대표 사진과 소개 제목·설명·조건 표를 첫 화면에 나란히 두고, 양식은 묶음 제목과 묶음 설명을 왼쪽 260px 열에, 입력 칸을 오른쪽에 둔다. LG의 "라벨 열 + 입력 열" 표를 묶음 단위로 키운 모양이다.

### 결정: 3번
- **첫 화면**: 경로(홈 / 맞춤작업복) → 제목 `맞춤작업복` + 작은 글자 `견적문의`(요소 목록 "페이지 제목 + 견적문의 표시") → 사진(왼쪽, 3:2, 모서리 16, "연출 이미지입니다.") + 소개(오른쪽: 제목 "기업 로고와 디자인을 반영한 / 맞춤 의류 제작"을 앞말 400 + 이름 700으로, 설명 두 문장, 정보 줄 4개 `문의 대상 · 최소 주문 · 디자인 파일 · 접수 확인`).
  - 근거: 요소 목록이 대표 사진 · 소개 제목과 설명을 따로 요구한다. 상품 상세의 사진 7 : 정보 5 비율(`DESIGN.md` 조립표)을 그대로 쓰면 홈 사진 배너와 같은 모서리·주석 규칙을 지키면서 1440에서 양옆이 비지 않는다. 정보 줄 4개는 요소 목록에 이미 있는 조건(회원 전용, 최소 100장, 5개 · 20MB · 100MB, 마이페이지 문의 내역으로 이동)만 다시 적은 것이다. 회사에 대한 새 사실은 넣지 않는다.
  - 사진 위에 글을 얹지 않는다. 소개 문장이 두 줄 이상이고 정보 줄이 붙어 사진 위에서는 읽기 어렵다.
- **양식 묶음 순서**: `제작 내용`(제작 품목 → 제작 수량 · 희망 납기일 → 샘플 제공 여부 → 디자인 파일 → 기타 요청사항) → `담당자 정보`(회사/단체명 · 담당자명 → 연락처 → 이메일) → `개인정보 동의` → 버튼 줄(취소 · 문의 접수하기).
  - 근거: 담당자 정보는 회원 정보로 미리 채워져 있어 확인만 하면 된다. 직접 써야 하는 칸을 위에 두어 손이 가는 곳부터 시작하게 한다. LG가 "무엇을 → 누가 → 동의 → 버튼"으로 쌓은 순서와도 같다.
- **PC 양식 모양**: 묶음마다 위에 1px 검정 선, 왼쪽 260px 열에 묶음 제목(18/700) + 설명 한두 줄, 오른쪽 열에 입력 칸. 오른쪽 열 안에서 나란히 두는 칸은 한 덩어리인 것뿐이다: `회사/단체명 · 담당자명`, `제작 수량 · 희망 납기일`. 나머지는 한 줄에 하나.
  - 근거: Baymard · NN/g(기록 "사용성 근거")는 짧고 한 덩어리인 칸만 한 줄에 두라고 한다. 왼쪽 열이 묶음 이름을 계속 보여 주어 긴 양식에서 어디쯤인지 알 수 있다. 1024 미만에서는 묶음 제목이 칸 위로 올라간다(LG 모바일과 같다).
- **연락처**: `앞자리 선택(휴대폰 010 · 011 · 016~019 / 지역번호 02~064 / 070) − 가운데 3~4자리 − 끝 4자리` 세 칸을 PC · 폰 모두 한 줄에 둔다(LG와 같다). 칸 묶음 폭은 PC 최대 480px.
- **이메일**: `아이디 @ 도메인` + `도메인 선택(직접 입력 · naver.com · daum.net · hanmail.net · gmail.com · nate.com · kakao.com)`. PC는 한 줄, 폰은 도메인 선택을 다음 줄로 내린다(LG 모바일에서 세 조각이 한 줄이라 칸이 약 70px로 좁아진 것을 피한다). 도메인을 고르면 도메인 칸에 채우고 고칠 수 없게 하며, `직접 입력`을 고르면 칸을 비우고 연다.
- **제작 수량**: 숫자 칸 + 칸 안 오른쪽 `장` + 아래 도움말 "최소 주문 수량은 100장입니다." 100 미만이면 같은 자리에 오류 문장.
- **샘플 제공 여부**: 카드형 선택 두 개(`제공 가능` · `제공 불가`, 각각 아래 설명 한 줄). 하나만 고르고 필수.
- **디자인 파일**: 공용 파일 첨부 상자(최대 5개 · 파일당 20MB · 합계 100MB, 이미지 · PDF · 문서 · 한글 · 압축). 개수 · 용량 오류는 공용 부품이 같은 문장으로 알린다. 입력 오류 상태에서는 첨부한 5개 아래에 첨부하지 못한 파일 3줄(파일당 20MB 초과 · 합계 100MB 초과 · 5개 초과, 각 줄에 이유 문장과 크기)을 오류색 선 줄로 보여 주고, 오류 요약에도 파일마다 한 줄씩 넣는다.
- **개인정보 동의**: 공용 동의 상자 한 줄(체크 · "(필수)" · 자세히 보기 → 개인정보처리방침). 수집 항목과 이용 목적을 아래 작은 글자로 한 줄 적는다. LG처럼 본문을 펼쳐 두지 않는다(약관이 2,000px를 차지했다).
- **오류**: GOV.UK 방식으로 두 곳에 같은 문장. 양식 맨 위에 오류 요약 상자(제목 "입력한 내용을 확인해 주세요." + 오류마다 해당 칸으로 가는 링크)를 두고, 해당 칸 아래 도움말 자리에 같은 문장을 빨간 글자로 둔다. 넣은 값은 지우지 않는다. 고치면 그 칸의 오류가 바로 사라진다(공용 동작).
- **비회원**: 양식은 그대로 보이되 모든 칸을 입력 불가(회색)로 둔다. 양식 맨 위에 회원 전용 안내 상자(자물쇠 표식 + 문장 + `로그인` · `회원가입` 버튼 + 간편 로그인 세 개)를 두고, 맨 아래 버튼 줄의 `문의 접수하기` 자리를 `로그인 후 문의하기`로 바꾼다. 모든 링크에 `return=custom-intro.php`를 붙여 이 화면으로 돌아오게 한다.
  - 근거: 다나와가 로그인을 막는 화면이 아니라 한 줄 안내로 권했고, 요소 목록이 "입력 항목이 보이지만 모두 입력 불가"를 요구한다. 칸을 보여 주면 무엇을 준비해야 하는지 로그인 전에 알 수 있다.
  - 간편 로그인은 흰 바탕 선 버튼에 로고 표식만(카카오만 `#FEE500` 원). 네이버 · Google은 검정 단색 표식.
- **접수 중 · 접수 완료 · 서버 오류 · 로그인 풀림**: 접수 중은 버튼 안 회전 표시 + 버튼 위 한 줄 안내(입력칸 열 폭 100%), 칸은 그대로. 완료는 가운데 확인 팝업(표식 + "문의를 접수했습니다." + 문의번호 줄 + 다음 단계 설명 + `문의 내역 보기` → `mypage.html?section=inquiries`). 서버 오류는 버튼 위 한 줄 상자(흰 바탕 + 오류색 선), 넣은 값 유지. 로그인 풀림은 가운데 팝업 + `다시 로그인`(돌아올 주소 포함).
- **결과 안내는 한 곳에 한 번만**: 화면 안에 안내 상자 · 팝업이 뜨는 상태(오류 요약, 서버 오류, 접수 완료)에서는 토스트를 띄우지 않는다. 같은 문장이 두 번 보이고, 폰에서는 토스트가 상자 글자를 가렸다(검수 지적). 상자가 뜨면 그 상자로 스크롤하고 포커스를 옮긴다. 파트너 제휴도 같은 규칙이다.
- **버튼 줄 위치**: PC(1024 이상)에서 버튼 줄은 입력칸 열(왼쪽 260px 묶음 제목 열 다음 칸) 안에서 오른쪽 끝에 붙인다. 파트너 제휴도 양식 열 오른쪽 끝이라 두 페이지의 규칙이 같다.
- **1100 이하 PC · 태블릿 첫 화면**: 사진 5 · 글 7로 바꾸고 제목은 앞말 / 이름 두 줄, 글 오른쪽에 떠 있는 상담 버튼 자리(36px)를 비운다. `파일당 20MB` 같은 값 덩어리는 줄바꿈하지 않는다.
- **모서리 · 색**: 선택 카드 · 첨부 파일 줄 · 첨부 상자 · 동의 상자 · 안내 상자는 16px, 파일 표식은 원(본문 글꼴 11/700). 입력칸은 `DESIGN.md` Shapes `rounded.md`(입력칸 파생 12px) 그대로. 오류색은 `DESIGN.md` 811줄의 red 세트 값(선 #D10019 · 글자 #B80016)을 CSS 변수 `--cf-err` · `--cf-err-t`로만 쓰고, 오류 상자는 옅은 면 없이 흰 바탕 + 선(견적문의 `quote`의 오류 요약과 같은 모양).
- **폰**: 사진은 화면 끝까지(모서리 0, 3:2) → 소개 → 정보 줄 → 양식 한 열. 버튼 줄은 `문의 접수하기`가 위, `취소`가 아래인 전체 폭(공용 `.form-acts`).
- **버튼 색**: 제출은 검정(`.bt--ink`). 폰 하단 상담 바의 `견적문의`가 이미 파랑이라 한 화면에 파란 버튼이 둘이 되지 않게 한다.

## 파트너 제휴

### 구조 후보
1. **양식만 가운데 한 열**: 연락처 3개 칸이라 짧지만, 요소 목록의 회사 주소 · 전화 · 팩스 · 이메일과 소개 · 빠른 답변 안내가 양식 위에 쌓여 PC에서 넓은 빈 곳이 생긴다.
2. **왼쪽 소개 · 연락처(5) + 오른쪽 양식(7)**: 회사 연락처를 보면서 양식을 쓴다. 폰에서는 소개 → 양식 → 연락처 순서로 바꿔 쌓아 양식이 첫 화면 가까이 온다.

### 결정: 2번
- **순서**: 경로(홈 / 파트너 제휴) → 제목 → 묶음 메뉴(공용 `.wrap.sub-nav > .stab` 알약 탭 줄: 납품사례 · 구매후기 · 이벤트 · 파트너십, 현재 페이지는 검정 알약 · 흰 글자 700, `aria-current="page"`. 같은 묶음의 세 페이지와 마크업이 같다) → 두 칸.
- **왼쪽**: 소개 제목(앞말 + 이름) + 소개 문장 → 빠른 답변 안내(`.note`, 세 줄) → 연락처 정보 줄(주소 · 대표전화(누르면 전화) · 팩스 · 이메일(누르면 메일)). 주소 · 전화 · 이메일 · 상담 시간은 홈 푸터 값만 쓰고, 팩스는 값이 없어 견본 값(`data-sample`).
- **오른쪽**: 묶음 제목 "제안 남기기" + 필수 표시 → `연락처 · 이메일` 두 칸 → 제안내용(4,000자, 글자 수) → 버튼 줄(취소 · 제안하기).
- **결과 안내**: 양식 위 한 줄 상자 하나로만 알리고 토스트는 띄우지 않는다(맞춤작업복과 같은 규칙). 제출 뒤에는 그 상자로 스크롤하고 포커스를 옮긴다. 접수 완료는 파란 한 줄 안내(`.msg--ok`), 칸은 비운다(요소 목록 "이 페이지로 돌아옴", "제출 직후에만"). 미입력 · 이메일 형식은 해당 칸 아래 문장 + 양식 위 오류 한 줄. 너무 잦은 요청 · 접수 실패는 양식 위 오류 한 줄, 넣은 값은 남긴다. 오류 줄은 흰 바탕 + 오류색 선.
- **버튼 줄**: 양식 열 오른쪽 끝(취소 · 제안하기). 폰은 전체 폭으로 쌓는다.
