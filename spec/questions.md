# 사장님이 정해 주셔야 하는 것

작업 중에 묻지 않고 가장 무난한 쪽으로 정해 진행한 곳입니다. 다르게 하고 싶은 항목이 있으면 알려 주세요. 페이지별 세부 질문은 맨 아래 "페이지별"에 모았습니다(작업자 기록 `spec/questions/*.md`에서 옮김).

## 사이트 전체
1. **홈 시안의 위 띠 문구가 요소 목록과 다릅니다.** 요소 목록에는 "공장 직납·후불 결제·기업·관공서 전용 맞춤작업복", "카카오톡 채널 상담 시 견적 추가 할인" 안내가 있는데, 홈 시안의 위 띠에는 이 문구가 없습니다. 하위 페이지는 홈 시안의 헤더를 그대로 복사해 쓰므로 홈 문구를 따랐습니다. 요소 목록 문구로 바꿀지 정해 주세요. (추가 할인 문구는 할인율 같은 사실을 확인해야 해서 지어 넣지 않았습니다.) 또 위 띠의 "사업자등록증 확인 후 기업회원 승인"은 요소 목록 L1182(가입 즉시 이용, 관리자 승인 없음)와도 맞지 않습니다. 둘 중 하나를 고쳐야 합니다.
2. **홈 시안에 없는 공통 요소를 하위 페이지에서만 덧붙였습니다.** 헤더의 로그인 회원 이름·로그아웃, 장바구니 담긴 수, 검색 층의 인기 검색어·진행 중 이벤트, 우측 상담 메뉴(고객센터 메뉴 묶음), 방문 기록(쿠키) 동의 안내입니다. 홈 시안에도 같은 모양으로 넣어야 합니다. 지금은 `js/sub.js`가 하위 페이지에서만 실행 중에 붙입니다.
3. **상담 메뉴의 마스코트 그림, 통장 사본 이미지, SNS 주소가 없습니다.** 자리만 잡아 두었습니다(`data-slot="mascot"`, `data-slot="bank-book"`, `data-sample`).
4. **사진 자료**: 분류 대표 사진, 이벤트, 로그인·가입 화면에는 홈 시안의 AI 연출 사진을 다시 썼고 "연출 이미지입니다."를 붙였습니다. 실제 사진으로 바꿀 자리는 `data-slot`으로 표시했습니다.

## 상품 목록
5. **작업복 분류의 상품 자료가 없습니다.** 시안에서는 조끼·자켓·바지 상품을 계절별 작업복의 견본으로 보여 줍니다.
6. **세부 분류·소재·형태·시즌·색 이름이 상품 자료에 없습니다.** 필터 선택지를 보여 주려고 상품명과 색 값에서 읽어 낸 견본 값을 썼습니다(`js/sub-data.js`). 실제 값은 운영 자료로 바뀝니다.
7. **필터를 여는 방식**: PC는 필터 종류 6개를 버튼 한 줄로 두고 누르면 그 종류만 아래에 뜨게 했고, 폰은 화면을 채우는 필터 모음으로 열게 했습니다(근거 `research/decisions/list.md`). 필터를 왼쪽에 늘 펼쳐 두는 방식을 원하시면 바꿀 수 있습니다.
8. **판매량순 정렬**: 판매 자료가 없어 시안에서는 순서만 바뀌는 견본입니다.

## 화면 구성
9. **따로 열리는 창**(견적서 7종, 시안확인, 견적문의 시안 보기)은 요소 목록에 "닫기"가 있어 새 창으로 보고, 사이트 헤더·푸터 대신 로고·문서 이름·닫기만 있는 얇은 머리줄을 썼습니다. 같은 창 안에서 사이트 헤더와 함께 여는 방식을 원하시면 바꿀 수 있습니다.
10. **마이페이지(13부분)와 고객센터(8부분)는 각각 한 파일**로 만들고 주소 값(`?section=`, `?tab=`)으로 부분을 바꿉니다. 부분을 바꿔도 페이지를 새로 불러오지 않고, 부분마다 주소를 공유할 수 있습니다.
11. **우편번호 검색**은 외부 서비스라 시안에서는 버튼을 누르면 견본 주소가 채워지기만 합니다.
12. **홈 시안이 링크하는 인쇄방법(`printing.php`)·로고 넣기 안내(`guide-logo.php`)** 는 요소 목록이 없어 만들지 않았습니다. 필요하면 요소 목록을 주세요.

## 사이트 전체 (작업 중 추가)
13. **입력 오류 빨강을 디자인 토큰으로 정식 등록할지 정해 주세요.** 지금은 홈 `site.css`의 빨강 강조 세트(선 #D10019 · 글자 #B80016 · 옅은 바탕 #FFF0F1)를 하위 페이지 공용 변수(`--err` `--err-t` `--err-soft`)로만 쓰고, DESIGN.md 토큰 목록은 바꾸지 않았습니다(작업 지시: 토큰은 바꾸지 않음). 알림(토스트)은 오류일 때도 검정입니다.
14. **페이지 안 메뉴를 알약 탭으로 통일했습니다.** 처음에는 밑줄 탭이었는데, 검수에서 DESIGN.md "탭은 알약" 규칙 위반으로 지적되어 고객센터·후기·이벤트·납품사례·파트너 제휴·약관·마이페이지(폰)의 메뉴를 홈 탭(`tab-pill`)과 같은 모양으로 바꿨습니다. 밑줄 탭을 원하시면 공용 한 곳(`.stab`)만 바꾸면 됩니다.
15. **상품 목록 한 쪽의 상품 수**: 요소 목록대로 48개(협력브랜드 45개, 검색 30개)를 보여서 폰 화면 길이가 약 9,700px로 홈보다 깁니다. 폰에서만 24개로 줄일지 정해 주세요.
16. **홈에 넣어야 할 것**(하위 페이지 작업 중 나온 것): 홈 구매후기 카드와 "후기 전체 보기"를 후기 목록·상세 페이지(`reviews.php`, `review-view.php?id=`)로 잇기, `js/reviews.js` 후기마다 업종·등록일·평가 수치 값(지금은 하위 페이지에서 견본 값), 헤더 장바구니 담긴 수(2번과 같음).
17. **1024px 화면에서 우측 상담 버튼이 본문 오른쪽 끝을 조금 가립니다.** 홈 부품(`.side-cs`)이라 고치지 않았습니다. 이 폭에서 숨길지 정해 주세요.
18. **견본 금액**: 장바구니 3건의 견본 금액은 공급가 6,146,000원 + 부가세 614,600원 = 6,760,600원으로 주문서·견적서·주문 완료·시안확인에 똑같이 맞췄습니다. 상품 단가(59,000원 등)는 부가세 별도로 읽었습니다.

## 페이지별
작업자 기록(`spec/questions/<과제>.md`)을 그대로 옮겼습니다. 각 줄은 "정해지지 않아 무난한 쪽으로 만든 것"과 그 이유입니다.

### 상품 상세 (product)
- 상품 옵션(L210) 자료가 없다 → `c463`에만 견본 옵션 "핏: 남녀공용 / 여성용"을 넣고 `data-sample`을 붙였다. 옵션 값이 1개 이하인 상품은 옵션 단계를 숨긴다.
- 포장 방식(기본 포장 / 개별 폴리백), 인쇄방법(자수·실크·전사 인쇄), 인쇄 부분(왼쪽·오른쪽 가슴, 등, 왼쪽·오른쪽 팔 / 모자는 앞면·옆면·뒷면)은 상품 자료에 없어 견본 값이다(`data-sample`). 조끼는 팔 부분을 뺐다.
- 협력브랜드 72종은 모두 사이즈·색상이 없다 → "협력브랜드 상품" 상태는 `b3026`에 견본 사이즈 95~110을 붙여(`?id=3026&brand=k2&state=sized`, `data-sample`) 사이즈별 수량 칸을 보이고, 기본 `?id=3026&brand=k2`는 글로 적기로 보인다.
- 가격이 "1만원대"처럼 구간으로만 있는 단체복(`c504` 등 7종)은 정확한 판매가가 없어 할인 계산을 하지 않고 총액에 "견적문의"를 적었다. 버튼은 주문하기 그대로. 운영 자료에 판매가가 있으면 계산된다.
- 글로 적은 사이즈별 수량은 "숫자 + 벌"만 더해 총수량에 넣는다(예: "95 4벌, 100 6벌" → 10벌). 벌을 안 적으면 0벌로 보고 미입력 안내를 띄운다.
- 따라오는 바는 구매 칸 끝의 요약(총수량·할인·총액·버튼)이 화면에 없을 때 뜬다. 그래서 첫 화면에서도 보인다(PC·폰 모두). 폰에서는 이 페이지만 공통 상담 바(`.mbar`)를 감추고 바에 전화·카카오톡을 넣었다.
- 폰(768 이하)의 상세 정보 네 부분은 탭처럼 하나씩 보인다(펼치면 상세 정보만 약 2,200px). PC는 네 부분을 모두 펼치고 이동 줄이 스크롤 위치를 따라간다.
- 협력브랜드 상품의 견적문의도 요소 목록 L229 그대로 주문내역(`mypage.html?section=orders`)으로 보낸다(견적문의 내역 `?section=inquiries`로 보낼지는 확인 필요).
- 첨부 합계 100MB 초과(L248)는 "최대 10개 · 파일당 10MB" 안에서는 실제로 생기기 어렵다 → 첨부 오류 상태에는 파일당 초과·중복 안내를 보이고 합계 기준은 안내 문장으로 적었다. 공용 첨부(`sub.js`)는 합계 초과도 검사한다.
- 인쇄 부분 안내 그림·상품정보·배송/포장·반품/교환 안내 이미지 자료가 없다 → 상품 앞·뒤 사진 위 번호 표식, 상세 갤러리 사진 + 정보 표, 아이콘 4칸, 2열 표로 짜고 각 자리에 `data-slot`을 붙였다.
- 반품/교환 안내의 문장은 고객센터 주문방법 "주문 전 확인 사항"과 취소/환불 정책 페이지의 연락 문장에서만 가져왔다(불량·오배송 기준처럼 요소 목록에 없는 규정은 적지 않음).
- (검수 뒤) PC 사이즈별 수량을 색상 행 × 사이즈 열 표에서 1024 이하와 같은 색상별 묶음(`− 숫자 +` 44px, 사이즈 칸 줄 나눔)으로 바꿨다. 사이즈별 합계는 묶음 아래 한 줄로 남겼다(폰은 뺌).
- (검수 뒤) 바가 떠 있는 동안 PC 우측 플로팅의 상담·카카오 원을 감추고 맨 위로만 남긴다. 이 페이지에서 상담 메뉴(빠른 상담 패널)는 요약이 화면에 보일 때만 열 수 있다. 다른 페이지와 다르게 둬도 되는지 확인 필요.
- (검수 뒤) 상품 없음 화면의 추천 상품 4개는 홈 '상품 랭킹'과 같은 추천순 자료 앞 4개다. 판매량 근거가 없어 제목을 "많이 찾는" 대신 "추천 단체복"으로 했다.
- (검수 뒤) 입력 오류 빨강(#D10019 · #B80016 · #FFF0F1)은 지침 0절대로 공용 부품 값을 그대로 쓴다. DESIGN.md colors에 오류 색을 올리고 공용 CSS를 변수로 바꾸는 일은 공용 담당 몫이라 하지 않았다.
- 비로그인으로 주문·장바구니를 누르면 고른 값을 이 브라우저(localStorage)에 30분 보관하고 로그인 화면(`login.html?return=…&restore=1`)으로 보낸다. 실제 서비스에서는 서버 보관이 필요할 수 있다.

### 장바구니 · 주문서 · 바로주문 (cart, order, order-now)
**견본 값**
- `c195` 웰론 보온 겨울조끼: 상품 자료의 색상은 블랙·베이지·화이트이고 사진은 밝은 회색인데, 지침 7.4대로 "네이비"(#1F3864 견본)로 적었다.
- 협력브랜드 상품(케이투 JK-F6101)은 색상·사이즈·포장 자료가 없어 "선택 없음" + 수량 칸 하나(12벌)로 두었다. 사이즈를 글로 적은 견본 내용은 만들지 않았다.
- 주문서의 최종 견적금액을 6,146,000원(패딩 4,130,000 + 조끼 840,000 + 케이투 견적 단가 98,000원 × 12벌 = 1,176,000)으로, 견적일 2026-11-14 · 유효기간 2026-11-29로 정했다. 주문 완료·견적서 페이지와 숫자를 맞춰야 한다. → (정리함) 모든 페이지를 공급가 6,146,000원 + 부가세 614,600원 = 6,760,600원으로 맞췄습니다.
- 기본배송지 견본 "녹산 공장 (46744) 부산광역시 강서구 녹산산업중로 333, 2동 자재창고"는 새로 만든 견본 값이다(지침 7.4에는 주소가 하나뿐).
- 주문서 접수 안내의 주문번호는 지침의 주문 번호 `O-20261115-0007`, order-now 접수 완료는 시안 요청 번호 `R-20261112-0031`을 썼다.

**장바구니**
- 상품 금액은 요소 목록대로 단가 × 수량이다(수량 할인 미적용). 상품 상세는 할인을 적용한 총액을 보이므로 두 화면 금액이 다르게 보일 수 있다.
- 주문 요약에 합계 금액을 두지 않고 "인쇄비·배송비와 견적문의 상품 금액은 견적서에서 안내합니다"로 적었다(요소 목록에 합계가 없고, 견적문의 상품이 섞이면 확정 금액처럼 읽힌다).
- 선택 삭제는 처음 들어와 선택을 바꾸기 전에는 흐리게 두고, 누르면 이유를 알린다(버튼을 막아 두면 왜 안 되는지 알 수 없어서).
- 수량이 모두 0이 되면 바로 지우지 않고 한 번 묻는다. 취소하면 직전 수량으로 돌아간다.
- 비로그인은 원래 로그인 화면으로 바로 넘기는 동작인데, 시안에서는 안내 화면 + 로그인 버튼으로 보여 준다(세 페이지 모두).

**주문서 작성(결제)**
- 잔금 결제에서 "잔금 금액"과 원 주문 결제액을 따로 보여 줄지 정하지 못했다. 금액은 견적 금액 그대로 두고, 원 주문번호 줄 · 수정 불가 표시 · 원 주문 증빙(세금계산서) · 동의 완료만 바꿨다. 증빙이 보이도록 잔금 결제의 기본 결제수단을 무통장입금으로 두었다.
- 후불결제 안내의 "인쇄 없는 할인 견적 기반 요청은 예외"가 후불 불가인지 허용인지 분명하지 않아 "단, 인쇄 없는 할인 견적으로 요청한 주문은 예외입니다"로 원문에 가깝게 적었다.

### 주문 완료 · 카드 결제 처리 (order-complete, nicepay-return)
- 무통장입금 주문 완료에 "입금 계좌" 줄(부산은행 101-2000-0000-00 · 예금주 주식회사 노을상사, `data-sample`)을 넣었다. 요소 목록의 주문 완료 절에는 계좌가 없지만 계좌 없이는 입금할 수 없어 넣었다. 계좌 복사 버튼은 목록에 없어 넣지 않았다. 입금 기한도 정해진 값이 없어 적지 않았다.
- 정보 줄에 요소 목록 값(번호·유형·금액·결제수단) 말고 "진행 상태"(접수 대기 / 상품 준비중 / 입금 대기 / 후불 요청, 서버 동작 L544 · L909의 상태 이름)와 "안내 메일"(L542 · L545의 고객 메일)을 더했다. 실제 상태 이름이 다르면 바꿔야 한다.
- 후불결제 요청 완료에 "결제 희망일 2026-12-15"(견본)를 결제수단 아래에 적었다. 주문서에서 받은 값이라 다시 보여 주는 것이다.
- 결제금액 견본은 `cart-checkout.md`의 주문서 결제 버튼 금액 6,146,000원과 같게 했다. 카드·무통장·후불 세 상태 모두 같은 금액이다(후불은 포인트를 쓸 수 없어 실제로는 금액이 다를 수 있다). → (정리함) 모든 페이지를 공급가 6,146,000원 + 부가세 614,600원 = 6,760,600원으로 맞췄습니다.
- 카드 결제 처리의 실패 화면에 "결제 상태" 칩(주문 확정 안 됨 / 결제 안 됨 / 확인 필요)을 두었다. "결제 안 됨"은 승인 전에 멈추는 다섯 경우(세션·취소·만료·불일치·위변조)에 붙였다. 승인 응답 위변조처럼 실제로는 승인이 됐을 수 있는 경우는 "카드 승인 오류"에 묶여 있어 "확인 필요"로 적었다.
- 결제 세션 확인 불가 상태는 주문을 특정할 수 없다고 보고 주문번호·결제금액 줄을 뺐다.
- 승인 후 주문 확정 오류와 카드 승인 오류의 다음 순서에 "다시 결제하지 말고 고객센터 0507-1378-6094로 알려 주세요"를 넣었다(번호는 푸터 값). 실제 처리 방법(자동 취소 여부 등)이 정해지면 문구를 맞춰야 한다.

### 견적문의 · 견적문의 안내 (quote, quote-intro)
**두 입력 방식**
- 대화형 입력과 한 화면 입력 양식을 오가는 전환 링크를 두지 않았다(요소 목록에 없다). 한 화면 양식은 `quote.html?mode=form` 주소로만 들어간다. 어느 쪽을 언제 보여 줄지(사이트 설정인지, 들어온 곳에 따라 나뉘는지) 정해야 한다.
- 상품 검색 팝업의 상태(열림·추천 상품, 자동완성, 검색 결과, 결과 없음, 찾는 중, 너무 긴 검색어, 불러오기 오류, 등록된 상품 없음)는 한 화면 양식에서 연 모습으로 만들었다. 대화형에서 연 모습은 `state=search+pick` 하나만 두었다(같은 팝업이다).

**대화형 입력**
- 진행률은 지금 경로의 질문 수 기준이다. 상품 유형·인쇄 여부·상품 수에 따라 질문 수가 바뀌어, 답을 하나 했는데 %가 내려갈 수 있다(예: "다른 상품도 문의" → 예를 고르면 전체 질문이 늘어 73% → 38%). 숫자 옆에 "답한 질문 9 / 24"를 같이 적어 이유가 보이게 했다.
- 답을 고치면(수정) 뒤 답은 그대로 둔다. 예외는 요소 목록의 상품 유형 변경(그 상품의 뒤 답 지움)과, "다른 상품도 문의"를 아니요로 바꿀 때 뒤 상품을 지우기 전에 확인 창을 띄우는 것 두 가지다.
- 인쇄 여부를 "인쇄 없음"으로 고치면 인쇄방법·로고 파일·인쇄 부위 답은 숨기기만 하고 지우지 않는다(다시 "인쇄 있음"으로 바꾸면 돌아온다). 접수할 때는 보내지 않는 것으로 가정했다.
- 다 답한 앞 상품은 한 줄로 접는다("1번째 상품 · 방한 후드 패딩 · 70개 · 인쇄 있음(자수 인쇄)"). 펼치면 답과 수정이 그대로 있다. 폰에서 대화가 끝없이 길어지는 것을 막으려고 정했다.
- 수량 칸은 숫자 하나다(요소 목록 L606). 사이즈별 수량은 다음 질문(옵션)에 글로 적게 안내했다. 숨고처럼 사이즈 줄마다 수량을 받는 방식은 쓰지 않았다.
- 마지막 단계의 보내기 버튼은 검정이다. 폰 하단 상담 바의 "견적문의"가 이미 파랑이라 한 화면에 파란 버튼이 둘이 되지 않게 했다.
- 접수 완료는 팝업(문의번호 `Q-20261110-0012`)으로 알리고 3초 뒤 `mypage.html?section=inquiries`로 옮긴다. 바로 옮길지, 사용자가 버튼을 누를 때 옮길지는 정해야 한다(버튼도 함께 두었다).
- 상품 상세에서 넘어온 인쇄방법 견본은 상품 상세 화면의 "실크 인쇄"로 했다(우리 선택지 열전사·나염·자수·기타에 없으므로 선택지에 더해진다). 상품 상세의 "전사 인쇄"와 우리 "열전사 인쇄"가 같은 것인지 확인이 필요하다.
- 넘겨받은 인쇄 파일은 "상품·디자인 이미지" 질문의 답으로 넣었다(요소 목록 L605: 넘겨받은 파일이 있을 때만 이 질문이 나온다). 로고 파일 질문으로 넣어야 하는지 정해야 한다.

**한 화면 입력 양식**
- 단계 표시의 3단계 "견적서 확인"은 이 화면에 없다(다음을 누르면 새 창 미리보기에서 한다). 그래서 1·2단계만 스크롤 위치와 필수값으로 바뀌고 3단계는 늘 대기 표시다.
- 필수값 비율은 상품마다 상품명·수량 두 칸 + 회사명·담당자·연락처 세 칸으로 센다. 상품이 하나도 없으면 상품명·수량 두 칸이 비어 있는 것으로 센다.
- 폰에서는 상품 묶음을 접을 수 있게 하고 처음에는 마지막 상품만 펼친다. PC는 모두 펼친다.
- 상품당 5개를 넘는 첨부는 상품 상세에서 넘어온 파일(최대 10개, L680)로만 생길 수 있어 그 경우로 `mode=form&state=err-attach` 견본을 만들었다. 넘어올 때 5개로 잘라 받을지, 지금처럼 다음 전에 지우게 할지 정해야 한다.
- 오류 문장의 상품 순서는 "1번째 상품", 묶음 제목은 "상품 1 / 2"로 썼다. 한쪽으로 맞출지 정해야 한다.

**비회원 · 안내**
- 비회원 안내의 "로그인"은 `login.php?return=quote.php`로 보낸다. 상품 상세에서 넘어온 정보를 이어받는 값(상품 키 등)을 주소에 어떻게 실을지는 개발 때 정한다.
- 비회원 안내에도 견적문의 안내와 같은 3단계(이름·설명 글자까지 같음)를 두고 1단계에 "지금 단계"를 붙였다.
- 견적문의 안내의 단계 그림은 자료가 없어 상품 사진 두 장(md-pick-463, 194-1)과 현장 연출 사진 한 장(fd-plant-w)을 넣고 `data-slot="quote-step-1~3"`을 붙였다. 관리자가 바꿀 그림의 비율은 4:3으로 가정했다.
- "평균 답변 시간 영업일 기준 1~2일"은 요소 목록 문구 그대로다. 실제 운영 수치인지 확인이 필요하다.

### 로그인 · 회원가입 (login, signup 5종)
