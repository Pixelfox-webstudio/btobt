# 질문 기록 — mypage (마이페이지)

결정이 필요했던 곳과 고른 해석. 한 줄씩.

- 주문 목록 "전체를 한 번에, 나누어 보기 없음"과 "폰에서 끝없이 긴 스크롤" 사이: 폰 카드를 줄여(머리 줄 번호·상태 / 사진 + 상품명·옵션 / 접수일·금액 + 버튼, 상태 풀이 문장은 주문 상세로) 한 장 약 185px로 만들고, 기본 1개월 12건은 접지 않았다. 그래서 조건별 버튼 9가지가 PC·폰 모두 기본 화면 목록에 한 번씩 나온다. 12건을 넘을 때만(3개월 14건 등) 폰에서 열 건 뒤를 "나머지 주문 N건 더 보기"로 접는다(PC는 모두 펼침). 다른 화면에서 지정한 주문이 접힌 쪽에 있으면 자동으로 다 펼친다.
- 진행 단계별 건수·취소/교환/반품 건수의 기준 기간: 요소 목록에 없어 "선택한 조회 기간 기준"으로 정하고 띠 오른쪽에 적었다. 기본 조회 기간은 1개월(2026-10-17~2026-11-17).
- 견적 문의 요약의 "확인할 견적": 견적완료 상태이면서 아직 열어 보지 않은 건으로 해석했다(종류별 줄에 `확인할 견적 N` 칩).
- 상태 칩 색: 고객이 할 일이 있는 상태(입금 대기·시안 완료·견적 완료·시안·견적 완료·배송 완료)는 검정, 진행 중은 회색, 구매확정은 선, 취소·반품은 빨강. 파랑 칩은 "확인할 견적"과 "공개됨"에만 썼다.
- 비밀번호 변경·회원 탈퇴는 요소 목록 메뉴 묶음에 없어 메뉴 줄로 두지 않고, 회원정보 수정 안의 밑줄 탭(비밀번호 변경)과 맨 아래 "회원 탈퇴" 링크, 옆 메뉴 맨 아래 작은 "회원 탈퇴"로 들어가게 했다.
- 안전용품 제작 문의 번호 형식: 7.4절 견본에 없어 `S-20261021-0002`처럼 S를 붙였다.
- 안전용품 메뉴를 보이지 않는 회원(L1221): 상태 `state=nosafety`로 메뉴·폰 탭·견적 문의 요약 줄을 감춘다.
- 배송조회: 요소 목록이 "택배사 조회로 이동"이라 견본으로 택배사 배송조회 화면 주소를 새 창으로 열게 했다(택배사·운송장 번호는 견본, `data-sample`).
- "견적서 보기(또는 예전 견적서 파일 보기)"의 예전 파일 변형은 따로 그리지 않았다. 예전 건은 같은 자리의 버튼이 파일을 연다고 보았다.
- 주소 검색: 우편번호 서비스 자리라 누르면 견본 주소(48058 부산광역시 해운대구 센텀중앙로 97)를 채운다. "주소 검색 서비스 불러오기 실패"(L1482)는 회원정보 수정 오류 상태에서 주소 칸 아래 안내로 보인다.
- 누적 주문금액(구매확정 합계) 958,400원, 주문·포인트·배송지·문의 값은 모두 견본(`data-sample`)이다. 포인트 잔액 흐름은 12,450P에 맞춰 거꾸로 계산했다. 적립률은 정해진 값이 없어 적지 않았다.
- 주문 대표 사진의 색과 옵션 색을 맞추려고 견본 주문의 색을 사진에 보이는 색으로 정했다(장바구니 견본 3건은 7.4절 그대로).
- 후기 사진 견본: 실제 후기(B2BT_REVIEWS)를 회원 개인의 후기로 쓰지 않으려고 상품 사진을 후기 사진 자리로 썼다(`data-slot="review-photo"`).
- "내가 쓴 후기"는 읽기만이라 "등록한 후기는 이 화면에서 고칠 수 없습니다."만 적었다(수정 절차는 요소 목록에 없다).
- 탈퇴 화면의 "지금 계정에 남아 있는 것"(진행 중 주문·답변 대기 문의·포인트·배송지 수)은 회원 본인 자료를 보여 줄 뿐이고, 탈퇴 뒤 그 자료를 어떻게 처리하는지에 대한 규정은 만들지 않았다.
- 간편 가입 회원 탈퇴의 확인 문구는 `탈퇴합니다`로 정했다(요소 목록에 문구가 없다).
- 공용 상담 메뉴(sub.js)의 "시안확인" 링크가 `mypage.php?section=draft`인데 마이페이지에 draft 부분이 없어 주문 내역으로 열린다. "배송조회" 링크(`state=shipping`)는 배송중 단계를 골라 둔 주문 내역으로 받는다.
- 다른 화면에서 지정한 주문(`?order=`)은 강조 테두리 + 그 카드로 스크롤. 스크롤된 채로 찍힌 캡처는 머리줄이 중간에 찍혀 보이지만 브라우저에서는 정상이다.
- (3차 검수 반영) 공용 부품 값 중 DESIGN.md 글자 단계에 없는 것(묶음 제목 `.fset__t` PC 18px, 입력칸 보조 설명 12.5px, 개수 배지 `.nb` 11px, 파일 크기 12.5px·확장자 11.5px·사진 "대표" 10.5px)과 둥근 표식 `.smark`의 그림자, 폰에서 한 줄로 늘어나 잘리는 알림(`.sub-toast`)은 공용 파일을 고칠 수 없어 `65-mypage.css` 맨 아래에 `body[data-page="mypage"]`로 묶어 임시로 고쳤다(20 / 13 / 12 / 12px, 그림자 없음, 폰 알림 좌우 16px 안에서 줄바꿈). 공용 쪽이 고쳐지면 그 묶음을 지운다.
- 오류 빨강 세 가지(#D10019 선 · #B80016 글자 · #FFF0F1 바탕)는 검수에서 "토큰에 없는 색"으로 지적됐지만, 지침 0절이 "홈 site.css의 red 강조 세트 값이라 그대로 쓴다"고 정했고 DESIGN.md는 공용 파일이라 바꾸지 않았다. DESIGN.md colors에 error · error-soft로 등록할지는 반장 결정으로 넘긴다.
- `.pop__t`·`.st`의 18px은 폰(≤768)에서만 쓰이고 PC는 20px이다. DESIGN.md 글자 단계표의 "패널 제목 20 / 폰 18" 값과 같아 그대로 두었다.
