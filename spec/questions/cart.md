# 질문 기록 — cart (장바구니 · 주문서 작성 · 주문 정보 입력)

정하지 못해 가장 무난한 쪽으로 만든 곳이다. 한 줄씩 적는다.

## 견본 값
- `c195` 웰론 보온 겨울조끼: 상품 자료의 색상은 블랙·베이지·화이트이고 사진은 밝은 회색인데, 지침 7.4대로 "네이비"(#1F3864 견본)로 적었다.
- 협력브랜드 상품(케이투 JK-F6101)은 색상·사이즈·포장 자료가 없어 "선택 없음" + 수량 칸 하나(12벌)로 두었다. 사이즈를 글로 적은 견본 내용은 만들지 않았다.
- 주문서의 최종 견적금액을 6,146,000원(패딩 4,130,000 + 조끼 840,000 + 케이투 견적 단가 98,000원 × 12벌 = 1,176,000)으로, 견적일 2026-11-14 · 유효기간 2026-11-29로 정했다. 주문 완료·견적서 페이지와 숫자를 맞춰야 한다.
- 기본배송지 견본 "녹산 공장 (46744) 부산광역시 강서구 녹산산업중로 333, 2동 자재창고"는 새로 만든 견본 값이다(지침 7.4에는 주소가 하나뿐).
- 주문서 접수 안내의 주문번호는 지침의 주문 번호 `O-20261115-0007`, order-now 접수 완료는 시안 요청 번호 `R-20261112-0031`을 썼다.

## 장바구니
- 상품 금액은 요소 목록대로 단가 × 수량이다(수량 할인 미적용). 상품 상세는 할인을 적용한 총액을 보이므로 두 화면 금액이 다르게 보일 수 있다.
- 주문 요약에 합계 금액을 두지 않고 "인쇄비·배송비와 견적문의 상품 금액은 견적서에서 안내합니다"로 적었다(요소 목록에 합계가 없고, 견적문의 상품이 섞이면 확정 금액처럼 읽힌다).
- 선택 삭제는 처음 들어와 선택을 바꾸기 전에는 흐리게 두고, 누르면 이유를 알린다(버튼을 막아 두면 왜 안 되는지 알 수 없어서).
- 수량이 모두 0이 되면 바로 지우지 않고 한 번 묻는다. 취소하면 직전 수량으로 돌아간다.
- 비로그인은 원래 로그인 화면으로 바로 넘기는 동작인데, 시안에서는 안내 화면 + 로그인 버튼으로 보여 준다(세 페이지 모두).

## 주문서 작성(결제)
- 잔금 결제에서 "잔금 금액"과 원 주문 결제액을 따로 보여 줄지 정하지 못했다. 금액은 견적 금액 그대로 두고, 원 주문번호 줄 · 수정 불가 표시 · 원 주문 증빙(세금계산서) · 동의 완료만 바꿨다. 증빙이 보이도록 잔금 결제의 기본 결제수단을 무통장입금으로 두었다.
- 후불결제 안내의 "인쇄 없는 할인 견적 기반 요청은 예외"가 후불 불가인지 허용인지 분명하지 않아 "단, 인쇄 없는 할인 견적으로 요청한 주문은 예외입니다"로 원문에 가깝게 적었다.
- 결제 버튼 문구: 카드·무통장입금 "6,146,000원 결제하기", 후불결제 요청 "6,146,000원 후불결제 요청". 폰 아래 띠는 "결제하기" / "후불결제 요청".
- 무통장입금 안내를 "입금 계좌는 주문 완료 화면에서 안내합니다"로 적었다. 주문 완료(무통장입금) 화면에 계좌가 있어야 한다.
- 카드 결제는 `nicepay-return.html`(기본 = 처리 중)로 보낸다. 2026-11-17 확인 결과 그 페이지에는 스크립트가 없어 처리 중 화면에서 `order-complete.html?state=card`로 넘어가지 않는다. 그 페이지 담당(result)이 자동 이동이나 버튼을 붙여야 흐름이 이어진다.
- 배송방법 설명(전국 / 서울·경기 / 지방 / 픽업장소 협의)은 order-now 요소 목록의 문구를 주문서에도 같게 썼다.
- "저장된 배송지에서 고르기" 단추는 새로운 배송지를 골랐을 때만 보인다(고르는 순간 팝업도 한 번 열린다).
- 취소/환불 정책 팝업 본문은 견본(`data-sample`)이다. 7일 교환·반품, 포인트 환원 같은 문구는 확인되지 않은 내용이라 실제 정책으로 바꿔야 한다.

## 주문 정보 입력 후 접수
- 상품 상세의 "주문하기"에서 오는 화면으로 보고 방한 후드 패딩 한 건만 두었다(요소 목록의 "삭제 후 메인으로 이동"이 상품 한 건을 전제로 읽혀서). 장바구니 3건 전부를 보여야 하면 알려 달라.
- 상품 줄에는 요소 목록대로 금액(4,130,000원)을 보이고, 요약의 상품금액은 요소 목록대로 "견적문의"로 두었다. 두 값이 함께 보이는 것이 맞는지 확인이 필요하다.
- 접수할 상품 미선택 안내(L370)와 장바구니로 이동 안내(L367)는 한 화면(`state=noitem`)으로 묶었다.
- 견적서 파일 형식 목록(이미지·PDF·문서·엑셀·한글·압축)은 jpg·png·gif·webp·bmp·pdf·doc(x)·ppt(x)·txt·xls(x)·csv·hwp(x)·zip·7z로 정했다.

## 디자인
- 수량 조절(`.qty`)은 홈 토큰 높이 40px 그대로라 지침의 터치 대상 44px보다 작다.
- 1100px 미만은 한 열(요약이 목록 아래)이고, 폰(768 이하)만 화면 아래 요청·결제 띠를 쓴다. 769~1099px에서는 요약 상자 안 버튼을 쓴다.

## 검수 반영(2026-11-17 오후)
- 접수·결제 버튼의 결과 문장(저장 실패·서버 거절·미선택)은 세 페이지 모두 한 곳에만 둔다: 769px 이상은 요약 상자 안 버튼 바로 위, 폰은 본문 맨 위. 폰은 버튼이 화면 아래 띠에 있고 요약 상자가 페이지 맨 끝이라 맨 위를 골랐다(아래 띠 위에 붙이면 2~3줄 문장이 화면을 계속 가린다). 장바구니 "처리 실패"(수량 변경·삭제 실패)는 목록 조작의 결과라 목록 위 그대로다.
- 주문서 "결제할 수 없는 견적"은 결제 버튼 대신 "담당자에게 문의"(1:1 문의 `customer-center?tab=qna`로 이동), "이미 저장된 주문"은 "주문내역 보기"(`mypage?section=orders`) 선 버튼으로 바꿨다. 두 상태에서는 결제 동의 칸도 감춘다. 담당자 직통 연락처가 생기면 그쪽으로 바꿔야 한다.
- 폰에서는 진행 순서(`.stp`)를 감췄다. 공용 `.stp`가 폰에서 현재 단계 이름만 남겨 번호 원이 장식처럼 보이기 때문이다. 흐름은 장바구니 요약 안내("결제는 견적을 확인한 뒤 주문서에서 진행합니다")가 알린다.
- 날짜 칸이 비었을 때 브라우저 기본 표시(mm/dd/yyyy 등) 대신 "날짜를 고르세요"를 덧씌운다. 기본 표시를 감출 수 없는 브라우저(Firefox)에서는 덧씌우지 않고 기본 표시를 그대로 둔다.
- 공용 10-form 의 12.5px 글자(`.fld__l small` `.fld__l .r` `.opt__b small` `.upl__tx small` `.files__s`)를 내 조각에서 임시로 13px 로 덮었다. 공용이 고쳐지면 지운다.
